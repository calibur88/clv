# assets/fonts 素材溯源

本目录登记字幕渲染的测试 / 参考字体。字体件来自仓库外，登记来源、整件 SHA-256、字体元数据与许可；
渲染用例按这里的哈希确认用的是同一份字节，不从文件名猜字重或 family。
本文件登记三份字体，各一节：第一件 `NotoSansCJKsc/` = 字幕渲染判据的基准族；第二件 `NotoNaskhArabic-v2.021/` = 阿语（RTL）面的**第二份基准**，补第一份缺的脚本覆盖；第三件 `noto-emoji/` = 表情符号（emoji）面的取样件，同样补第一份缺的脚本覆盖（它不是基准族，与第一份零重叠）。

## 用途与判据

- 用途：字幕渲染器的**测试 / 参考字体**，固定 CJK 字形与布局；不是库的运行时依赖。产品路径仍由宿主 / CAL 的系统字体解析（Windows DirectWrite），`font_dir` 指到本目录时才按文件建 face。
- 默认：`NotoSansCJKsc-Regular.otf`（family `Noto Sans CJK SC`，weight 400）作默认测试字面；`Bold`（weight 700）作粗体对照；7 件覆盖 100 / 300 / 350 / 400 / 500 / 700 / 900。
- **family 名不全是同一个**：Regular / Bold 的 family = `Noto Sans CJK SC`；Thin / Light / DemiLight / Medium / Black 的 family 名带字重后缀（见上表）。测试的 `font-family` 链与 `font-weight` 选择按 family/subfamily + `usWeightClass` 映射，不按文件名猜。
- 许可：OFL 1.1，允许随软件分发 / 嵌入；`LICENSE` 随目录入库；字体件不改名、不修改。
- 像素 / 布局判据：同平台同字体同 CAL 构型做 golden；跨平台只断布局 / bbox / 覆盖率，像素差异按字幕规范「渲染差异声明」一节允许。哈希只证明「用的是同一份字体字节」，不证明跨平台像素一致。

## 复现 / 校验

1. 从上面的 URL 下载 `08_NotoSansCJKsc.zip`，解出 `NotoSansCJKsc/` 下的 7 个 OTF 与 `LICENSE`。
2. 校验整件哈希（Git Bash / MSYS2）：

```
sha256sum assets/fonts/NotoSansCJKsc/*.otf assets/fonts/NotoSansCJKsc/LICENSE
```

3. 与上表逐件对平；任一不符即不是登记件，先查下载源，不要把不符件接入渲染用例。
4. 元数据（family / subfamily / version / usWeightClass）用 `fontTools 4.66.1` 的 `TTFont` 读 `name` 与 `OS/2` 表；版本行与上表对平。

### 用途与判据

- **基准族第二份**：管阿语（RTL）这一面 —— Bidi 分趟、整形按位置换字形、阿语覆盖率三件事都在它身上断。第一份对这几个码位全落 `.notdef`，没有这份就断不了。
- **golden 的取法**：各份只出自己覆盖的脚本，**同一张 golden 不混两份字体**（两族 hinting 不同，混了就归因不到改动）；像素 golden 仍按在册哈希取，字幕规范「字体回退约定」与「测试要点」两节与本节同口径。
- 测试路径取 **`NotoNaskhArabic/full/otf/NotoNaskhArabic-Regular.otf`**（w400）与 **`NotoNaskhArabic/full/otf/NotoNaskhArabic-Bold.otf`**（w700）—— 与 CJK 那份同取 Regular + Bold 两档、同为 OTF；`font-family: Noto Naskh Arabic` 命中，`font_dir` 指到本目录即可。
- **GSUB 实测，判据为什么换尺子**：`full/otf/Regular` 的特性集 = `aalt ccmp dlig fina init liga locl medi ordn pnum rlig rtlm tnum`，出现的 LookupType = 1 / 2 / 3 / 4 / 5 / 6。逐条查下去：**`liga` 只有 2 条连字、`rlig` 的 11 个 lookup 里 Type-4 连字 0 条**，`lam + alef` 这一组**不做成连字字形**，而是单字置换成 `uni0644.init.rlig` + `uni0627.fina.rlig`。
  ⇒ 判据**不能写「字形数 < 码点数」**（在这份字体上恒不成立，写出来就是假红），改成「**shaped 字形号 ≠ nominal 字形号，至少一处**」：证明整形按位置换了字形，而不是只按 cmap 取孤立形。
- 活体读数（本机实跑：HarfBuzz 14.4.0 经 `hb-ot-font` 取度量，FreeType 2.14.3 建 face；探针件属工程过程记录，不随本目录发行）：
  - 本族 Regular：`الله` 4 码点 → 4 字形，glyph id `81 68 70 8`，**.notdef 0**；`لا` 2 码点 → 2 字形，nominal/shaped = `66/10` 与 `8/71`，**替换生效 2 处** ⇒ 判据 PASS。
  - 对照：基准族 `NotoSansCJKsc-Regular.otf` 同两个串全部落 `.notdef`（阿语无覆盖）⇒ 判据报「不适用」而不是「整形失败」。两份件的分工由此可分，也正是当初那条假红的根因。
- 其它阿语特性（换行、竖排、`locl` 方言形）不在本件判据内（字幕规范「v0.2 预留」一节已归 v0.2）。

### 用途与判据

- **用途**：表情符号面的取样件 —— 回退链走到「emoji 码位」那一档时要有真件可指，否则该档只能停在豆腐块上。它**不是基准族**：与第一份的脚本覆盖**零重叠**（拉丁 / CJK 全落 `.notdef`），拿它做 CJK 或拉丁的 golden 属于误用。
- 三条形态后果（登记只立事实，判据待表情面开工时拍）：
  1. **无轮廓** ⇒ 依赖 `glyf` / `CFF` 的取形路径在这件上没有输入，度量只剩 `hmtx` 的 advance 加位图自带的定位；本版**未做活体读数**，`hb-ot-font` / `hb-ft` 两条入口在这件上的行为留作表情面开工的第一手实测。
  2. **单 strike 109 ppem** ⇒ 字号不是 109 px 时必然走缩放，位图缩放的质量档与轮廓字体不同；**跨平台像素 golden 在这件上不成立**（各平台位图缩放实现不同），判据要落在「取到同一张位图 + 缩放后包围盒」这一层。
  3. **只有一档 Regular**（weight 400、`fsSelection` 无 ITALIC、`italicAngle = 0`）⇒ 组合选脸的 style 硬过滤对 `italic` 请求直接拒，weight 请求一律最近匹配到 400；这正是「style 给不出只准落下一档、不准静默降级」那条的现成用例材料。
- 与前两件的分工：emoji 码位归这件、文字归前两份，**同一张 golden 不混三份字体**（口径同前两件）。

### 复现 / 校验

1. 拉树条目：`GET /repos/googlefonts/noto-emoji/git/trees/main:2D/fonts`，对 `NotoColorEmoji.ttf` 那行核 `size = 10 730 124` 与 `sha = e605743d05f261634f0b3f68a439d9b557d8f335`。
2. 本地算 git blob：`sha1("blob " + 字节数 + "\0" + 内容)` ⇒ 与上一步同值即「同一对象」；再 `sha256sum` 对「逐件清单」。
3. 形态复核：`fontTools` 读 `name` / `OS/2` / `post` / `maxp` / `head` / `cmap`；strike 读 `CBLC.strikes[*].bitmapSizeTable` 的 `ppemX` / `ppemY`；表清单里确认**没有** `glyf` / `CFF` / `COLR` / `CPAL` / `SVG`。
   表数要按 `TTFont.reader.tables`（sfnt 目录，**13 张**）数，**不要按 `TTFont.keys()`**（14 项）—— 后者多一个合成伪表 `GlyphOrder`，它不是 sfnt 表。
4. 分支件会随时间变：若哪天树条目的 blob 变了，本节的哈希与「同一对象」结论同时作废，**按新对象另起一节登记**，不改本节的值。
