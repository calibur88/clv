# assets/synth — 门面基准序列（自写生成素材）的登记件

本目录**不放字节，只放定义**。素材是 `scripts/gen_synth_sequence.py` 的输出：
1080p / 30 fps / 30 s 的原始 yuv420p 帧流，六段共 2 799 360 000 B（= 段字节 466 560 000 × 6，算式见下文「画面」一节；2.6 GiB），
把它提交进仓库既没必要也不可能——生成器按下面「复现」一节的命令逐段调用，就能把它逐字节复现出来，
而下面的 SHA-256 就是「复现对了」的判据。

## 复现

```
python scripts/gen_synth_sequence.py --manifest                      # 打印各段参数表与彩条定值（首两行含 FPS 与节目/全段总字节，打印为 ASCII）
python scripts/gen_synth_sequence.py --segment 3 --stream            # 第 3 段 150 帧的帧流走 stdout，SHA-256 走 stderr，不落盘
python scripts/gen_synth_sequence.py --segment 3 --out DIR           # 落盘为 DIR/synth_seg3.yuv，参数行（含 sha256=）走 stdout，产物落盘
python scripts/gen_synth_sequence.py --audio --out DIR               # 30 s 单声道 WAV
python scripts/gen_synth_sequence.py --segment 5 --frames 48 --stream  # 只出前 48 帧（跑测窗口）
```

依赖：numpy 2.5.3（本仓库既有开发期依赖，版本锚在 `requirements.txt`）+ CPython 3.14.8（解释器版本在全仓没有锚，这一格只登记本机实测时用的那一个版本）。
生成器**不读任何外部素材、不取网络、不调任何第三方编解码器**，只用上面这两件。
同机同环境已实测重跑与下面的哈希逐字节相符；含浮点的支路（段 3 扫描、音频的两条正弦与渐强）在跨机、跨环境下末位不作保证。

确定性已实测：段 1..7 与音频各自连跑两次逐字节相同（`--stream` 模式一字节不落盘），含段 1 的纯查表支路与段 3 的浮点正弦支路；
最近一轮复核（2026-10-20）产物与下表登记值零变化。表里任一条哈希对不上，先查生成器改动，再查 numpy 版本，
别急着怀疑素材。

## 画面：六段，每段 150 帧（5 s），帧号 i = 0..149

显示尺寸 1920×1080，逐行 yuv420p（Y 平面 1920×1080，Cb / Cr 各 960×540，一帧 3 110 400 B）。
派生算式（本文件所有帧/段/窗口字节都由它来，权威定义在生成件 `scripts/gen_synth_sequence.py` 的 `FRAME_BYTES`、`SEG_FRAMES`）：
帧字节 = 1920 × 1080 × 3 ÷ 2 = 3 110 400；段字节 = 帧字节 × 150 = 466 560 000；节目总字节 = 段字节 × 6 = 2 799 360 000；窗口字节 = 帧字节 × 帧数。

| 段 | 内容 | 生成式 | 该段 150 帧整段 SHA-256 |
|---|---|---|---|
| 1 | 静态七色彩条（垂直） | 条号 `= x * 7 // 1920`，色度列 `= x * 2 * 7 // 1920`，七色 Y/Cb/Cr 见下表 | `b3e2387078548acc74d6c6fc8d976f1143f7de86db544ca482d762aafbb89aa2` |
| 2 | 16 级阶梯灰阶 | `lvl = x * 16 // 1920`，`Y = lvl * 17`（0, 17, …, 255），色度恒 128 | `96ec341f5347c82b25118f3fbca1dac0374989c35f8cd9ef788579e99cd6c50c` |
| 3 | 空间频率扫描 | 周期 `T(x) = 64 + (2 − 64) · x / 1919`，`Y = clip(128 + 100·sin(2πx/T), 16, 235)`，相位 0，色度 128 | `4fa56a9d1e15d49028ad754b04b6225256ff615efbef0c137a484953406ccc7f` |
| 4 | 40 × 40 棋盘 | `(x//40 + y//40) & 1` → Y = 235 / 16，色度 128（行 27 × 列 48，整除） | `55357f4fde6586d556033e4e9289f2f915441b9d3c98c641dea6d2fca25b334d` |
| 5 | 200 × 200 运动方块 | `x0 = (20·i) mod 1720`，`y0 = 440`；块内 Y = 235，底 Y = 16，色度 128（每帧右移 20 px，越界回卷） | `0c35a72d217443413f758f04414dfc576ce321b6940380b342761beeb276a5b4` |

第 2 段的 Y 域刻意铺满 `[0, 255]`（`lvl × 17` 会越出有限范围的 16–235），为的是让编码器在
「超出显示范围的电平」上也给出可复现的行为；这不是配色错误。

## 彩条定值（bt.709 有限范围矩阵，100 % 满幅 RGB → Y/Cb/Cr）

`Y  = 16 + 219 · (0.2126 R + 0.7152 G + 0.0722 B) / 255`
`Cb = 128 + (224/255) · (B − Y_full) · 0.5 / (1 − 0.0722)`
`Cr = 128 + (224/255) · (R − Y_full) · 0.5 / (1 − 0.2126)`
取整 = `floor(x + 0.5)`；越界夹到 Y∈[16,235]、Cb/Cr∈[16,240]。

| 条 | RGB | Y | Cb | Cr |
|---|---|---|---|---|
| 白 | (255, 255, 255) | 235 | 128 | 128 |
| 黄 | (255, 255, 0) | 219 | 16 | 138 |
| 青 | (0, 255, 255) | 188 | 154 | 16 |
| 绿 | (0, 255, 0) | 173 | 42 | 26 |
| 品 | (255, 0, 255) | 78 | 214 | 230 |
| 红 | (255, 0, 0) | 63 | 102 | 240 |
| 蓝 | (0, 0, 255) | 32 | 240 | 118 |

## 色彩标记

全片按 **bt.709  primaries / 有限范围(tv)** 生成：Y ∈ [16, 235]、Cb/Cr ∈ [16, 240]、中间电平 128。
4:2:0 色度按段直接给值：段 1 按条取彩条定值，其余各段（含段 7）Cb / Cr 两平面恒 128；不做由亮度平均出色度的下采样。
跑测时不对源做任何色彩转换。

## 音频：30 s 单声道，48 kHz / 16 bit

| 区间 | 内容 |
|---|---|
| 0–10 s | 1 kHz 正弦，幅度 50 % 满刻度 |
| 10–15 s | 静音 |
| 15–20 s | 白噪声，峰值 30 % 满刻度（确定性 PRNG：splitmix64，种子 `0xC1F` 写死在生成器里） |
| 20–25 s | 440 Hz 正弦，幅度 80 % 满刻度 |
| 25–30 s | 1 kHz 正弦，幅度 0 → 满刻度线性渐强 |

WAV（44 B 头 + 2 880 000 B PCM = 2 880 044 B，1 440 000 样本）整件 SHA-256：
`e1769ce69628cba834cf2edbd4f95a90cffaad3d41b5a01346e8d1666a715f11`

## 与编码器的对接事实（实测，不是推断）

- **对齐**：1080 ÷ 16 = 67.5 不整除 ⇒ 编码面取 120 × 68 个宏块 = **1920 × 1088**，编码器内部自己补那 8 行，
  送入前不需要裁剪也不需要补边（探针实测 `coded=1920x1088 mb=120x68`）。度量在**裁回 1920 × 1080** 之后才算。
- **音频面**：48 kHz / 单声道被两个公开入口接受；1 440 000 样本走 CLV 音频面编成 352 个 FLAC 帧
  （921 168 B + 34 B 流信息）再解回来，PCM 2 880 000 B `memcmp` 全等，且**重装箱出来的 WAV 整件
  与源件 SHA-256 相同**（即上面音频一节末尾那条「WAV 整件 SHA-256」，同一条哈希，含 44 B 头）。
- **无损**：`quantizer = 0` 这一档现在走无损通路（早先它被合法域占用、只能按最细有损档验收）。
  现状（2026-10-10 实测）：量化步长合法域改成三段（`0 = 无损` / `1..127 = 有损`），`0` 不再被折成 1；
  系数载体为无损自占一档 **15 bit**（帧内帧间同宽，装的是整数变换原值，界 8192 / 16320）。
  本素材六段各取前 12 帧走无损腿，实测**三平面 SSE 全 0**（逐字节全等），代价比 1.13–1.14。
- **加段自证**：生成器后头新加了段 7（渐变面），加完之后把段 1..6 整段重生成求哈希，
  与「画面：六段，每段 150 帧（5 s）」一节的表里那六条登记值**逐位对平 6 / 6** ⇒ 新支路没碰到既有六段的一个字节。

## 段 7 · 渐变面（补材，不排进 30 s 节目）

画质度量取用的三类内容形态是静止面 / 动态面 / 渐变面——原六段里没有平滑渐变形态的内容，
所以在生成器里加这一段补上第三类。它与音频不对齐，也不参与门面节目的 30 s 计数。

### 现行算式（2026-10-11 改，全整数、逐值可复算）

- `v(x, y) = (x + y) × 219 ÷ (1920 + 1080 − 2)` ∈ [0, 219]（左上到右下的对角坡）
- `t(i) = i × 110 ÷ (SEG_FRAMES − 1)` ∈ [0, 110]（时域推进，**每帧 +0 或 +1，且全帧同值**）
- `Y = 16 + v ÷ 2 + t`（两次都是整除）∈ **[16, 235]**：16 在首帧左上角取到、235 在末帧右下角取到；在定义域 `i = 0..149` 内全序列不越有限范围（越出这 150 帧时域项会推出上界，不作声称）
- 150 帧 = 466 560 000 B（段字节，派生自上「画面」一节的算式），整段 SHA-256：
  `e069d15c0904a7310502f23efb401fc9d749a7f2ca4732999ad2cf3d5217b7c5`
- 生成命令：`python scripts/gen_synth_sequence.py --segment 7 --out <目录>`（与「复现」一节同形制）
- 跑测用窗口（32 / 48 / 128 帧）由 `--frames N` 直接出，窗口哈希 = 生成器自己打印的那行 `sha256=`，
  与整段哈希同出一处，不存在两次抽帧不同字节的问题。
  - 32 帧 = 99 532 800 B：`43cea850d0e1a9efd82e3f9e67f08570dcdb50a486e8c6ccecd811519f99aca1`
  - 48 帧 = 149 299 200 B：`b25336ab2b6213f6ae346dfa92b186e403fe57eef49de06732e626a098b8370b`
  - 128 帧 = 398 131 200 B：`e66665cdd8abf4a821310757f397431c79fcb763ac955971bb352ab8b0500fcb`

### 亮度面之外的两面口径（U / V）

段 7 的 **Cb 与 Cr 恒为 128**（`_ramp()` 返回两平面同值的 `np.full((H//2, W//2), 128)`），即本段**不含任何色度内容**。
两条读数口径由此写死，别把常量当成质量：

- 本段 U / V 路 SSE 恒 0 ⇒ PSNR 恒报哨兵 `99.000`。
  这只说明「没东西可错」，**不说明色度编码好**；色度档的真实表现由段 1（七色彩条，Cb/Cr 各 7 个电平）与段 6（综合图）量。
- 本段的载荷与 bpp 全部来自亮度面，横向比载荷时不能拿它与含色度内容的段比绝对值。

### 旧算式与旧哈希（作废留痕，不抹行）

2026-10-10 首版算式：`Y = 16 + (v + off) ÷ 2`，`off(i) = i × 219 ÷ 149`，整段哈希
`493a005007fd007ad49c62d84c79b4fda9d37fab6cffcfc6c26e13d9fa27d918`（150 帧 = 466 560 000 B，与现行算式一条同为本文件的段字节）。
**这组哈希自 2026-10-11 起作废**（现行段 7 的哈希记在本节「现行算式」一条）。作废之前跑出的所有读数
（含三窗口哈希对照与渐变面的画质度量列）都是**旧素材的读数**，与现行段 7 不可比。

作废原因（判据就是下面这几条实测，逐帧差分本段可复算）：`off` 每帧 +1 或 +2，
整除把时域推进变成**逐帧翻转的奇偶抖动** —— 实测 149 帧里 79 帧同帧内既有 0 又有 +1（一半像素 +1、另一半不动），
帧 2→3 更达 100% 像素 +1；对照静止面帧间 0 变化。那样量的是「坡 + 满幅 1 级 dither」，不是平滑渐变。
现行算式改成整级均匀加：帧间要么全 0、要么全 +1，**149 帧全测奇偶翻转 0 次**。

候选 `t = i × 109 ÷ 149` 一版同样治好抖动，但末帧最高只到 234、取不到 235，端点项不合格，故改用 110。

**改段自证（2026-10-11，改完即跑）**：段 1..6 整段重生成求哈希，与「画面：六段，每段 150 帧（5 s）」一节表里那六条登记值
**逐位对平 6 / 6** ⇒ 改段 7 没碰到既有六段的一个字节。自证走 `--stream` 模式，一字节不落盘。
