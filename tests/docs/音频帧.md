# 测试项 · 音频帧与编解码面（audio）

| 栏 | 内容 |
|---|---|
| **测试项名** | 音频面：帧头自核 / 流声明对账 / 一包一帧 / 元数据视图 / FLAC 编解码闭环 |
| **测什么** | FLAC 帧头位域与采样率码表的自洽、流级参数与帧头对账、一包恰好一帧的边界、VORBIS_COMMENT 元数据与 PICTURE 字段的读回、编解码闭环字节保真。 |
| **怎么测** | 句柄端到端走公开 `CLV_Audio*` ABI；单元级直测走 `src/audio/frame.h`、`metadata.h`。 |
| **测哪里** | `tests/win32/audio/`（`test_audio_framing` / `test_audio_codec` / `test_audio_blob_refs`）+ `tests/win32/api/test_audio_metadata_view.cpp`。素材 = `assets/fixtures/sample-15s.flac`（真件载体，库内件，来源与两条逐字节对平登记在 `assets/fixtures/provenance.txt`）。 |
| **判据** | 闭环判据 = 字节等源、无容差。帧头位域与采样率码表在件头写死。子集两档护栏：块尺寸 16384、采样率 ≤48k 时 4608。真件三例（`SampleTrack*`）：块表四块 34 / 7835 / 306 / 8192 B、vendor 12 B、11 条注释逐条对平且**在真件上**查键大小写不敏感、PICTURE 300×300 / 深度格自定为 12 / 数据 7 793 B 整块对平；承载块往返 = 真注释块 307 B + 真封面块 7 836 B + 派生大块 70 516 B 三份逐字节回来，声明 2^32 B 判 `TOO_LARGE`。「零条目」与「载荷跨过 65 535 B」两形由真块派生（改条目数 / 真封面块复制九遍 = 9 × 7835 + 1 B），65 535 与 65 536 两档在独立层的 `IndependentContainer.ExtChainOverHopCapIsRejectedWithCode` 各自钉住（承载块长度字段是 4 字节，两档都必须受理）。流信息值域三判（`AudioFraming.StreamInfoRejectsOutOfRangeDepthRateAndBlocksizeFloor`）：位深只受理 {16, 24}，8 / 12 / 20 / 32 落在 5 位可表达域内仍判 `VALUE_RANGE`；采样率 655354 受理、`kSubsetSampleRateRejectFloor` = 655355 起拒，0 先命中「采样率为 0」那一判、同返 `VALUE_RANGE`；块大小下界按位深分档（`kSubsetMinBlocksize16` = 64、`kSubsetMinBlocksize24` = 72），界值受理、界值 − 1 拒，且 64 在 24-bit 档仍拒 —— 这一格证明下界随位深走，不是全局取 64。注释块视图自洽（`AudioFraming.CommentView*` 三支）：两个查询口（按下标取 / 按键名查）在入口判三件事 —— 条目区起点（8 + 厂商串长度）≤ 声明块长、声明块长 ≥ 头部必需字段 8、长度加法放到 64 位域里做；起点越界与块长不足各一档，不回绕档 `vendor_length` = 0xFFFFFFF4（起点 0xFFFFFFFC，由起点判拒），回绕档 0xFFFFFFF8 与 0xFFFFFFFF（32 位里回绕成 0 与 7，只有 64 位算式仍判越界），拒档一律不写出参、不改视图。负向不破例 = 同页自洽视图上正常查询照旧出条目、序号越界返 `CLV_AUDIO_VALUE_RANGE`、键不存在返 `CLV_AUDIO_COMMENT_KEY_NOT_FOUND`，都不许升格成「结构不成立」。 |
| **平台** | Win32 实测；Linux / macOS 暂无用例。 |
| **现状** | 通过（audio 39 例 + api 面元数据视图 9 例）。真件读不到时三例 `SampleTrack*` 一律 `GTEST_SKIP`（ctest 计通过），不判硬失败 —— 与视频面真素材档、容器面 fixture 档用的是同一种处置。 |
