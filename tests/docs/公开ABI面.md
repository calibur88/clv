# 测试项 · 公开 ABI 面（api）

| 栏 | 内容 |
|---|---|
| **测试项名** | 公开 ABI 面：只吃公开 C ABI 的端到端契约 |
| **测什么** | 版本双轨、内存分配器、日志、文件 IO、参数结构体布局、容器 / 视频 / 音频句柄端到端、元数据视图、视频 profile、无损容器、呈现节器件、字幕公开头的形状与句柄——全部不 include 实现层头，只调公开头声明的 C ABI。 |
| **怎么测** | 纯公开面调用（`include/CLV_*.h`）。`ParamStructLayout` 三例含「磁盘无残件」验证（写参数结构后确认不落地残留）。`PaceApiTest` 三十一例（`TEST_F` 夹具）+ `PaceApiStandalone` 三例（共 34 例）走**假设备 + 假时钟 + 假消费端**：排队字节数与单调墙钟由用例供，主钟的数值由用例扮演消费端按设备真取走的量报告，一步一跳手动推进 —— 所以「报告驱动、库不外推、回退拒收、墙钟回退重登记、死队列计数、递交长度控写、水位分档、倍率钳位、跳变边沿只交一次」这些在真器件上要靠时序才能碰到的分支，都在这里逐条钉死。 |
| **测哪里** | `tests/win32/api/`（11 件：`test_file` 24 / `test_pace` 34 / `test_audio_metadata_view` 9 / `test_logger` 15 / `test_container` 6 / `test_memory` 4 / `test_version` 6 / `test_video_tool_rejection` 4 / `test_param_struct_layout` 3 / `test_subtitle_api` 4 / `test_video_lossless_container` 1，相加 = 110）。 |
| **判据** | 版本双轨字面量钉。`ParamStructLayout` 三例。官方 CC0 件三例见音频面文档。日志投递侧定性 = 冒烟档（不判内容 / 条数 / 顺序）；**落盘侧是实判**：路径档三种入参（`NULL` / 空串 / 含反斜杠）都判 `INVALID_PATH` 且不碰盘，参数档判 `rotate_size_kb == 0`、`SIZE_MAX` 一类乘不下的值与 `max_files > 200 000` 都归 `INVALID_ARGUMENT`，后端档按构型分侧（spdlog 侧装上后消息读得回、null 侧回 `UNSUPPORTED_BACKEND` 且不留件），换落点判「旧的不再收新的、新的不再收旧的」，`max_files = 0` 判不轮转且重设不 truncate（轮转件命名按后端 `calc_filename` 的形状拼出来查它在不在），`CLV_LogStrError` 逐格全覆盖 + 未知值 `"unknown"`，枚举行三件 `static_assert` 钉 `OK == 0` / 102–104 连续 / 末码 105。内存缓冲句柄（`ClvFile` 六例）钉五件事：所有权（`Close` 后宿主缓冲照常可读、库不接管）、`mode` 两档受理（`APPEND` 与越界值落 `INVALID_ARGUMENT`，且**不产出值 9**）、固定容量（写档越界整次拒 + 完成量写 0 + 游标不推进）、`Size` 两档读法（只读档 = 容量、只写档 = 高水位）、参数档与文件后端同式（非零 `size` 配空指针 ⇒ `INVALID_ARGUMENT`，读写两侧各钉一次；`size == 0` 不碰指针 ⇒ OK + 0）。节器件：主钟只跟消费端报告走 —— 报告之间一格不推进（库不外推）、回退的报告整口拒收并计一笔「回退拒收次数」、一条都不报时钟停在原地且死队列计数 > 0；起播零点与主钟同源各一例（预灌期不推进钟、按住的那段既不推进也不报警）；调用方供的墙钟回退判 `CLOCK_SKEW` 且墙龄从小值重登记（不许无符号回绕）；阈值 = `period`（对齐带 ±半周 / 等待半周）与 `period + 实测最大报告步长`（丢帧阈）逐档重算核对；递交长度四档（`0` / 56 / 72 / 比本版更大）用 128 B 哨兵 `0xA5` 逐字节回查「旧尺寸之后零写入」，建仓侧旧尺寸不读尾部（时基落回纳秒缺省，报 1e9 tick 就是 1.0 s）；水位三档按 `max_latency_bytes` 分档、读数问不出时 `UNKNOWN` 且 `queue_ms` 归 0；建议倍率钳在 [62259, 68813]；设备跳变边沿只持续一次判定且不动任何账；减账口先报后清（超扣整口拒、三账不动，报得下的那批等设备读数掉下来时抵掉）；`BeginPass` 逐格复位报告值 / 影子账 / 零点 / 四个诊断量；容量缺省 1000 ms 背压与 2000 ms 积压上界各钉一次；冒烟判据 = 理想趟走完 30 帧 `dropped = 0`；设备形状三格（100 ms 一块 / 停一格 1 s / 慢一成）与死队列两格的共同判据 = 出满、零丢、不卡死、主钟单调。字幕头四例：错误码段 106–117 逐值钉号位、九个结构体 `struct_size` 的 `offsetof == 0`、能力位 bit3/bit4 按构型分侧、`CLV_SubtitleStrError` 逐值出可打印 ASCII 且段外值（1 / 105 / 118 / 9999）只回 `"unknown"`。 |
| **平台** | Win32 实测；Linux / macOS 暂无用例。 |
| **现状** | 通过（110 例，两档全跑，`TEST` 与 `TEST_F` 都数）。`CLV_COEF_CODING=0` 定长档构型下 `VideoToolRejection.FrameHeaderExtraSignallingBitsRejectOnlyThatFrameNotTheStream` 两档都实跑、不跳过：默认档把帧头选择器抹成 0、定长档抹成 1，两侧都是「这一帧被拒、且拒在帧头之后」—— 码 67 `CLV_VIDEO_PAYLOAD_TOO_SMALL`、拒在宏块载体读取段、只坏这一帧不进拒解态。 |
