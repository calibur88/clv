# 测试项 · 门禁（gate）

| 栏 | 内容 |
|---|---|
| **测试项名** | 门禁：全量编译 + 双配置 ctest + 判据 + 探针 + 示例直跑 |
| **测什么** | 交付前的整体验收闸——clean 全量编译 0 warning / 0 error、双配置（spdlog ON / OFF）各全量 ctest、C11 + CXX17 公开头探针、判据 1–4、最大片数计时、例数列表、两份示例的可运行性。 |
| **怎么测** | 门禁脚本按序执行：环境探针 → 配置 A（spdlog ON / warnings-as-errors ON / demos ON）clean 构建 → 配置 B（全 OFF）clean 构建 → C11 + CXX17 双语言公开头探针。全部前置判完才允许跑 ctest；任一前置非零则写 `GATE_FAIL reason=…` 并跳过 ctest（硬门）。ctest 主配置与 OFF 配置各全量，判退出码 0 且 `100% tests passed out of EXPECT`（闸内 `set EXPECT` 与实测例数两处必须一致）。ctest 之后直跑三份示例（`clv_demo_core` / `clv_demo_container` / `clv_demo_video`，第三份是链 SDL3 的双轨播放器）与三份逐例读数（验收判据、最重一例计时、用例清单），各自退出码非零即判红。 |
| **测哪里** | 交付前的整体验收序（净构建全量编译 + 双配置全量 ctest + 验收判据 + 公开头双语言探针）；读数只登记在本表的「现状」行，不引用仓库外的产物。 |
| **判据** | 期望例数 = `CMakeLists.txt` 里的 **`set(CLV_EXPECTED_TESTS 431)`**（承载件在本仓，配置期以 `STATUS` 行回显），双配置各要 `100% tests passed out of <同一个数>`；数的是**注册数**（`out N` 那个 N），不是通过数，skip 与 fail 分两栏读。**431** 的分域实测 core 20 / api 110 / container 77 / audio 39 / video 142 / subtitle 22 / independent 21，相加 = 431；实测配方 = 逐域数 `tests/win32/<域>/*.cpp` 里匹配 `^[[:space:]]*TEST(_F)?\(` 的行再相加。谓词两处都不能省：只认顶格就漏掉带缩进写的与包在命名空间花括号里的那几条，不数 `TEST_F` 就少节拍面那 31 条。分域相加不等于注册数就是数法错了，先对平再改账。例数变了就必须同批改这一格（`CMakeLists.txt` 那一行、本行、下一行、`README.md` / `API.md` / `ARCHITECTURE.md` / `tests/docs/README.md` 的对外计数），改数字只许跟着实测走，不许反过来为绿而改。clean `Building` 行数 ≥ TU 数、warning / error 各 0。判定顺序：先看各前置 `*_EXIT`，再看例数 N（防陈旧二进制误判）。**构型感知**：`CLV_COEF_CODING=0`（定长档）与 `=1`（默认，法 1）两档的载体实长与字节不同，**测试树内唯一一处选档判断** = `tests/win32/video/test_config_expect.h`（`#if CLV_COEF_CODING` 两支；直接 include 它的四件 = `video/test_video_payload.cpp`、`video/test_video_domain_edges.cpp`、`api/test_video_tool_rejection.cpp`、`independent/test_ind_video_motion.cpp`）。库侧另有两处编译期兜底，只给不经 CMake 的裸编译定缺省值、不选期望档：`src/video/block.h` 的 `#ifndef CLV_COEF_CODING`（定出 `kEncoderCoefCoding`）与 `src/video/clv_video.cpp` 匿名命名空间的 `#ifndef CLV_DEC_MB_THREADS`（定出 `kMbThreads`）。期望载体由 `scripts/gen_video_payload_fixtures.py` 两档都发（后缀 F0 / F1），生成件里不留 `#if`、也不留第二处实长数字。两档各要 0 fail 且无构型相关跳过：定长档那一侧「取错法必须被拒」是实跑条 `VideoToolRejection.FrameHeaderExtraSignallingBitsRejectOnlyThatFrameNotTheStream`（把定长流的帧头选择器抹成法 1，实测被拒，形态登记在下面现状行），不是跳过项；真素材不在位那一例的跳过是设计如此，另算（见下格）。**判据分档的两条口径**：① 期望载体走**生成件两档都发**（`scripts/gen_video_payload_fixtures.py` 出 F0 / F1 两套数组），选档只在 `tests/win32/video/test_config_expect.h` 一处 —— 依据：`video_payload_fixtures_p.h` 是生成件、件头写着「请勿手改」，手改它等于把判据做成下次重生成就消失的东西；② **不建** `tests/win32/independent/frozen/` 那类第二套冻结件目录，冻结字节一律留在夹具件里，独立面用例经分档头取本档那一份 —— 依据：第二套冻结件必然与生成件漂移。「取错法必须被拒」这一判走公开 ABI 面：只断到「这一帧被拒、且拒在帧头之后」，**不定位到具体实现行**（落在 `block.cpp` 的读界还是 `macroblock.cpp` 的取载体字节，属白盒测试范畴，公开面看不到）。行级定位归白盒测试面，不在公开面用例里伸手拿实现层的符号——那会把这条「只吃公开头」的边界拆掉。 |
