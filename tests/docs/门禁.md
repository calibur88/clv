# 测试项 · 门禁（gate）

| 栏 | 内容 |
|---|---|
| **测试项名** | 门禁：全量编译 + 双配置 ctest + 判据 + 探针 + 示例直跑 |
| **测什么** | 交付前的整体验收闸——clean 全量编译 0 warning / 0 error、双配置（spdlog ON / OFF）各全量 ctest、C11 + CXX17 公开头探针、判据 1–4、最大片数计时、例数列表、两份示例的可运行性。 |
| **怎么测** | 门禁脚本按序执行：环境探针 → 配置 A（spdlog ON / warnings-as-errors ON / demos ON）clean 构建 → 配置 B（全 OFF）clean 构建 → C11 + CXX17 双语言公开头探针。全部前置判完才允许跑 ctest；任一前置非零则写 `GATE_FAIL reason=…` 并跳过 ctest（硬门）。ctest 主配置与 OFF 配置各全量，判退出码 0 且 `100% tests passed out of EXPECT`（闸内 `set EXPECT` 与实测例数两处必须一致）。ctest 之后直跑三份示例（`clv_demo_core` / `clv_demo_container` / `clv_demo_video`，第三份是链 SDL3 的双轨播放器）与三份逐例读数（验收判据、最重一例计时、用例清单），各自退出码非零即判红。 |
| **测哪里** | 交付前的整体验收序（净构建全量编译 + 双配置全量 ctest + 验收判据 + 公开头双语言探针）；读数只登记在本表的「现状」行，不引用仓库外的产物。 |
| **判据** | 期望例数 = `CMakeLists.txt` 里的 **`set(CLV_EXPECTED_TESTS 390)`**（承载件在本仓，配置期以 `STATUS` 行回显），双配置各要 `100% tests passed out of <同一个数>`；数的是**注册数**（`out N` 那个 N），不是通过数，skip 与 fail 分两栏读。**390** 的分域实测 core 20 / api 91 / container 77 / audio 39 / video 142 / independent 21，相加 = 390；实测配方 = 逐域数 `tests/win32/<域>/*.cpp` 里匹配 `^[[:space:]]*TEST(_F)?\(` 的行再相加。谓词两处都不能省：只认顶格就少 26 例（带缩进写的、以及包在命名空间花括号里的那几条没进来），不数 `TEST_F` 就少节拍面那 16 条。分域相加不等于注册数就是数法错了，先对平再改账。例数变了就必须同批改这一格（`CMakeLists.txt` 那一行、本行、下一行、`README.md` / `API.md` / `ARCHITECTURE.md` / `tests/docs/README.md` 的对外计数），改数字只许跟着实测走，不许反过来为绿而改。clean `Building` 行数 ≥ TU 数、warning / error 各 0。判定顺序：先看各前置 `*_EXIT`，再看例数 N（防陈旧二进制误判）。**构型感知**：`CLV_COEF_CODING=0`（定长档）与 `=1`（默认，法 1）两档的载体实长与字节不同，**测试树内唯一一处选档判断** = `tests/win32/video/test_config_expect.h`（`#if CLV_COEF_CODING` 两支；直接 include 它的四件 = `video/test_video_payload.cpp`、`video/test_video_domain_edges.cpp`、`api/test_video_tool_rejection.cpp`、`independent/test_ind_video_motion.cpp`）。库侧另有两处编译期兜底，只给不经 CMake 的裸编译定缺省值、不选期望档：`src/video/block.h` 的 `#ifndef CLV_COEF_CODING`（定出 `kEncoderCoefCoding`）与 `src/video/clv_video.cpp` 匿名命名空间的 `#ifndef CLV_DEC_MB_THREADS`（定出 `kMbThreads`）。期望载体由 `scripts/gen_video_payload_fixtures.py` 两档都发（后缀 F0 / F1），生成件里不留 `#if`、也不留第二处实长数字。两档各要 0 fail 且无构型相关跳过：定长档那一侧「取错法必须被拒」是实跑条 `VideoToolRejection.FrameHeaderExtraSignallingBitsRejectOnlyThatFrameNotTheStream`（把定长流的帧头选择器抹成法 1，实测被拒，形态登记在下面现状行），不是跳过项；真素材不在位那一例的跳过是设计如此，另算（见下格）。**判据分档的两条口径**：① 期望载体走**生成件两档都发**（`scripts/gen_video_payload_fixtures.py` 出 F0 / F1 两套数组），选档只在 `tests/win32/video/test_config_expect.h` 一处 —— 依据：`video_payload_fixtures_p.h` 是生成件、件头写着「请勿手改」，手改它等于把判据做成下次重生成就消失的东西；② **不建** `tests/win32/independent/frozen/` 那类第二套冻结件目录，冻结字节一律留在夹具件里，独立面用例经分档头取本档那一份 —— 依据：第二套冻结件必然与生成件漂移。「取错法必须被拒」这一判走公开 ABI 面：只断到「这一帧被拒、且拒在帧头之后」，**不定位到具体实现行**（落在 `block.cpp` 的读界还是 `macroblock.cpp` 的取载体字节，属白盒测试范畴，公开面看不到）。行级定位归白盒测试面，不在公开面用例里伸手拿实现层的符号——那会把这条「只吃公开头」的边界拆掉。 |
| **平台** | Win32 / MSVC + Ninja。 |
| **现状** | 通过。净构建双配置读数（构型 A = Debug / spdlog ON / warnings-as-errors ON / demos ON / 动态库按缺省 OFF——门禁的配置行不覆写 `CLV_BUILD_SHARED`；构型 B = 同 Debug 但四开关全 OFF）：A `Building` 81 行 = 编译单元 81（CXX 78 = 库侧 36 + 测试侧 42，C 3 = 三份示例），warning 与 error 各 0 行；B `Building` 78 行 = 编译单元 78（CXX 78，demos OFF 故无 C 条目），warning 与 error 各 0 行；两把各 `100% tests passed out of 390`，各 Skipped 1 / Failed 0。库侧那 36 件比上一版多 1 = 新增后端 `platform/fileio/memory_fileio.cpp`。`Building` 行数只按「该构型这一轮真的编了哪些目标」读，**它不是库面的属性**：把 `CLV_BUILD_SHARED` 打开，同一批库源会以 `clv.dir` 再编一份，A 侧读数从 80 涨到 115（实测差额 35 = 库侧 35 个 TU 的第二份编译，第三方从 `_install` 取预编译件、不进这个数；那是 375 例时的 base 80，本版 base 变 81 后同式应推得 116，本数**未重跑**，只作量级不作同批差值）—— 两条路线之间的差不是回归，同一轮内只按「A 减 B = demos 那三条 C 编译单元」自洽核对，不同配方的读数不做差。**示例直跑（闸内两份 + 播放器那份另跑）**：`clv_demo_core` 退出码 0（10 项自动判定全过、人工 2 项）、`clv_demo_container` 退出码 0（自动全过、人工 1 项）、`clv_demo_video` 退出码 0 且 Release 构型下 `--passes 2` 两趟各 105 帧 / 丢 0 / 背压堵 0 次（**这一格是沿用上一版的 Release 读数，本版终局轮没重跑这一份** —— 门禁脚本只直跑 core 与 container 两份，且本版改的归还路径在这份示例里已改走带回报的门，读到的仍是旧登记）；同一份素材 Debug 下解码腿 86.8~89.4 ms/帧 ⇒ 丢 101 / 102，属吞吐不达，判据钉 Release，理由见 `demo/README.md`「循环验收形」。C++17 探针一旦还引用已退场的公开码，这道闸必须判红 —— 它挡的就是这一类。**闸内两步的覆盖面口径**：构型 A 既编译示例也直跑示例（示例内钉死的版本期望值只有跑起来才失效，见「怎么测」）；`demo_local/bin/clv.dll` 的拷贝挂在整份刷新目标 `clv_demo_local` 上而不是某个 exe 的 POST_BUILD —— exe 只按导入库判要不要重链，挂错点时只改库内实现不重链、拷贝不执行、直跑读的是旧 DLL（成因与实测见 `CHANGE.log` 修复段与 `demo/CMakeLists.txt` 注释），故示例直跑的第一步是核对 `demo_local/bin/clv.dll` 与构建产物里那一件同哈希。**双编码档读数**：定长构型 = `BUILD_RC=0` / `CTEST_RC=0` / 注册 **390** / **0 fail** / Skipped **1**；默认构型 = 同 390 / 0 fail / Skipped **1**；`VideoToolRejection.FrameHeaderExtraSignallingBits…` 在两档都是 `[  OK  ]`（定长档没有构型相关跳过），两档剩下的那 1 例 Skipped 都是 `VideoQualityRealMedia.…`。**定长流谎称法 1 的实测形态** = 码 **67 `CLV_VIDEO_PAYLOAD_TOO_SMALL`** / 段 = **宏块载体读取**（选择器 1 是合法值，帧头那关放行；同用例 kBad 表里未赋法的 2..7 才当场 `HEADER_BAD`）/ **单帧拒**（`StreamRejected` 读回 0，之后下一干净帧照常出 I 帧）/ 退出码 0。**真素材缺件的处置一律跳过**：视频面 `VideoQualityRealMedia.…` 在没有 `CLV_TEST_YUV` / `assets/fixtures/provenance.txt`）。**ctest 常态读数（双档、以及下面两把 ASan 构型同判）= 注册 390 / fail 0 / Skipped 1**；那 1 例恒为 `VideoQualityRealMedia.ThreePlanePsnrAndBitrateFallMonotonicallyWithQuantizer`（已登记在 `tests/docs/公开ABI面.md`），**不视为 fail、也不计入「全过」的反例** —— 别为凑 0 去摘它或改成 fail。**哈希尺的坑**：MSVC 的 PE 默认写 TimeDateStamp 并随机化 PDB GUID，**整件哈希不能当「同源码复现」的尺**（同一份源码、同一构型连编两次的 `clv.dll` 只差 35 字节，全在时间戳与 `.rdata` exe，"两侧都插桩"按构造成立；`CLV_DEC_MB_THREADS` 不覆写 = 出厂 16），两把都是 `BUILD_RC=0` / `CTEST_RC=0` / `100% tests passed out of 390`；ctest 只回显失败用例的输出，故另各跑一遍**单进程全量**收 sanitizer 的 stderr：两把的普查都是 `ASAN_ERROR_LINES=0`（堆 / 栈 / 越界 / 未初始化零命中），`LEAK_LINES=0` 那格只说明本工具链不给泄漏读数（MSVC ASan 无 LSan），不等于已验证零泄漏。定长那把还专项跑到 `VideoToolRejection.FrameHeaderExtraSignallingBits…` 的定长分支，逐个 `[ OK ]` ⇒ 分档头 `#else` 侧、定长载体消费路径（18 B / 56 B 那两档的 432 B 对应值）、定长分支那三条断言都不是"编进二进制但永不执行"。 |
