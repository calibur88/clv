# CLV 音频帧规范

> 本文是 CLV 音频流（`stream_type = 1`、`codec_id = 1`，载荷为 **FLAC 帧本体**）的帧层与元数据层规范：帧头位域与四张码表、扩展编码号的写法、两道校验、流式子集**由谁判**、流声明对账、承载块与注释块 / 图标块的读回口径、错误码段位。字节口径以仓库内实现与用例钉住的值为准；本文缺项时**不自行补设定**。  
> 文档版本：0.8.2 · 日期：2026-10-21 · 载荷语法版本：**FLAC 帧本体，本层只解释帧头一层**；版本由流描述符（`codec_id` / `codec_version`）声明，帧内不另立版本字段。  
> **格式变更须伴随版本升号**：动到线上字节（字段宽度、码表、取值域、校验覆盖范围）即抬声明的 `codec_version`，只澄清语义不动布局才在本文档版本上递增；升号同轮必须重锚入库素材与本文的字节口径条目。  
> 调用面契约（句柄、入参出参、错误码文案）见 `include/CLV_Audio.h` 的头注释；一包一帧的外层、片序、时间基与扩展块结构见 `docs/容器规范.md`；分层与依赖见 `ARCHITECTURE.md`。

## 2 全局约定

| 项目 | 约定 |
|---|---|
| 一包一帧 | 一个数据包承载一个完整 FLAC 帧（含帧头与帧尾校验）。跨包的重组、片序与时间戳链都归容器层 |
| 本层两条独立义务 | **帧头自核**（同步码、块大小、采样率、声道、位深等字段自身自洽 + 帧尾校验）与**对账**（帧头的采样率 / 声道数 / 位深与流声明核对）。块大小**不在对账清单内**，它的约束由帧头自洽与「不要求恒定块大小」共同承担 |
| 校验不外包 | 帧尾 CRC-16 属本层自核义务：不把「后端会丢掉坏帧」当契约，也不依赖后端的内部处置 |
| 整数字节序 | 帧头的 `extra` 字节与帧尾 CRC-16 为**大端**；注释块的长度前缀为**小端**；图标块的长度与尺寸前缀为**大端**（两套取数式不能互用） |
| 输出 PCM | 一律整数、**交错**存放，**小端、二进制补码**；每样本字节数 = `ceil(bit_depth ÷ 8)`（16 位 = 2，24 位 = **3**，不取 4） |
| 时间戳 | 每帧输出**不带**时间戳：`CLV_AudioFrameInfoC` 的 `dts_ticks` / `pts_ticks` / `timebase_den` 恒为 0。音频的 DTS 由**逐帧实测的块大小**以样本为单位累加导出（`first_sample`），容器带的 `dts_delta` 只作校验、不作时间来源；**不得**以「首帧块大小恒定」推导后续帧的时间 |
| 句柄与线程 | 所有句柄（含 `CLV_AudioBuffer` / `CLV_AudioBlob`）按**单线程使用**契约计，引用计数不是原子量；`AddRef` / `Release` 须配平，对已归零的对象再 `Release` 不生效（不回收、不回绕） |
| 出参宽度 | 出参里的长度与计数字段都是 `uint32_t`：入参尺寸超出该域即判值域不成立（`kOutFieldMax`），不做静默截断 |
| 参数结构体自报 | `struct_size` 合法值两档：`sizeof(本结构)` 或 `0`（未填 = 与库同批编译的存量写法）；**其余任何值一律显式拒**（`CLV_AUDIO_VALUE_RANGE`），库不按字节长度去猜对方是哪一版布局。新代码一律显式填 `sizeof(*p)` |
| 内存耗尽 | 分配口本身不设防；本面每个公开入口把分配失败收敛成 `CLV_AUDIO_OUT_OF_MEMORY` 后回报——**坏流给句柄、分配失败给 null** |

## 3 帧头

### 3.1 字段布局

```text
偏移  长度        字段                取值与约束
0     1           同步码高 8 位       必须 = 0xFF
1     1           同步码低 6 位 + 保留 + 块策略位
                                    本层只受理 0xF8 与 0xF9：bit1（保留）必须为 0，
                                    bit0 = 块策略（0 = 按帧号，1 = 按样本号即变长块）
2     4 bit       块大小码            高 4 位，见 §3.2
2     4 bit       采样率码            低 4 位，见 §3.2
3     4 bit       声道码              高 4 位，见 §3.2
3     3 bit       位深码              bit3..bit1，见 §3.2
3     1 bit       保留                bit0 必须为 0
…     1..7 B      扩展 UTF-8 编码号   固定块流 = 帧号，变长块流 = 首样本号，见 §3.3
…     0/1/2 B     extra               仅特定块大小码 / 采样率码时在场，见 §3.2
…     1 B         帧头 CRC-8          覆盖以上全部帧头字节（不含自身），见 §3.4
帧尾  2 B         帧 CRC-16           覆盖整帧（不含自身），大端，见 §3.4
```

| 规则 | 内容 |
|---|---|
| 长度下限 | 可用字节 `< 7` 直接判帧头不成立；帧头解出后还**必须**给帧尾 CRC-16 留出 2 字节（`header_size > size − 2` 即不成立） |
| 「值只在流信息里给」 | 采样率码 `0b0000` 与位深码 `0b000` 解析为 **0**，由调用方回落流声明，本层不猜；该路径为鲁棒性保留，**不参与流式子集合法性判定**（`StreamableSubsetOk` 收到 0 视为未知、放行） |
| 帧长不在帧头里 | 本层只判帧头自洽，**不推断帧边界**；一包一帧的边界由容器外层 `total_size` 给出 |
| 出参纪律 | 判不成立时出参不被写入（`ParseFrameHead` 返回假、`CLV_AudioInspectFrame` 不填 `*out`） |
| 只读帧头 | `CLV_AudioInspectFrame` 只解帧头不解码，供逐帧取块大小以导出 DTS；它同时判子集，越子集返 `CLV_AUDIO_BLOCKSIZE_OUT_OF_RANGE`（与帧头不成立是两个码） |

### 3.2 四张码表

**块大小码**（4 bit，`0b0000` 为保留值，读到即拒）：

| 码 | 块大小 | 附加字节 |
|---|---|---|
| `0b0001` | 192 | — |
| `0b0010` | 576 | — |
| `0b0011` | 1152 | — |
| `0b0100` | 2304 | — |
| `0b0101` | 4608 | — |
| `0b0110` | 存储值 + 1 | 1 字节大端 |
| `0b0111` | 存储值 + 1 | 2 字节大端 |
| `0b1000` … `0b1111` | `1 << 码`，即 256 / 512 / 1024 / 2048 / 4096 / 8192 / 16384 / 32768 | — |

`0b0010..0b0101` 四档就是 `144 << 码`；定值码段整体就是 `1 << 码`。码 `0b1111` 给出 32768 样本，**越出子集上界**（§4），由子集判点拒、不在码表层拒。

**采样率码**（4 bit）：

| 码 | 采样率 | 附加字节 |
|---|---|---|
| `0b0000` | 0 = 值只在流信息里给 | — |
| `0b0001` | 88200 | — |
| `0b0010` | 176400 | — |
| `0b0011` | 192000 | — |
| `0b0100` | 8000 | — |
| `0b0101` | 16000 | — |
| `0b0110` | 22050 | — |
| `0b0111` | 24000 | — |
| `0b1000` | 32000 | — |
| `0b1001` | 44100 | — |
| `0b1010` | 48000 | — |
| `0b1011` | 96000 | — |
| `0b1100` | 存储值 × 1000（单位 kHz） | 1 字节大端 |
| `0b1101` | 存储值（单位 Hz） | 2 字节大端 |
| `0b1110` | 存储值 × 10（单位 Hz ÷ 10） | 2 字节大端 |
| `0b1111` | **禁用值**，读到即拒 | — |

走 extra 的三档若解出的采样率为 0，同样判帧头不成立。

**声道码**（4 bit）：

| 码 | 声道数 |
|---|---|
| `0b0000` … `0b0111` | 1 … 8（值 = 码 + 1） |
| `0b1000` / `0b1001` / `0b1010` | 都是 2（三种立体声去相关形态，本层只认声道数） |
| `0b1011` … `0b1111` | **保留值**，读到即拒 |

**位深码**（3 bit）：

| 码 | 位深 |
|---|---|
| `0b000` | 0 = 值只在流信息里给 |
| `0b001` | 8 |
| `0b010` | 12 |
| `0b011` | **保留值**，读到即拒 |
| `0b100` | 16 |
| `0b101` | 20 |
| `0b110` | 24 |
| `0b111` | 32 |

位深码表上合法的取值集宽于本层的受理集：**帧头位深与流声明对账、且流信息核对只收 `{16, 24}`**（§4、§5），8 / 12 / 20 / 32 的帧过不了流声明那一道。

### 3.3 扩展 UTF-8 编码号

首字节决定总字节数：`< 0x80` 是单字节 7 位载荷；否则首字节前导 1 的个数即总字节数 `lead`，**`lead` 只受理 2..7**（`10xxxxxx` 与 `11111110` 及以上都非法）。续字节**必须**是 `10xxxxxx`。首字节贡献 `7 − lead` 位、每个续字节贡献 6 位。

| `lead` | 位宽 | 该档可载上界 |
|---|---|---|
| 1 | 7 | `0x7F` |
| 2 | 11 | `0x7FF` |
| 3 | 16 | `0xFFFF` |
| 4 | 21 | `0x1FFFFF` |
| 5 | 26 | `0x3FFFFFF` |
| 6 | 31 | `0x7FFFFFFF` |
| 7 | 36 | `0xFFFFFFFFF`（与流信息总样本数的 36 位域同宽） |

位宽 = `(7 − lead) + 6 × (lead − 1)`，可载上界 = `2^位宽 − 1`（`ExtUtf8Cap`，七档逐值由编译期断言钉住）。

**最短形式两侧都判**：值越出本档可表达域（`v > Cap(lead)`）不成立；落得进更短一档（`v ≤ Cap(lead − 1)`）同样不成立——多装了字节就是非最短编码。单字节档没有「更短的一档」，故下界判直接比 0。

### 3.4 两道校验

| 校验 | 参数 | 覆盖范围 | 位置 |
|---|---|---|---|
| 帧头 CRC-8 | 多项式 `0x07`、初值 `0`、**不反射**、无收尾异或 | 帧头全部前置字节（CRC-8 自身之前） | 帧头末字节 |
| 帧 CRC-16 | 多项式 `0x8005`、初值 `0`、**不反射**、无收尾异或 | 整帧 `[0, frame_size − 2)` | 帧尾 2 字节，**大端** |

`frame_size < 3`（帧头 + 至少 2 字节尾）不成立。两道的表都在首次调用处就地建好（`Crc8Table` / `Crc16Table`）。

## 4 块大小档与流式子集：判定范围

**界值只有一处存放**：`src/audio/frame.h` 的具名常量；后端适配层、门面与流信息核对都引用那里，不另抄第二份。

| 界 | 值 | 常量 |
|---|---|---|
| 块大小上界 | 16 384 样本 | `kSubsetMaxBlocksize` |
| 低采样率时的更低界 | 采样率 ≤ 48 000 Hz 时块大小 ≤ 4 608 样本 | `kSubsetRateThresholdForShortBlock`、`kSubsetMaxBlocksizeAtLowRate` |
| 块大小下界 | 16-bit 时 64 样本；24-bit 时 72 样本 | `kSubsetMinBlocksize16`、`kSubsetMinBlocksize24` |
| 采样率拒档 | ≥ 655 355 Hz 的采样率一律不受理（判在流信息核对） | `kSubsetSampleRateRejectFloor` |

**哪些界由本层判、判在哪一格**：

| 判点 | 谁判 | 判什么 | 不成立时 |
|---|---|---|---|
| 帧头自核（逐帧） | 本层 `ParseFrameHead` | 同步码、两个保留位、四张码表的保留 / 禁用值、编码号字节合法性与最短形式、extra 字节是否够、帧头 CRC-8、帧尾 CRC-16、帧头之后留得下 2 字节尾 | `CLV_AUDIO_FRAME_HEADER_BAD` + 丢帧 + `frames_dropped_header` |
| 子集上界（逐帧，读侧） | 本层 `StreamableSubsetOk` | 块大小 ≤ 16 384；采样率 ≤ 48 000 时还须 ≤ 4 608。块大小或采样率为 0 视为未知、放行 | `CLV_AUDIO_BLOCKSIZE_OUT_OF_RANGE` + 丢帧 |
| 块大小落进流信息区间（逐帧，读侧） | 本层对账 | `si.min_blocksize ≤ blocksize ≤ si.max_blocksize` | `CLV_AUDIO_FIELD_MISMATCH` + 丢帧 + `frames_dropped_mismatch`（**不计连续失配段**） |
| 流信息核对 | 本层 `ParseStreamInfo`（公开口 `CLV_AudioParseStreamInfo` 与解码器建句柄是同一判点） | 载荷**必须恰为 34 字节**；采样率非 0 且 `< kSubsetSampleRateRejectFloor`；位深 ∈ `{16, 24}`；`min_blocksize` / `max_blocksize` 都不得为 0 且 `min ≤ max`；**`min_blocksize ≥ 位深档下界`**；两个帧长都非 0 时 `min_framesize ≤ max_framesize` | 公开口返 `CLV_AUDIO_VALUE_RANGE`；建句柄处按缺流信息处置 → 致命、拒解整条流 |
| 编码入口（落后端之前） | 本层门面 | `sample_rate ≠ 0`、`channels ∈ [1,8]`、`bit_depth ∈ {16,24}`、`reserved = 0`、`level ≤ 8`；`blocksize ≠ 0` 时先判**下界**（按位深）再判**子集上界** | 前四组判 `CLV_AUDIO_VALUE_RANGE`、块大小两档判 `CLV_AUDIO_BLOCKSIZE_OUT_OF_RANGE`；都是**交不出句柄**那一档 |
| 单帧 payload 上限 | 本层门面 | `size > 该流 max_packet_size` 即拒，判在解析之前 | `CLV_AUDIO_TOO_LARGE` |

**哪些界由后端兜**：

| 项 | 口径 |
|---|---|
| 子帧层流式子集约束 | 预测阶 ≤ 12、Rice 分块阶 ≤ 8 由 libFLAC 兜底：本层**不解子帧头**，编码侧以 `set_streamable_subset(true)` 交给后端 |
| 未压缩（verbatim）子帧兜底路径 | 后端把它当作衡量其余压缩子帧的基线，每个子帧都必然参与比较，压缩不划算时自然落未压缩帧；本层不设、也无处可设该开关。**写方义务**：封装 FLAC 时必须保留这条兜底路径——某帧压缩结果不小于其 PCM 原始尺寸时，必须以未压缩帧落盘。该路径不可关，它是 payload 上限里那点余量成立的依据 |
| 采样率的实际可接受区间 | 由后端决定，超出区间在打开编码器时被拒（公开面探针可复现：这一档返回底层失败而非受理）；本头只登记被拒档的边界，不另抄后端内部判定值 |
| 帧头过了但对端解不出 | 按「丢这一帧 + 计数」处置（`CLV_AUDIO_FRAME_HEADER_BAD` + `frames_dropped_header`），不判整条流 |
| 整条流的 MD5 | 后端逐帧喂时 MD5 校验必然对不上（那是对整条码流的承诺），解码侧关掉它；帧的对账由本层的帧头自核与对账承担 |

**两侧宽窄不对称是本版口径**：块大小**上界**只在写方按子集收（越上界编不出流）；读方的流信息核对不卡这一条上界（`min/max_blocksize` 是线上 16 位字段，任何取值都不过 65 535，写 `> 65 535` 的判式恒假），拿上界去卡流信息会误拒那一类流。读方的逐帧子集判点仍按上表生效。

## 5 流声明对账

| 项 | 口径 |
|---|---|
| 对账字段 | 帧头的**采样率 / 声道数 / 位深**与流声明（`CLV_AudioStreamParamsC`）比；帧头写 0 的字段（「值只在流信息里给」）不参与对账，回落流声明 |
| 单帧不一致 | 丢这一帧 + warn + `frames_dropped_mismatch`，返回 `CLV_AUDIO_FIELD_MISMATCH`，继续解下一帧；**不得**因单帧不一致回退为整条流或整文件判损坏 |
| 持续失配 | 同一字段连续失配到达 `kFieldMismatchRunLimit = 8` 帧即判流声明本身失真 → **拒解整条音频流**（其余流不受影响），返回 `CLV_AUDIO_STREAM_REJECTED` |
| 打断连续段 | 只有**整帧对账通过**才打断连续段——被丢的帧既不算证据也不复位；解码后实测的位深 / 声道与声明矛盾时同样进这一族判点 |
| 块大小 | **不在对账清单内**：它的约束由 §4 的帧头自洽与流信息区间共同承担，且不计连续失配段 |
| 建句柄处的核对 | 流信息与流声明互相矛盾（采样率 / 声道 / 位深任一项不等）即**拒解整条音频流**；该档照常交出拒解态句柄、不返 NULL |
| 拒解态 | 拒解态下除重置、关闭、统计口 `CLV_AudioDecoderStats` 自身外，其余入口一律返回 `CLV_AUDIO_STREAM_REJECTED`、一帧不出；重置是该态的唯一出口，且**不被该态拦截** |

## 6 元数据的落位与承载块

| 项 | 口径 |
|---|---|
| 不复用 FLAC 容器层 | 不使用 `.flac` 文件外壳；文件级元数据逐块搬进 CLV 扩展块 |
| 流信息 | 只走 **`ext_type = 5`**（载荷即 34 字节 STREAMINFO） |
| 其余文件级块 | 走 **`ext_type = 6`**，块内**首字节 = FLAC 原块类型码**（0 除外），其后逐字节照搬原块载荷——**搬运形态不新增字段、不改写** |
| 权威 | **流描述符为权威**：STREAMINFO 与流描述符不一致时拒解整条音频流，其余流不受影响 |
| 拆分 | `CLV_AudioSplitMetaBlock` 把承载块拆成「类型码 + 原块载荷」；判定只看类型码，不解释载荷 |
| 分类与去向 | 类型码 `0` = 流信息混入承载块 → **丢块 + 计数 + 继续**（`CLV_AUDIO_METADATA_BAD`，计数 `blocks_rejected_streaminfo`）；`1` = 填充 → **丢弃不承载**（`blocks_dropped_padding`）；`2..6` = **计入承载 + 计数**（`blocks_stored`）；`≥ 7` = **跳过 + 计数**（`CLV_AUDIO_BLOCK_TYPE_UNSUPPORTED`，`blocks_skipped_unknown`）。**三种处置都不判损坏** |
| 句柄不留副本 | `STORE` 的实际含义是**计入承载并计数**，句柄内**不留字节副本**：注释块与图标块的字节本来就由容器读方稳定交出（有效期到 Close），解读走无状态只读口即可 |
| 音频流的扩展块义务 | 视频流必挂 `ext_type = 3` 参数块那条**不适用**于音频流；音频流不写该块 |

### 6.1 STREAMINFO（34 字节）位域

```text
位宽   字段              取值与约束
16     min_blocksize     不得为 0；不得小于位深档下界（64 / 72）
16     max_blocksize     不得为 0；不得小于 min_blocksize
24     min_framesize     可为 0（未给）
24     max_framesize     可为 0；与 min 都非 0 时不得小于 min
20     sample_rate       不得为 0；不得 ≥ 655 355
3      channels - 1      线上存「声道数 − 1」，解出 1..8
5      bit_depth - 1     线上存「位深 − 1」，本层只收 {16, 24}
36     total_samples     未知时填全 1（2^36 − 1）
128    MD5 摘要          本版本该字段恒为零，不参与校验
```

| 规则 | 内容 |
|---|---|
| 位序 | 字段按上表顺序大端填充；`sample_rate` 起的那 64 位窗口里依次落 20 / 3 / 5 / 36 位（`ParseStreamInfo` 的位移式） |
| 摘要字段 | **本版本该字段恒为零，不参与校验**。编码侧关掉了对端的整条 MD5 计算，产出时 16 字节留零；读回视图如实搬运线上字节，外部素材带的非零摘要原样交出、库不比对 |
| 编码侧产出 | 六个统计字段由本次编码的**实测值**给出（最小 / 最大块大小、最小 / 最大帧长、总样本数）；**须先冲刷、且先喂过样本**：一个样本都没喂时块大小与帧长统计为空，取流信息口返回 `CLV_AUDIO_STATE_ERROR` |
| 长度 | 载荷长度不恰为 34 字节即判「缺流信息」，走致命档 |

## 7 注释块与图标块的读回视图

两个面都是**无状态只读**：本层不提供注释块 / 图标块的写入或改写口；写方要塞什么内容由调用方决定并经容器搬运，本层只在读侧解释。取到的指针跟着源字节走（容器关闭前稳定），本面对这些字节**不复制、不持有、不改写**。

### 7.1 VORBIS_COMMENT（原块类型码 4）

```text
u32 小端 vendor 长度 | vendor 串 | u32 小端 注释条数 | 每条 { u32 小端 长度, "KEY=VALUE" }
```

| 项 | 口径 |
|---|---|
| 键名比对 | **不区分大小写**，比的是 `=` **左侧**；键与值都不含 `=` 本身 |
| 同名多条 | 按块内出现次序取第 `occurrence + 1` 次命中（`occurrence` 从 0 起） |
| 字符串 | vendor 与值都是 UTF-8 字节串，**不保证 NUL 结尾**，读方按长度用 |
| 条目数 | **不是声明值**，必须与实有条数对得上：逐条走完，任何一条的长度越出块界即整块不成立 |
| 条目形态 | 每条**必须**带 `=`；没有 `=` 即整块结构不成立（这样查询口返回「不成立」只表示块坏，不与「没查到」混成一个出口） |
| 判级 | 块内任一长度前缀越出块界、条目数与实有条数不符、条目里没有 `=` ⇒ 判**该块内容不成立**，只拒这一块，不影响流、不影响别的块（`CLV_AUDIO_METADATA_MALFORMED`）。这一档与「承载块首字节 = 0」的 `CLV_AUDIO_METADATA_BAD` **分开设**：后者是搬运层问题（丢块 + 计数 + 继续），前者是内容层问题（解析失败，出参不留半份） |
| 调用次序 | `CLV_ContainerReaderGetExtBlock` → `CLV_AudioSplitMetaBlock` → `CLV_AudioParseVorbisComment` + `CLV_AudioVorbisCommentEntryAt` / `CLV_AudioVorbisCommentFindKey` |

### 7.2 视图自洽要求

注释块视图（`CLV_AudioVorbisCommentC`）里的指针都落在调用方递交进来的那块字节上，库不复制、不持有。

**注释块视图必须由本头的解析函数产出，不得由调用方自拼**；**自拼且不自洽的视图按结构不成立拒绝，不再交出块外字节**。

两个查询口（取第几条、按键名查）入口共用三条自洽校验（`VCommentViewIsSane`）：

| # | 校验 | 不过时 |
|---|---|---|
| 1 | 块指针非空 | `CLV_AUDIO_METADATA_MALFORMED`，不写出参 |
| 2 | 声明块长不小于头部必需字段（4 字节厂商串长度 + 4 字节条目数 = **8**） | 同上 |
| 3 | 条目区起点 `8 + vendor_length` **不大于**声明块长——起点按 64 位算式算，长度加减在这一层就不存在下溢与回绕两笔糊涂账 | 同上 |

不自洽的视图**不进条目扫描**，因此不会从块外取字节。视图过了自洽这一道之后，索引越出 `comment_count` 判 `CLV_AUDIO_VALUE_RANGE`；自洽视图查不到该键仍照实报 `CLV_AUDIO_COMMENT_KEY_NOT_FOUND`（出参不写）。

### 7.3 PICTURE（原块类型码 6）

```text
图标类型码 | MIME 长度 | MIME | 描述长度 | 描述 | 宽 | 高 | 位深 | 调色板色数 | 图像数据长度 | 图像数据
```

| 项 | 口径 |
|---|---|
| 字节序 | 长度前缀与尺寸字段一律 **u32 大端**——与注释块的小端**正反一趟**，两套取数式不能互用 |
| 定长部分 | 8 个 u32 共 **32 字节**；三个变长段都允许零长，全零长的退化块恰 32 字节，是**合法结构**（宽 / 高 / 位深 / 色数全 0 的图标块是真实片子里的常见形状，解析口不因此判不成立，一律原样交出） |
| 判级 | 任一长度前缀越出块界即 `CLV_AUDIO_METADATA_MALFORMED` |
| 图像数据 | 原样交出，本层**不解码、不裁剪、不校验其像素内容** |

### 7.4 扩展声道掩码

| 项 | 口径 |
|---|---|
| 承载 | `WAVEFORMATEXTENSIBLE_CHANNEL_MASK` **可以**随注释块进容器 |
| 依赖 | **帧头与声道顺序不得依赖扩展掩码**——这是流式子集的一条，读方搬运该块时忽略该键才算守住 |
| 尽力剥离 | 承载块进解码器门前先尽力剥掉该键：剥得动就剥并记进 `mask_keys_removed`；剥不掉（注释块结构本身不成立）**原样收录、照常继续**，不拦 |
| 确定性口 | 要确定性剥离并拿到结果块的走 `CLV_AudioStripChannelMask`：`removed` 报剥掉的键数，一块都没剥掉时结果块与输入**逐字节相同**；剥不动时如实返 `CLV_AUDIO_METADATA_MALFORMED`、不产出结果块。`CLV_AUDIO_METADATA_BAD` 不从这里出——那一档只管承载块首字节 = 0 |

## 8 错误码段与留白

| 项 | 口径 |
|---|---|
| 段位 | 音频面是**独立枚举**：成功恒 0，失败码落在 **32 到 63** 段内，**现用到 49**；枚举成员 17 个、失败码 16 个 |
| 段间关系 | 五面的错误码各自独立枚举：文件与容器从 1 顺排、音频 32 到 63、视频 64 到 95、节拍 96 起，不得跨头比对数值——各头的 1 语义无关 |
| 追加纪律 | 号位只在**段尾追加**：段内不改序、不复用留白位、既有码值与语义不动；**退场码的号位同样留白，不再投给任何新码**，因此下列数值不因任何退场而前移 |
| 留白号位 | **41 与 45 不复用**。41：该档对应的两类情形已分别由 `TOO_LARGE` 与 `STATE_ERROR` 覆盖，实现里无产出点；45：非子集 / 能力外请求一律走上列具体码，本层不投「不支持」这一格 |
| 内部枚举的范围 | `src/audio/status.h` 的 `AudioErr` 只覆盖实现层会产出的码，**止于 47**；段尾追加的 48 / 49 只在门面（承载块解读口）直接产出、不经内部枚举，其数值由门面的编译期断言显式钉住；41 / 45 两个空位同样显式钉住，后继追加若把号位挤偏就先红 |

| 值 | 名称 | 何时回报 |
|---|---|---|
| 32 | `CLV_AUDIO_INVALID_HANDLE` | 句柄为空或已关闭 |
| 33 | `CLV_AUDIO_INVALID_ARGUMENT` | 出参指针为空、数组与计数不匹配、载荷为空等 |
| 34 | `CLV_AUDIO_VALUE_RANGE` | 参数值域不成立：采样率为 0、声道越 `[1,8]`、位深非 16/24、索引越出条目数、入参尺寸越出 `uint32_t` 域 |
| 35 | `CLV_AUDIO_FRAME_HEADER_BAD` | 帧头自核不过：同步码不符、字段取保留 / 禁用值、编码号非法、帧头 CRC-8 不符、帧尾 CRC-16 不符、帧头过了但后端解不出 → 丢帧 |
| 36 | `CLV_AUDIO_FIELD_MISMATCH` | 对账不一致：采样率 / 声道数 / 位深与流声明不符，或块大小越出流信息给的区间 → 丢帧 |
| 37 | `CLV_AUDIO_BLOCKSIZE_OUT_OF_RANGE` | 块大小越出流式子集上界、越出编码入口的档位下界，或与流信息不符 → 丢帧（读侧）/ 交不出句柄（写侧） |
| 38 | `CLV_AUDIO_STREAMINFO_ABSENT` | 缺流信息：未给 / 长度不符 / 字段越出本层子集（位深集合、采样率上界、块大小下界）→ **拒解整条流** |
| 39 | `CLV_AUDIO_METADATA_BAD` | 承载块首字节 = 0（STREAMINFO 不得出现在此）→ 丢块 + 计数 + 继续 |
| 40 | `CLV_AUDIO_BLOCK_TYPE_UNSUPPORTED` | 承载块类型码 ≥ 7 → 跳过 + 计数，不判损坏 |
| 42 | `CLV_AUDIO_TOO_LARGE` | 单帧超过该流 payload 上限（判在解析之前） |
| 43 | `CLV_AUDIO_STATE_ERROR` | 调用顺序不成立：已冲刷后继续喂、未喂样本就取流信息、零样本时取流信息 |
| 44 | `CLV_AUDIO_OUT_OF_MEMORY` | 库内分配失败 |
| 46 | `CLV_AUDIO_BACKEND_FAILURE` | 底层编解码器返回失败但结构上看不出问题（含采样率越出后端可接受区间） |
| 47 | `CLV_AUDIO_STREAM_REJECTED` | 流信息与流声明矛盾，或同一字段持续失配到阈值：建句柄时交出拒解态句柄并返回本码，此后除重置、关闭、统计口外统一返回本码 |
| 48 | `CLV_AUDIO_METADATA_MALFORMED` | 注释块 / 图标块的字节结构不成立：长度前缀越出块界、条目数与实有条数不符、条目里没有 `=`；以及视图自洽校验不过 |
| 49 | `CLV_AUDIO_COMMENT_KEY_NOT_FOUND` | 注释块里查不到该键，或该键的命中数不够 `occurrence` |

**观测口**：`CLV_AudioStatsC` 的九项一次取回——`frames_ok`、`frames_dropped_header`（凡按帧头一类原因丢的帧都进这里：自核不过、帧尾 CRC-16 不符、越出子集，以及帧头过了但对端解不出）、`frames_dropped_mismatch`、`blocks_stored`、`blocks_dropped_padding`、`blocks_rejected_streaminfo`（只记分类出的类型码 = 0 那一档）、`blocks_skipped_unknown`、`mask_keys_removed`、`stream_rejected`。**计数只增不清零，重置后保留。**

## 9 上限一览

| 对象 | 上限 / 域 | 来源 |
|---|---|---|
| 采样率 | `1 .. 655 354`；实际可接受区间由后端决定 | `kSubsetSampleRateRejectFloor`（判在流信息核对）、后端 `init` |
| 声道数 | `[1, 8]`；帧头声道码 `0b1011..0b1111` 为保留值 | 编码 / 解码参数入口、`ParseFrameHead` |
| 位深 | `{16, 24}`（流声明与流信息都只收这一对） | 门面入口、`ParseStreamInfo`；公开头合法域条 |
| 块大小 | 下界 64（16-bit）/ 72（24-bit）；上界 16 384，采样率 ≤ 48 000 时 4 608 | `kSubsetMinBlocksize*`、`kSubsetMaxBlocksize*` |
| 帧头长度 | 变长；可用字节 `< 7` 不成立，且解出后必须留得下 2 字节帧尾 | `ParseFrameHead` |
| 扩展 UTF-8 编码号 | 最长 7 字节、36 位（与流信息总样本数同宽）；最短形式两侧都判 | `ExtUtf8Cap` |
| 压缩档 `level` | `[0, 8]`；不承诺跨版本稳定 | `CLV_AudioEncParamsC.level` 判点 |
| 单帧 payload | 该流 `max_packet_size` | `CLV_AUDIO_TOO_LARGE`；`max_packet_size` 本身属容器侧字段 |
| 连续失配阈值 | 8 帧 | `kFieldMismatchRunLimit` |
| 承载块解读的长度前缀 | `uint32_t` 域；入参尺寸越出它即判值域不成立 | `kOutFieldMax` |
| 每样本字节数 | `ceil(bit_depth ÷ 8)`：16 → 2，24 → 3 | `BytesPerSample` |

**帧头与流信息之间没有的事**：帧头里不写帧长；流信息不声明每条流的 `max_packet_size`（那是容器侧字段）；两处的采样率 / 声道 / 位深靠 §5 的对账而非结构自证来核对。

## 10 预留与未落地

| 项 | 状态 |
|---|---|
| 块大小码 `0b0000`、采样率码 `0b1111`、位深码 `0b011`、声道码 `0b1011..0b1111`、帧头的两个保留位 | 保留 / 禁用值，读到即判帧头不成立；语义未赋予 |
| 错误码留白位 41 / 45 | 不复用，见 §8 |
| 子帧与残差的位级语法 | **不由本层解析**：本层只解帧头一层，子帧层语法与流式子集的子帧约束由后端按 FLAC 原语法处理 |
| 多声道布局 / channel mask 的定义 | 未赋予语义；掩码只随注释块搬运、帧头与声道顺序不依赖它 |
| 音频 seek 点的精度要求（是否必须帧边界） | 未赋予约束；seek 与索引属容器层 |
| 注释块 / 图标块的写入口 | 本层不提供；写方内容经容器搬运，本层只在读侧解释 |
| STREAMINFO 的 MD5 | 本版恒零、不参与校验；将来启用整条校验属格式侧变更 |
| `ext_type = 5` / `6` 的载荷语义 | 容器层只搬运与校验 CRC，除视频参数块的存在性外不解释载荷；这两类的字段形态由本文规定 |

## 11 术语

| 术语 | 定义 |
|---|---|
| 帧头自核 | 本层对帧头字节的自洽判定（同步码、码表取值、编码号、CRC-8、帧尾 CRC-16），与容器层校验相互独立 |
| 对账 | 把帧头里带值的字段与流声明逐帧比对；单帧不一致丢帧，同一字段持续失配拒解整条流 |
| 流式子集 | 本层受理的帧头层约束集合：块大小上下界、采样率与位深码不得取保留值、声道顺序不依赖扩展掩码 |
| 变长块流 | 块策略位 = 1：编码号是首样本号，每帧块大小可以不同，DTS 必须逐帧实测块大小累加 |
| 承载块 | `ext_type = 6` 的扩展块：首字节 = FLAC 原块类型码，其后照搬原块载荷 |
| 计入承载 | 分类 + 计数，**句柄内不留字节副本**（字节本来就由容器读方交出） |
| 视图 | 注释块 / 图标块的读回结构体：指针落在调用方递交的那块字节上，不复制、不持有 |
| 自洽视图 | 满足 §7.2 三条入口校验的视图；不自洽即按结构不成立拒绝 |
| 拒解态 | 致命码置下的句柄态；除重置、关闭、统计口自身外其余入口一律返回拒解码 |

## 12 溯源

本文的帧头字段、码表与两道校验对应 FLAC 帧格式规范（RFC 9639）的「帧」与「元数据块」两节；下表只登记对应关系与**本层改写之处**，字节口径以本文与实现为准。

| 本文口径 | 对应条款主题 | 与本层的关系 |
|---|---|---|
| §3.1 字段布局、§3.2 四张码表 | FLAC 帧头与帧头码表 | 照本层实现列全；本层**只解帧头**，子帧不进本层 |
| §3.3 扩展 UTF-8 编码号与容量算式 | FLAC 的扩展 UTF-8 编码 | 本层把最短形式**两侧都判**（越本档域与落得进更短一档都不成立），比「只防超长」更硬 |
| §3.4 CRC-8 / CRC-16 参数 | FLAC 的帧头校验与帧校验 | 本层自行判帧尾 CRC-16，不外包给后端 |
| §4 子集界值 | FLAC 流式子集约束 | 帧头层由本层判；子帧层（预测阶、Rice 分块阶）由后端兜 |
| §6.1 STREAMINFO 位域 | FLAC 的流信息元数据块 | 本层把位深集合收窄为 `{16, 24}`、按位深加块大小下界、摘要字段恒零不参与校验 |
| §7.1 VORBIS_COMMENT 形态 | FLAC 的注释元数据块（V-comment） | 本层把「条目必须带 `=`」「条目数须与实有条数相符」做成整块结构判点 |
| §7.3 PICTURE 形态 | FLAC 的图片元数据块 | 全零长的退化块在本层是合法结构 |
| §7.4 扩展声道掩码 | FLAC 的 `WAVEFORMATEXTENSIBLE_CHANNEL_MASK` 约定 | 掩码可随注释块进容器，但声道顺序不依赖它；搬运时尽力剥离 |
