# CLV 字幕规范

> 本文是 CLV 字幕流（`clv_s1`，`codec_id = 0`）的权威规范：覆盖语法、块与文本行、属性、时间、布局与重叠、滚动、安全、转义、与容器的关系（含字幕包载荷外层与全局样式块的字节布局）、错误处理、示例、渲染管线使用约定与测试要点。
> 文档版本：**0.9.1** · 格式版本：**`clv_s1 0.1-r13`** · 日期：2026-10-29。
> payload 编码：UTF-8 · **Unicode 基准：18.0.0**（utf8proc 2.12.0 / SheenBidi 3.0.0 / HarfBuzz 14.4.0 / FreeType 2.14.3 / simdutf 9.1.2）。
> 一个字幕包 = 一个显示段，可含多个块。
> 容器结构（`stream_desc` / 数据包框架 / 扩展块框架 / 时间基）见 `容器规范.md`；字幕侧的**载荷内布局**由本文 §9.2 / §9.3 定义，容器规范只引用、不加框架字段。
> 公开 C ABI 的版本轨道：字幕面自 `0.9.0` 追加，随 `1.0` 一并纳入冻结轨道；函数、结构与错误码见 `include/CLV_Subtitle.h` 与 `API.md`。
> 实现落点：`src/subtitle/`（解析 / 布局 / 合成）、`src/subtitle/cal/`（CAL 接口与降级）、`backends/text/`（第三方适配）、`platform/font/`（系统字体解析）。

## §1 语法

~~~ebnf
tab        = "\t" ;
document   = { block | text-line | comment | blank } ;
block      = "<#" id "/" newline { block-line } "/>" newline ;
block-line = attr newline | blank | comment | other newline ;
attr       = key ":" SP value ;
text       = { any-char-except-LF } ;
value      = { any-char-except-LF } ;
text-line  = "#" id ( SP | tab ) text newline ;
comment    = line-comment | block-comment ;
line-comment  = "//" ... newline ;
block-comment = "<!--" ... "-->" newline ;
blank      = { SP | tab } newline ;
other      = { any-char-except-LF } ;
id         = digit+ ;
~~~

**规则：**

| 条 | 内容 |
|---|---|
| 块定义 | `<#N/` 后换行，属性行，`/>` 独占一行 |
| 块内 | 空行、注释行、无法识别的行忽略，不参与属性解析 |
| 文本行 | 必须匹配 `^#\d+[ \t]`，分隔符为单个空格或制表符，其后字节原样保留为 `text`；否则整行忽略 |
| CR | `text` / `value` 中的 CR 是**字面量**，库不剥；CRLF 文件由调用方先剥 CR，否则行尾 CR 参与语法判定（块闭合行会不成立、属性值会带 CR） |
| 块外内容 | 除空行、注释外，一律忽略 |
| ID | 全局唯一，严格递增，允许跳号 |
| ID 范围 | `1 .. 2^32-1`，超范围该行/该块忽略 |
| ID/start 流级单调 | 均跨包，解码器维护流级 max ID 与 last start；seek 时重置，**重置后首个块无条件接受作为新基准** |
| 文本行作用域 | 仅在其有效块定义之后、下一个块定义之前有效；否则整行忽略 |
| 空白行 | 仅含空白（SP/tab）的行视为空行 |
| 未定义引用 | 该文本行不显示 |
| 新块出现 | 前一块结束，属性不继承 |
| key | 区分大小写，全小写 |
| value 首尾空白 | 保留；实现可 trim |

## §2 块与文本行

**块作用域：** 从块定义起，到下一个块定义或文档结束。被忽略的块定义仍作为块边界。

**源 LF 与换行的分工：** 源文本的 LF 只终止文本行、不进入内容；一行 `#N` 文本里要出第二个显示行，只能靠 `[\n]`（§8.6 / §5.1）。

**多行组：** 同一块 N 下连续多个 `#N` 行 → 垂直堆叠。中间插入其他块 ID → 前一组结束。前一组结束后再出现该组 ID 的文本行，整行忽略。

**块生命周期：** 由 `time` 决定，与包边界无关。**块定义与其文本行必须同包**——丢包后解析状态无恢复路径。

**文档序：** 块与文本行按出现顺序排列，等于有效块 ID 升序；均跨包，故文档序也是流级顺序。「前一块」「后一块」「下一块」均指流级文档序。

## §3 属性

### 3.1 必需

| 属性 | 格式 |
|---|---|
| `time` | `HH:MM:SS.mmm - HH:MM:SS.mmm` |

缺 `time` → 整块不显示。

### 3.2 可选

| 属性 | 默认值 | 单位 / 取值范围 |
|---|---|---|
| `font-color` | `#FFFFFF` | `#RRGGBB` / `#RRGGBBAA` |
| `font-size` | 屏高的 4% | `N%`（相对屏幕高）或 `Npx`（视频像素） |
| `font-family` | 实现默认 | 字符串，逗号分隔 |
| `font-weight` | `normal` | `normal` / `bold` / `100`–`900` |
| `font-style` | `normal` | `normal` / `italic` |
| `text-align` | `center` | `left` / `center` / `right` |
| `position` | 底部居中 | `x% y%` 或 `xpx ypx`；锚点 = 块中心；原点 = 左上角，x 向右 y 向下；百分比相对屏幕 |
| `line-height` | `120%` | `N%` 或 `Npx`；% 相对 font-size |
| `opacity` | `1.0` | `0.0`–`1.0` |
| `scroll` | 无 | `top` / `bottom` / `left` / `right` |
| `scroll-rect` | 无（仅滚动块有效） | `x y w h`；`%`（相对屏幕）或 `px`；四分量同单位；`w` / `h` 必须 > 0；`x + w` / `y + h` 可越屏 |

**字号基准：** `px` = 视频像素。跨分辨率内容应使用 `%`。默认 `4%` 在 1080p 下 ≈ 43px。

**alpha 叠加：** `font-color` 含 AA 分量时，最终 alpha = AA 分量 × opacity。

**未定义属性忽略。`x-*` 前缀 v0.1 忽略。** `text-shadow` / `text-stroke` v0.1 不定义，按未知属性忽略。

### 3.3 未知属性

忽略，不报错。不匹配 `attr` 语法的行按无法识别行忽略。

## §4 时间

| 规则 | 内容 |
|---|---|
| 格式 | `HH:MM:SS.mmm`，小时 ≥ 2 位，毫秒固定 3 位 |
| 分隔 | 起止用 ` - `（空格-连字符-空格） |
| 必需 | 缺 `time` → 整块不显示 |
| 单调 | start 在整个字幕流内单调非递减（跨包，按流级文档序）；违反 → 仅忽略违规块 |
| `end < start` | 整块不显示 |
| `end = start` | 合法，零时长，不显示；**该块为无效块**（§9） |
| 重叠 | 允许 |
| 精度 | 毫秒，内部转 tick；1 ms = 1,081,080 tick（精确映射） |

> tick 换算依据：字幕时间基 `1/1081080000`（`容器规范.md` 的文件头一节），故 `1081080000 / 1000 = 1,081,080` tick/ms，整除成立。时间换算全程用整数，浮点不参与。

## §5 布局与重叠

| 情形 | 规则 |
|---|---|
| 显式 `position` | 按位渲染，锚点 = 块中心；碰撞由作者负责 |
| 无 `position` 的静态块 | 底部居中区域内，按 start 升序自动堆叠（后出现的往上挪一行距） |
| start 相同 | 按块 ID 升序堆叠（ID 小的在下，ID 大的在上） |
| 超过屏幕顶部 | 停止上挪，**后出现的块在上层覆盖显示** |
| 滚动块 | 独占其内容条带，不参与堆叠；与静态块重叠时滚动块在上层；**静态块继续渲染，只有落在条带内的部分被遮挡**（条带几何见 §6.1） |
| 静态块不触发滚动块硬切 | 滚动块结束或被硬切后，若静态块仍在 time 内，则继续显示 |

**默认位置：** `position: 50% 90%`（块中心在屏宽 50%、屏高 90% 处）。

**`scroll-rect` 下的 `position` 基准：** 滚动块传了 `scroll-rect` 时，`position` 的坐标系是该**视口矩形**，`%` 相对视口宽高；其余情况（静态块、滚动块未传 `scroll-rect`）一律相对屏幕。视口本身固定不动，文字在视口内滚动。

**包级默认：** §9.2 的包级 `position` / `alignment` 先于块属性生效，块自己的 `position` / `text-align` 覆盖包级默认（覆盖序见 §13.6）。

### 5.1 换行、自动折行与多行

| 项 | 规则 |
|---|---|
| 显式换行 | 内容含 U+000A 即在该处断行，前后各成一行；**唯一来源 `[\n]`**（§8.6） |
| 空行 | 连续 `[\n][\n]`、行首或行尾的 `[\n]` 都产出**空行，且占一个行高** |
| 自动折行触发 | 单行内容宽 > **可用行宽** |
| 可用行宽 | **恒 = 屏宽，与 `scroll-rect` 无关**；视口只裁不参与求值（本节求值次序的推论） |
| 断行点 | 西文在空格 / 标点后断，**不切断单词**；CJK 逐字可断；**单个词超可用行宽则强制断**（宁可切断也不溢出） |
| 断点空格 | 断点处的那个空格**两侧都剥** —— 不留在行尾（否则行宽虚高一格），也不留在行首（否则左对齐看着没对齐） |
| 避头尾 | 标点不得出现在行首（避头）、不得出现在行尾（避尾）；**集合见附录 A**，跨实现要能复现同一份表 |
| 与显式换行的关系 | **显式换行优先**；每个显式段再各自自动折 |
| 行高 | `line-height` × 已定字号，缺省 120%（§3.2；不属于实现自定项） |
| 多行总高 | 行数 × 行高 |
| 对齐 | **每行独立**按 `text-align` 对齐 |
| 内容包围盒 | 宽 = 最长行；高 = 行数 × 行高 |
| Bidi | **每行独立**（换行 = 段落分隔） |
| 逐码位回退 | 换行符不参与回退；每行内部正常逐码位（§13.2） |
| 堆叠 | 静态块自动堆叠按**块总高**（多行）向上堆 |

**求值次序：字号 → 行高 → 内容包围盒 → 与视口比对 → 裁剪，只有这一个方向。**

| 步 | 量 | 基准 |
|---|---|---|
| 1 | `font-size` | `px` 直取；`%` = 0.1% **屏高**。百分比字号的基准恒为**屏幕**，**不随 `scroll-rect` 变** —— 以视口为基准就是换了个形式的"先定框后放字" |
| 2 | `line-height` | `px` 直取；`%` = 0.1% **已定的字号**（§3.2） |
| 3 | 内容包围盒 | 按第 1 / 2 步的结果整形后算出：宽 = 最宽行 advance 之和，高 = 行数 × 行高（§6.1） |
| 4 | 视口 | `scroll-rect` 换算成屏幕绝对矩形（`%` 相对屏幕），与第 3 步的包围盒比对 |
| 5 | 裁剪 | 视口外的部分不分配、不绘制（§6.1「裁剪」行） |

**反序的后果**：先定框、后放字时，字号一旦大于框就会被缩字或裁掉而**显示不全**。渲染器不替作者缩字，也不因框小而把字改小 —— 超出部分被裁掉**只在作者有意让文字超出视口时才是预期行为**（作者要小字就写小字号）。

**两个轴要分开说**（同一条次序的两个推论，方向不同结论不同）：

| 轴 | 裁剪是否预期 | 规则 |
|---|---|---|
| 滚动轴（内容穿过视口那一维） | **预期，且定义性如此** | 推进轴 = 视口 + 内容 ⇒ 起点内容整体在视口外、终点也是，中途必然只看得见一部分 |
| 交叉轴（内容排布那一维） | **装得下就不许裁** | 视口在该轴**装得下内容包围盒**（水平滚 = 行数 × 行高，垂直滚 = 最宽行宽）时，渲染器把内容**夹进视口内**；默认锚点（视口 90%）不得把行推到视口外。装不下时夹不动 ⇒ 那一档才是"作者有意溢出" |

判"装得下"用的量是**内容包围盒**，不是实测墨的范围 —— 字形墨在行框外的伸出量，与静态块越出屏幕属同一档，不另开规则。

### 5.2 描边外沿

描边画在字形轮廓**外侧**，宽度 = `stroke_width` 像素，颜色 = `stroke_color_rgba`（载体见 §9.3）。
外沿 = 每侧一个 `stroke_width`，合计 **2 × 宽**；它计入内容包围盒，三个消费点必须用同一份量：

| # | 消费点 | 规则 |
|---|---|---|
| 1 | 推进轴（视口 + 内容） | 垂直 = 视口高 + 行数 × 行高 + 2×宽；水平 = 视口宽 + 最宽行 advance + 2×宽 |
| 2 | 交叉轴「装得下」判断 | 比较双方 = 含描边的内容包围盒与视口；夹取也按含描边的行框 |
| 3 | 脏矩形 | 含描边外沿（按实际绘制像素的包围盒取） |

| 项 | 约定 |
|---|---|
| 合成次序 | 先描边环、后字本体；两层各自乘 `opacity`（千分） |
| 段落边界 | 多段回退时每段各自描边，段与段之间不串色 |
| 彩色字形 | 彩色位图不描边（本版交互口径，见 §13.5） |
| 缺字 | `.notdef` 同样描边 |

> 注：交叉轴判据要按含描边的行框重算；`stroke_width = 0` 时本节各量与 r12 完全一致（恒等，不改既有 golden）。

## §6 滚动

| 值 | 入口 | 方向 |
|---|---|---|
| `top` | 底部 | 向上滚（朝顶边） |
| `bottom` | 顶部 | 向下滚（朝底边） |
| `left` | 右边 | 向左滚（朝左边） |
| `right` | 左边 | 向右滚（朝右边） |

**命名 = 目标边；入口 = 对面一侧。**

| 情形 | 行为 |
|---|---|
| time 内提前滚完 | **v0.1 不可达**：无更快速度；冻结在终点的语义保留，v0.2 恢复 `scroll-speed` 后可达 |
| time 结束仍未滚完 | **v0.1 不可达**：速度按（视口 + 内容）/时长，恰好滚完；`end_time` 到点仍按下一行硬切 |
| `end_time` 到点 | **v0.1 可达**：无论文字是否恰好滚完，一律硬切，不延后、不加速、不保留残影、不淡出 |
| 后续滚动块 start 到达 | 立即硬切前者，未滚完部分丢弃 |
| 静态块 start 到达 | 不触发当前滚动块硬切；静态块按 §5 分层显示 |
| 同一时刻多个滚动块 start 到达 | 按文档序，后者硬切前者 |

**「后续滚动块」定义：** 按流级文档序，当前正在显示的滚动块之后的第一个含 `scroll` 的块；**跨包统一调度**。

**速度（v0.1 唯一一档）**：`scroll-speed` 已删除；速度恒为 `(视口推进轴 + 内容推进轴) ÷ time 时长`。视口缺省 = 整屏，传 `scroll-rect` 时为指定矩形。

### 6.1 条带几何：按内容包围盒

条带的几何按**内容包围盒**取，不取整屏：条带跟着内容走，不铺满整屏。§5 的遮挡范围与 §14 的滚动判据都据此给出可断言的期望值。

| 项 | 规则 |
|---|---|
| 视口 | 不传 `scroll-rect` = 整屏；传了 = 指定矩形，**固定不动**；滚动文字只在视口内可见。视口**不参与字号与包围盒的求值**，它只裁已经定好大小的字（次序见 §5） |
| 推进轴尺寸 | **视口推进轴 + 内容推进轴**：垂直 = 视口高 + 行数 × `line-height`；水平 = 视口宽 + 单行 advance 之和 |
| 交叉轴尺寸 | = 内容包围盒在该轴的 extent。垂直滚取组内最宽行的像素宽；水平滚取行高 |
| 条带位置 | 由块锚点决定：有 `scroll-rect` 时 `position` 相对视口，否则相对屏幕；条带随内容平移，视口不动 |
| 边距 | **不加额外边距**：条带就是包围盒本身，描边宽度按 §9.3 / §3.2 计入包围盒 |
| 遮挡范围 | 只遮**内容包围盒**内的静态块像素，**不随视口扩大**；视口外静态块照常可见 |
| 堆叠 | 滚动块不参与 §5 的自动堆叠，也不推动静态块上挪 |
| 裁剪 | 滚动文字只画视口内；视口越出画面的部分不分配、不绘制；静态块裁到视频画面。**交叉轴另有一条**：视口在该轴装得下内容包围盒时必须先夹进视口再画，不得靠裁剪兜底锚点问题（见 §5 的两轴表） |
| 脏矩形 | 本次绘制覆盖区按实际绘制像素取，**不铺满视口**；合并与容量规则见 §13.5 |

**多行滚动块**：推进轴 = 视口推进轴 + **多行内容高**（行数 × 行高，§5.1）；视口按多行内容**整体**裁剪；遮挡按多行内容包围盒。折行的可用行宽仍恒取屏宽 —— 窄 `scroll-rect` **不改变折点**，只改变哪些像素落盘（§5 求值次序；判据见 §14 与 §5.1 末行）。

**视口固定、内容移动**：`scroll-rect` 是屏幕上的绝对矩形（`%` 相对屏幕，不是相对视口自身）；`position` 只在「滚动块 + 传了 `scroll-rect`」时相对视口、`%` 相对视口宽高，其余情况一律相对屏幕。

| 项 | 内容 |
|---|---|
| 不受本项影响 | 入口边与方向（§6 表）、超时硬切、后续滚动块硬切、静态块不触发硬切；提前滚完冻结改按 §6 的 v0.1 不可达口径；速度按（视口 + 内容）/时长 |

## §7 安全

| 条 | 内容 |
|---|---|
| 只解析 | `<#N/>`、`#N text`、注释、空行 |
| 其他内容 | 一律忽略，不渲染、不执行、不加载外部资源 |
| HTML / 脚本 | 不解析 |
| 外部资源 | 不加载 |
| 注释识别 | 只在行首（行首空白后紧接 `//` 或 `<!--`）识别 |
| 文本行内 | `//`、`<!--`、`<` 均为字面量 |
| 注释长度 | 单行 ≤ 4096 字节，超出截断 |
| 跨行注释 | v0.1 不支持，`<!-- -->` 必须同行闭合 |
| BOM | 每个 payload 开头允许一个 UTF-8 BOM，忽略 |
| UTF-8 非法 | 丢整包（防御性策略；按字节扫 `\n` 定位行边界可靠，理由为包级恢复统一） |
| 彩色字形位图 | 只按 CBDT/CBLC 的 PNG 数据通路解码（libpng + zlib），不解析 PNG 文本块、不联网、不加载外部资源；FreeType 交回的是**预乘 BGRA**，合成前反预乘成 straight alpha（§13.3） |

## §8 转义

仅作用于**文本行**。块属性值一律不转义（§3 各属性、含 `font-family` 里的 `[\n]` 全部字面）。

### 8.1 结构

~~~text
[  \  <指令名> <参数>  ]
↑  ↑       ↑      ↑     ↑
前 指      指令   参数   后
缀 令      名          缀
      标记
~~~

- `[\` 是**前缀**；紧跟其后的 `\` 是**指令标记**；标记之后到**第一个 `]`** 之间是**指令名 + 参数**。
- 指令名与参数之间的**第一个空格是分隔符，被消费**；参数内其余空格原样保留。
- **内容不以 `\` 开头的，一律原样输出**，不是指令。

### 8.2 指令表

| 指令 | 参数 | 输出 |
|---|---|---|
| `n` | — | 换行符 U+000A（§5.1 换行的**唯一来源**） |
| `\` | — | 字面 `\` |
| `emoji` | `<序列>` | 整段 `<序列>` 路由 emoji 面（§13.2.3），由 GSUB 合成 |
| `emoji` | 空 | 输出空 |
| `emoji` | 含普通文字 | 整段交 emoji 面；合成出的保留，出不来的落豆腐块 |
| 其他 | — | 原样输出 `\<指令>`（连指令标记一起照抄，参数一并带上） |

无参数的指令被给了参数（`n`、`\`），按「其他」档原样输出。

### 8.3 裸字符

| 输入 | 输出 |
|---|---|
| `\`（前面不是 `[`） | 字面 `\` |
| `\n`（裸，前面不是 `[`） | `\` + `n` **两个字符，不换行**（作者陷阱） |
| `[`（后面不是 `\`） | 字面 `[` |

### 8.4 无嵌套

只有最外层 `[\` 生效；内层 `[\` **不重新开启解析**，只按普通字符处理。封闭符是**第一个 `]`**。
例：`A[\B[\n]C` → `AB[\nC`（内层被吞）。

### 8.5 丢弃作用域

从 `[\` 起找不到 `]` ⇒ 丢弃从 `[\` 到**源字节 LF 或文本行结束**的部分。块仍成立、时间照走，只丢该源行 `[\` 之后的内容。**静默、零计数、不判错**。
丢弃发生在解码**之前**的词法层，`[\n]` 造出来的换行不算行尾。

### 8.6 与源 LF 的分工

源文本的 LF 是**文本行终止符**（§2 行模型），不进入 `text`、不作为换行内容；内容里的换行**只能**由 `[\n]` 产生。二者在 §5.1 里分别决定「几个文本行」与「一行之内几个显示行」。

## §9 与容器的关系

> 容器 PTS/DTS 是**主时间轴**。排序、seek、多路复用均以容器 PTS 为准。  
> 字幕包容器 PTS = 该包**第一个有效块**的 start；若包内无有效块，容器 PTS 仍须按容器规范填写，但不参与字幕时间映射。  
> **有效块 = `end > start` 的块**；`end ≤ start` 为无效块。  
> 文本 `time` 是**包内局部描述**，用于包内多块的时间细分。  
> 若文本 start 与容器 PTS 不一致，以容器 PTS 为准，文本 `time` 整体平移对齐。  
> end 由文本 `time` 提供，容器不重复表达。  
> **正常 muxer 产出应一致；不一致按容错处理**，不得据此推断 muxer 错误。

### 9.1 流描述符

| 项 | 值 | 出处 |
|---|---|---|
| `stream_type` | `2`（字幕） | `容器规范.md` §3.3 |
| `codec_id` | `0` | `容器规范.md` §3.3 |
| `codec_version` | `1` | `容器规范.md` §3.3 |
| `timebase_num / den` | `1 / 1081080000` | `容器规范.md` 的文件头一节 |
| `max_packet_size` | `4096` | `容器规范.md` §3.3；约束见 §9.2 |

### 9.2 字幕包载荷外层（本版定义）

一个容器包的 payload 由「定长头 + 可选字段 + UTF-8 文本」构成。**所有整数 little-endian**，时间字段单位 = tick。

| 偏移 | 长度 | 字段 | 类型 | 规则 |
|---|---|---|---|---|
| 0 | 8 | `start_time` | `u64` | 包显示段起点。按无符号读入后过合法域 `start_time < 2^63`，越界判 `PACKET_HEADER_BAD`；转 `int64_t` 之后才参与比较与平移 |
| 8 | 8 | `end_time` | `u64` | 显示段上限。同样 `< 2^63`，且必须 `end_time > start_time`；否则 `PACKET_HEADER_BAD`；转 `int64_t` 后与 `start_time` 同 delta 平移 |
| 16 | 4 | `text_len` | `u32` | 其后 UTF-8 文本字节数 |
| 20 | 1 | `flags` | `u8` | bit0 `has_position`，bit1 `has_alignment`；**bit2–7 必须为 0**，否则 `PACKET_HEADER_BAD` |

**可选字段偏移真值表**（四种 flags 组合，逐格给出；偏移一律相对 payload 起点）：

| `has_position` | `has_alignment` | `position` 偏移 / 长度 | `alignment` 偏移 / 长度 | `text` 偏移 | `header_len` |
|---|---|---|---|---|---|
| 0 | 0 | — | — | 21 | 21 |
| 1 | 0 | 21 / 8 | — | 29 | 29 |
| 0 | 1 | — | 21 / 1 | 22 | 22 |
| 1 | 1 | 21 / 8 | 29 / 1 | 30 | 30 |

`header_len = 21 + (has_position ? 8 : 0) + (has_alignment ? 1 : 0)`。

| 字段 | 在场条件 | 类型与单位 | 语义 |
|---|---|---|---|
| `position` | `has_position = 1` | 两个 `int32`（x、y），单位 = 视频像素，原点左上，锚点 = 块中心 | **包级默认位置**；块自己的 `position` 覆盖它（§13.6） |
| `alignment` | `has_alignment = 1` | `u8`，枚举 `0 = left`、`1 = center`、`2 = right`；其他值 `PACKET_HEADER_BAD` | **包级默认对齐**；块自己的 `text-align` 覆盖它 |

**定界与下界**（9.2.1–9.2.6 任一不成立即判 `PACKET_HEADER_BAD`、整包丢弃并计数；9.2.7 另走 `PACKET_TOO_LARGE`）：

| # | 判据 |
|---|---|
| 9.2.1 | `payload_size < 21`（定长头都不全） |
| 9.2.2 | `payload_size < header_len`（可选字段被截） |
| 9.2.3 | `header_len + text_len != payload_size`（长度不符或有尾随字节） |
| 9.2.4 | `flags` 的 bit2–7 非 0 |
| 9.2.5 | `start_time` 或 `end_time` ≥ `2^63`，或 `end_time ≤ start_time` |
| 9.2.6 | `alignment` 不在 0 / 1 / 2 |
| 9.2.7 | `header_len + text_len > 4096`（超 `max_packet_size`）判 `PACKET_TOO_LARGE`，与上面各档不同码 |

**判定顺序**：9.2.1 → 9.2.7 逐条走，**先中先判，一次只出一个码**。长度不符（9.2.3）与超 `4096`（9.2.7）可以同时成立，此时按顺序落 `PACKET_HEADER_BAD`，不落 `PACKET_TOO_LARGE`；写方不得靠调序选出另一个码，读方两条路都要能拒。

**符号与溢出**：线上字段是无符号 `u64`，视图侧时间是 `int64_t`。规则是先按 u64 读入、过 `< 2^63` 域判、**再**转 `int64_t`（直接强转超界值在 C 里是实现定义行为，本规范不允许）。平移用 checked int64：`delta = container_pts − start_time_i64`，`end_time_i64 + delta`；任一步越出 `int64` 域判 `PACKET_HEADER_BAD`。块级 `time` 同 delta 平移，**单块平移越界只丢该块并计数，不牵连同包其余块**。 块级 `time` 平移后**为负**（delta 为负且该块 raw time 早于包 `start_time`）不属于越界：按「显示段已过」处置 —— **照样解析出块、不显示、不判错、不丢**，负 tick 原样留在块里，由渲染器按时间窗判其不在场。这一档必须写死，否则模糊测试会撞到一个未定义分支（§14 的模糊项）。

**容器 PTS 优先**：`start_time != container_pts` 时整包按 delta 平移并计数（容错路径，正常 muxer 不应产出）；`end_time` 是显示段上限，块 `end` 超出时由渲染器裁到包尾。

**文本本体**：`text` 从 `header_len` 起、长 `text_len`，内容按 §1–§8 解析；外层不解释文本，文本也不解释外层。

**空包**：`text_len = 0` 合法；包内全部块无效（`end ≤ start` 等）时包仍然存在，渲染器不出字，**不判损坏**，与 `PACKET_HEADER_BAD` 不同档。

### 9.3 全局样式块（`ext_type = 4`）

载体规则不变：全局样式存 `ext_type = 4` 扩展块，**每流至多一个**，**不放首包**；单块载荷上限 = `ext_len`（4 字节）全 1 = 4 294 967 295 字节；`next_ext_offset` 只用于同一流挂多类内容（`容器规范.md` 的扩展块一节）。本节定义其**内部字节布局**。

| 偏移 | 长度 | 字段 | 类型 | 规则 |
|---|---|---|---|---|
| 0 | 2 | `struct_size` | `u16` | 恒 `= 20 + font_family_len`（`bit0 = 0` 时该式退化为 `= 20`）；必须 `≥ 20`、`font_family_len ≤ 65 515`；任一不成立判 `STYLE_BLOCK_BAD` |
| 2 | 1 | `version` | `u8` | `1`；其他值 `STYLE_BLOCK_BAD` |
| 3 | 1 | `flags` | `u8` | bit0 `font_family`，bit1 `font_size`，bit2 `font_color`，bit3 `stroke_color`，bit4 `stroke_width`；**bit5–7 必须 0**，否则 `STYLE_BLOCK_BAD` |
| 4 | 2 | `font_size` | `u16` | `font_size_unit = 0` 时单位 0.1% 屏高（`40` = 4.0%），`= 1` 时像素 |
| 6 | 1 | `font_size_unit` | `u8` | `0` = 0.1% 屏高，`1` = px；其他值 `STYLE_BLOCK_BAD` |
| 7 | 1 | `reserved` | `u8` | 必须 0 |
| 8 | 4 | `font_color_rgba` | R,G,B,A | straight alpha |
| 12 | 4 | `stroke_color_rgba` | R,G,B,A | `stroke_width = 0` 时无意义 |
| 16 | 2 | `stroke_width` | `u16` | 像素；`0` = 无描边 |
| 18 | 2 | `font_family_len` | `u16` | UTF-8 字节数，不含 NUL；`≤ 65 515`（与 `struct_size` 的 u16 上界共同成立，防 `20 + len` 回绕） |
| 20 | N | `font_family` | UTF-8 | 逗号分隔回退链，按 §13.2 逐族尝试 |

**定界**：`payload_size < 20`、`payload_size != struct_size`、有尾随字节，均判 `STYLE_BLOCK_BAD`。

**在场与采纳是两件事**（本节的读法基准，逐条钉死）：

| # | 规则 |
|---|---|
| 9.3.1 | **固定头 20 字节全量在场**：偏移 2–19 的 `version` / `flags` / `font_size` / `font_size_unit` / `reserved` / `font_color_rgba` / `stroke_color_rgba` / `stroke_width` / `font_family_len` 一律照偏移读，**不因 `flags` 的位而缺席** |
| 9.3.2 | `flags` 的 bit1–bit4 只决定**该字段是否采纳**（进不进基线），不决定它在不在线；位为 0 时那几格字节仍然存在、仍然参与 `payload_size` 与 CRC，只是读方不采用其值（值本身不校验，允许为任意比特） |
| 9.3.3 | **唯一受 bit 影响的可变长段是 `font_family`**：`font_family` 的 N 字节仅 `bit0 = 1` 时在场；`bit0 = 0` 时 `font_family_len` **必须 = 0**（此时 `struct_size = 20`），`bit0 = 0` 而 `len > 0` 判 `STYLE_BLOCK_BAD` —— 否则 `struct_size = 20 + len` 会声明一段布局未定义的字节 |
| 9.3.4 | `bit0 = 1` 声明「字族链在场」，故 `font_family_len` **必须 > 0**：`bit0 = 1` 而 `len = 0` 判 `STYLE_BLOCK_BAD`（位说有一串、长度却说没有，属自相矛盾的声明，与 `bit0 = 0` 而 `len > 0` 同档对称）；`len > 0` 时那 N 字节必须构成合法 UTF-8，非法同样判 `STYLE_BLOCK_BAD`（与 §7 的整包判 UTF-8 非法是两处不同判点，各判各的码） |
| 9.3.5 | 判定按 9.3 表序与上面各档逐条走，**先中先判，一次只出一个码**；`version` 先于 `flags` 判，`flags` 先于长度式判 |

| 项 | 约定 |
|---|---|
| 缺块 | 样式块缺席时，全部走渲染器默认（§13.6） |
| 位为 0 的字段 | 该字段不进基线，按 §13.6 的覆盖序落 `renderer_default` 或内置默认 |
| 与块属性的关系 | 样式块在覆盖序里位于 `renderer_default` 之上、`parser_default` 之下（§13.6）；它不改变解析出的文本，也不是新语法 |
| 描边 | `stroke_*` 只在样式块里有载体；文本属性侧的 `text-stroke` v0.1 仍按未知属性忽略（§3.2、§12） |

### 9.4 容器侧不做的事

- 容器规范不为字幕载荷增设框架字段，也不定义 `ext_type = 4` 的内部布局；它只提供扩展块框架与 `max_packet_size`，本节两处的形状由本文负责。
- 字幕包与视频 / 音频包共用同一套包框架与寻址，字幕不引入专用段。
- 字幕包**不切分片**：一个显示段不跨包（§2 的「块定义与文本行同包」是同一条约束的两面）；容器的分片写入口对字幕流退化为单包。
- 样式块不参与包时间轴：`ext_type = 4` 挂在流描述符的扩展块链上（`容器规范.md` 的扩展块一节），不是包，也不带 PTS。

## §10 错误处理

### 10.1 文本层

| 情形 | 行为 |
|---|---|
| 文本行不匹配 `^#\d+[ \t]` | 整行忽略 |
| `#N` 未定义 | 该行不显示 |
| 引用已结束组 | 整行忽略 |
| 被忽略块定义作用域内文本行 | 按未定义引用处理 |
| ID 超范围 | 该行/该块忽略 |
| ID 非递增 / 回退 | 忽略该块；后续引用按未定义处理 |
| time 缺失 | 整块不显示 |
| `end < start` | 整块不显示 |
| `end = start` | 不显示（非错误） |
| time 序违规 | 仅忽略违规块 |
| 块未闭合 | 文档结束仍未闭合 → 该块整体忽略，**其作用域内文本行按未定义引用处理** |
| 未知属性 | 忽略 |
| 未知块 ID 重复 | 忽略后出现的块 |
| UTF-8 非法 | 丢整包 |

### 10.2 包层与样式层（本版新增）

| 情形 | 行为 | 错误码 |
|---|---|---|
| §9.2.1–9.2.5、9.2.6 任一成立 | 丢整包并计数，解析器继续可用 | `PACKET_HEADER_BAD` |
| `header_len + text_len > 4096` | 丢整包并计数 | `PACKET_TOO_LARGE` |
| 包 payload 非合法 UTF-8 | 丢整包并计数，不做逐行容错 | `INVALID_UTF8` |
| §9.3 定界 / 版本 / flags / 域判不成立（含 `bit0 = 0` 而 `font_family_len > 0`、`bit0 = 1` 而 `font_family_len = 0`、`bit0 = 1` 而字族非合法 UTF-8） | 样式块整体不采纳，渲染按 §13.6 的链落 `renderer_default` 或内置默认；已解析的文本不受影响 | `STYLE_BLOCK_BAD` |
| 块 `time` 平移后越出 `int64` 域 | 只丢该块并计数，同包其余块保留 | 不占码（统计） |
| 块 `time` 平移后为负（未越界） | 块照常解析出、不显示、**不丢、不判错、不计数** | 不占码 |
| 多条判据同一次命中 | 按 §9.2 / §9.3 的表序**先中先判，一次只出一个码** | 见各档 |
| 句柄为空 / 已关闭、参数指针与计数不匹配 | 拒绝，不写出参 | `INVALID_ARGUMENT` / `INVALID_HANDLE` |
| 渲染缓冲或脏矩形容量不足 | 见 §13.5 的截断与实际计数规则 | `OUTPUT_TOO_SMALL` |

**丢弃不等于失败**：包级 / 块级丢弃后，解析器与渲染器的句柄继续可用，计数进 `CLV_SubtitleStatsC`；调用方据码决定重试或忽略，句柄不因一次坏包而失效。

### 10.3 不占错误码的档

缺字 / 字体回退失败 / 未知属性 / 块级语法忽略 / 平移越界丢块，一律**进统计计数**，不分配错误码：它们是可预期的容错路径，不是调用方错误。

**块级不可用的公开视图**：**总计数 + 32 位原因掩码**。`bit0 = 语法忽略`（ID 非法 / 回退、start 序违规、平移越界丢块、未闭合），`bit1 = 时间不显示`（缺 `time`、`end ≤ start`、整段在过去）；`bit2–31` 保留且必须为 0。一个块可同时置两位，**总数只计一次**。

### 10.4 错误码号位

号位 `106` 起归字幕面。登记 **106–117** 共 12 档，其中 **112 / 113 / 114 本版没有产出者**（下表逐格写明替代行为，§10.3 那条「容错路径不分配错误码」就是它们的去处），**118+ 留白、不复用、不因任何退场而前移**；`0 = OK`。

| 值 | 名 | 触发 | 档 |
|---|---|---|---|
| 106 | `CLV_SUBTITLE_INVALID_ARGUMENT` | 出参为空、数组 / 计数不匹配、参数非法 | 调用 |
| 107 | `CLV_SUBTITLE_INVALID_HANDLE` | 句柄为空或已关闭 | 调用 |
| 108 | `CLV_SUBTITLE_INVALID_UTF8` | 包 payload 非法 UTF-8；丢整包 + 计数 | 包 |
| 109 | `CLV_SUBTITLE_PACKET_HEADER_BAD` | §9.2 的定界 / 下界 / 尾随 / 坏 flags / 域判 | 包 |
| 110 | `CLV_SUBTITLE_PACKET_TOO_LARGE` | `header_len + text_len > 4096` | 包 |
| 111 | `CLV_SUBTITLE_OUT_OF_MEMORY` | 库内分配失败 | 调用 |
| 112 | `CLV_SUBTITLE_STATE` | **本版无产出者**：未 Feed 时块计数为 0，越界取块 / 取行回 106，句柄为空回 107，关闭之后的句柄归调用方保证不再使用；号位留白不复用，`StrError` 照旧回文案 | 调用 |
| 113 | `CLV_SUBTITLE_BACKEND_FAILURE` | **本版无产出者**：CAL 或平台后端返回失败时，渲染器不出这一块（不落布局记录，脏矩形与字形计数随之为 0），动作口仍回 `OK`；号位留白不复用 | 渲染 |
| 114 | `CLV_SUBTITLE_RENDER_FAILED` | **本版无产出者**：布局 / 栅格 / 合成本身的失败按上一条处理，不当作动作口错误返回；号位留白不复用 | 渲染 |
| 115 | `CLV_SUBTITLE_UNSUPPORTED` | 渲染器未编入、保留能力、v0.2 语法 | 调用 |
| 116 | `CLV_SUBTITLE_OUTPUT_TOO_SMALL` | RGBA 缓冲 / stride 不足，或脏矩形容量不足 | 调用 |
| 117 | `CLV_SUBTITLE_STYLE_BLOCK_BAD` | §9.3 的长度 / 版本 / flags / 域判不成立 | 块 |

**号位与档已定；符号名随公开头批定**，本表用拟定名。每个值配 `CLV_SubtitleStrError`，未知值返回非空 ASCII `"unknown"`；动作口**只返码**，不设独立错误出参。

## §11 示例

**基本：**

~~~text
<#1/
time: 00:00:01.000 - 00:00:03.000
font-color: #FF0000
font-size: 24px
/>
#1 你好，世界
~~~

**多行堆叠：**

~~~text
<#1/
time: 00:00:01.000 - 00:00:04.000
font-color: #FFFFFF
/>
#1 第一行
#1 第二行
#1 第三行
~~~

**滚动（向上）：**

~~~text
<#1/
time: 00:00:05.000 - 00:00:10.000
font-color: #00FF00
scroll: top
scroll-rect: 0% 0% 100% 50%
/>
#1 滚动文本一
#1 滚动文本二
~~~

**多块重叠（无 `position`，自动堆叠）：**

~~~text
<#1/
time: 00:00:01.000 - 00:00:03.000
font-color: #FF0000
/>
#1 红色默认字号

<#2/
time: 00:00:02.000 - 00:00:04.000
font-size: 32px
/>
#2 默认颜色 32px
~~~

- `#1`：红色，默认字号，底部居中
- `#2`：默认颜色，32px，因无 `position`，在 `#1` 上方一行堆叠

**完整包示例（容器 PTS = 1.000s，文本 start 一致）：**

~~~text
<#1/
time: 00:00:01.000 - 00:00:05.000
font-color: #FFFFFF
font-size: 22px
/>
#1 欢迎
#1 来到 CLV

<#2/
time: 00:00:03.000 - 00:00:06.000
font-color: #FFAA00
scroll: bottom
/>
#2 滚动字幕
~~~

- `#1` 静态，1–5s
- `#2` 从 3s 起**向下滚**（从顶部进入），6s 结束
- 3–5s 重叠：`#2` 滚动块在上层，`#1` 静态继续渲染；`#1` 只有落进 `#2` 内容条带（§6.1）的那部分被遮挡

**平移变体（容器 PTS = 1.000s，文本 start = 2.000s）· 容错场景：**

~~~text
<#1/
time: 00:00:02.000 - 00:00:06.000
font-color: #FFFFFF
/>
#1 欢迎

<#2/
time: 00:00:04.000 - 00:00:07.000
font-color: #FFAA00
scroll: bottom
/>
#2 滚动字幕
~~~

- delta = 1.0 − 2.0 = −1s，全部块平移 −1s
- 实际显示：`#1` 1–5s，`#2` 3–6s
- 此为**容错场景**，正常 muxer 不应产出

**安全忽略：**

~~~text
<#1/
time: 00:00:01.000 - 00:00:03.000
/>
#1 合法行

这是裸文本，整行忽略。
<script>alert(1)</script>  整行忽略。

<#2/
time: 00:00:04.000 - 00:00:06.000
/>
#2 另一合法行
~~~

**包外层四档与真值表对平（构造用例的期望值，非字节 dump）：**

| 场景 | flags | `header_len` | `text` 偏移 | `payload_size` 应等于 |
|---|---|---|---|---|
| 仅文本 | `0x00` | 21 | 21 | 21 + `text_len` |
| 带 position | `0x01` | 29 | 29 | 29 + `text_len` |
| 带 alignment | `0x02` | 22 | 22 | 22 + `text_len` |
| 两者都带 | `0x03` | 30 | 30 | 30 + `text_len` |

## §13 渲染管线使用约定（CAL）

字幕渲染经 **CAL（CLV 能力抽象层）** 接口，上层管线只依赖接口，不直接调第三方库。  
**接口定义（语义、输入输出、错误码、线程模型）见 `include/CLV_Subtitle.h` 与 `API.md`**；本节只写字幕管线的使用约定。

> 字幕管线只使用**文本栈 7 个接口**（§13.1 表 1–7 步）；合成与上屏不经 CAL（§13.1 第 8 步）。

### 13.0 分层与代码落点

| 层 | 目录 | 放什么 | 不放什么 |
|---|---|---|---|
| CAL 接口与调度 | `src/subtitle/cal/` | 7 个接口的声明、后端选择、降级分发 | 第三方代码、OS API 代码 |
| 第三方库适配 | `backends/text/` | simdutf / utf8proc / SheenBidi / HarfBuzz / FreeType 的包装（含 face 与栅格） | 业务逻辑、布局 / 滚动 |
| 平台 OS API 适配 | `platform/font/` | DirectWrite 一系的字体解析 | 第三方库代码 |
| 字幕管线 | `src/subtitle/`、`src/subtitle/render/` | 解析 / 编码 / 样式 / 布局 / 堆叠 / 滚动 / RGBA 图层合成 | 直接调第三方或 OS 句柄 |

**分档看的是依赖种类，不是用途**：链第三方库的一律进 `backends/text/`，链 OS API 的一律进 `platform/font/`；字体 face / 栅格虽属「字体」用途，其代码仍在 `backends/text/`。

**七接口落点**：

| 接口 | 实现 | 落点 |
|---|---|---|
| `IUtf8Validator` | simdutf | `backends/text/utf8_simdutf.cpp` |
| `INormalizer` | utf8proc | `backends/text/normalize_utf8proc.cpp` |
| `IBidiEngine` | SheenBidi 新 API（`SBText` 一族） | `backends/text/bidi_sheenbidi.cpp` |
| `ITextShaper` | HarfBuzz | `backends/text/shape_harfbuzz.cpp` |
| `IFontResolver` | DirectWrite | `platform/font/resolve_win32.cpp` |
| `IFontFace` | FreeType（FTL） | `backends/text/face_freetype.cpp` |
| `IGlyphRasterizer` | FreeType（FTL） | `backends/text/raster_freetype.cpp` |

> 说明：上表是**已落地**的分档（`src/subtitle/cal/`、`backends/text/`、`platform/font/` 均已建）；接口语义与错误码以 `include/CLV_Subtitle.h` 与 `API.md` 为准。

### 13.1 流水线顺序（固定）

~~~text
UTF-8 校验 → NFC → Bidi → 整形 → 栅格 → 合成
~~~

| 步 | 使用的 CAL 接口 | 字幕侧使用约定 | 规范条款 |
|---|---|---|---|
| 1 | `IUtf8Validator` | 校验整包 payload；非法 UTF-8 → **丢整包**，不做逐行容错 | §7、§10.2 |
| 2 | `INormalizer` | NFC 规范化；桌面后端 utf8proc **2.12.0**（Unicode 18） | §7、§13.3 |
| 3 | `IBidiEngine` | UAX #9 重排；SheenBidi 3.0.0 **新 API（`SBText` 一族）**，run 边界取 `SBTextCreateVisualRunIterator`。**两条实测语义**：迭代器给的是**视觉序**（最左一趟在前），消费方要按 `off` 排序后再谈相邻性；run 是 **level 段、不是 script 段**（中性与空白并入相邻 level）。`off` / `len` 按**字节**计 | §1 文本行、§13.3 |
| 4 | `ITextShaper` | 码点 → 字形；v0.1 只需「单行 → 字形序列」整形，不自动折行 | §3.2 `font-*`、§12 |
| 5 | `IFontResolver` | `font-family` 逗号分隔逐个尝试，构成回退链（四档与问法见 §13.2.1） | §3.2、§13.2 |
| 6 | `IFontFace` | 字体度量与 face 解析；`font-weight` × `font-style` 的组合选脸见 §13.2.2 | §3.2 |
| 7 | `IGlyphRasterizer` | 字形栅格化 | §5、§6 |
| 8 | 合成 | 按 §5 分层与 §3.2 alpha 叠加规则合成到 **RGBA8 字幕图层**；布局（自动堆叠 / 滚动条带）由字幕管线自研，不经 CAL；与视频帧的混合归宿主（§13.8） | §5、§6、§13.5 |

### 13.2 字体回退约定

#### 13.2.1 回退链的四档与问法

`font-family` 逗号分隔的每个值经 `IFontResolver` 依次尝试；全部无匹配则渲染缺字占位（豆腐块）并计数，**不判错、不丢包**。

回退顺序固定为**四档，问中即停**：

| 档 | 问谁 | 问什么 |
|---|---|---|
| 1 作者链 | 随包字体目录 | `font-family` 给的每个值，按给的顺序 |
| 2 基准族 | 随包字体目录 | 在册的两份（顺序见下表），不看作者给没给 |
| 3 系统回退 | OS 字体集合（Windows = DirectWrite） | 作者链给的每个值；作者链为空时改问基准族名 |
| 4 豆腐块 | —— | 前三档全空：按码点占一格空框、计数、进脏矩形 |

未给 `font-family` 时第 1 档为空，块直接由第 2 档（基准族）接住 —— 这就是「渲染器默认字族 = 基准族」的落点。
基准族排在系统之前是刻意的：随包字体是打包时定死的，同一份码流在同一构型下落哪张 face 不随装机变化；只有基准族给不出的（例如该族没有斜体）才去问系统。

基准族是**两份**：拉丁与 CJK 走 `NotoSansCJKsc/`，阿语走 `NotoNaskhArabic-v2.021/`——第二份补的是第一份**没有覆盖的脚本**，不是可选附件。

| 项 | 约定 |
|---|---|
| 基准族第一份 | `assets/fonts/NotoSansCJKsc/`（Noto Sans CJK SC, Sans2.004, 7 OTF + LICENSE, OFL 1.1, 逐件 SHA-256 已登记, 110.1 MiB）；该族**自带拉丁字形**，拉丁与 CJK 同一份，不另配拉丁基准 |
| 基准族第二份 | `assets/fonts/NotoNaskhArabic-v2.021/`（Noto Naskh Arabic, `Version 2.021`, OFL 1.1, 30 件逐件 SHA-256 已登记并做 zip 内件对平, 5.35 MiB）；覆盖第一份缺的**阿语（RTL）**面，地位与第一份同级 |
| 两份的分工 | 一份管一套脚本：拉丁 / CJK 归第一份，阿语归第二份；**同一张 golden 不混两份字体**（两族的 hinting 不同，混了就归因不到改动） |
| 测试路径 | 两份各取 Regular + Bold 两档（其余字重与其余构建入库备查，不进用例） |
| 系统回退 | 基准族缺字时按 OS 解析（Windows = DirectWrite）；跨机像素不可比的部分按 §14 只断布局 |
| 豆腐块 | 全部不命中时画缺字占位并计数 |
| 阿语（RTL）面 | 由第二份基准承担：`assets/fonts/NotoNaskhArabic-v2.021/`（逐件哈希与 zip 内件对平见 `assets/fonts/provenance.txt` 第二件）。第一份对阿语码位无覆盖（实测全落 `.notdef`），所以 Bidi 分趟、整形换形、阿语覆盖率这三件事只能在第二份上断 |
| 字体件与运行时依赖 | 字体件不是库的运行时依赖，只有测试路径经策略的 `font_dir` 指它（§13.6） |

#### 13.2.2 `font-weight` × `font-style` 的组合选脸

一档里的一个字族名可以对应多张 face（一文件一张，或一个集合文件里多张）。选法固定两步，顺序不可换：

| 步 | 规则 |
|---|---|
| 1 style 硬过滤 | 只留 `font-style` 精确一致的那些：`normal` 要 OS/2 `fsSelection` bit0 = 0，`italic` 要 bit0 = 1；OS/2 缺席或版本不足（v0 / v1）时退回 `head` `Mac_Style` bit1。**过筛集为空 = 这一档给不出该 style**，落链的下一档，绝不拿另一个 style 顶替（禁止静默降级） |
| 2 weight 最近匹配 | 在过筛集里取 OS/2 `usWeightClass` 与 `font-weight` 差最小的一张；**平票取小**（要 600 而集里只有 500 / 700 ⇒ 取 500）。`font-weight` 未给按 §3.2 的默认 `normal`（= 400），`font-style` 未给按 `normal` |

| 项 | 口径 |
|---|---|
| 判据只认表 | weight 与 style 一律读字体自带的 OS/2 / head 表，不认文件名里的 `-Bold` / `-Medium` 之类后缀——后缀是打包者写的，表是字体带的 |
| 选中的就是画的 | 第 2 步选中的 face 序号（集合文件里第几张）一路带进度量与栅格入口；不允许「选了 Semibold、画了 Regular」 |
| weight 不降级 style | style 的硬过滤在 weight 之前：nearest-match 只在同 style 的集里发生，跨 style 不存在「最近」 |
| 全链落空 | 四档问完仍无 face ⇒ 豆腐块档；该档没有 face，落面读数的身份位（weight / face 序号 / style）给 0，不回显请求值 |

#### 13.2.3 码位级回退与 emoji 槽

回退粒度 = **码位级**；段边界受 Bidi run 约束。

| 项 | 规则 |
|---|---|
| 段定义 | 段 = 同 face ∩ 同 bidi run；段边界 = min(face 切换点, run 边界) |
| 切分 | 从左到右逐码位判：当前 face 覆盖就追加，不覆盖就切段并从候选序列头重问 |
| 候选序列 | 作者链 → 基准族（§13.2.1 顺序）→ **emoji 槽** → 系统回退 → 豆腐块 |
| emoji 槽 | 固定在基准族之后、系统之前；只接码位级回退里没人覆盖的码位；未配置 emoji 面时跳过 |
| `[\emoji ...]` | 直达 emoji 槽，不经候选序列；整段交 GSUB 合成 |
| ZWJ / VS16 | 归入当前 emoji 段（不因 cmap 不单独映射而切断序列），由 GSUB 合成家庭 / 旗帜 / 变体序列 |
| 段内整形 | 每段独立整形；连字不跨段；段间 advance 首尾相接（无重叠、无缝隙） |
| 覆盖查询 | `FT_New_Face` + `FT_Select_Charmap(FT_ENCODING_UNICODE)` + `FT_Get_Char_Index ≠ 0`；只认 Unicode charmap（避免 Apple Roman 一类旧子表的假覆盖）；降级档一律报不覆盖 |
| 全链不覆盖 | 连续码位并成一个豆腐段，逐码位 `.notdef` 并计数（§8.1 / §13.2.1 第 4 档） |
| 样式 | 候选序列与 §13.2.2 同一套硬过滤；emoji 面不参与 weight / style 过滤 |

> 实测依据：CJK 面不覆盖阿语、Naskh 面不覆盖中文（实测的交叉覆盖查询）；同一张系统面（Tahoma）同时覆盖拉丁与阿语时，`اA` 仍按 bidi run 切两段（实测）。

### 13.3 后端映射（桌面 / 裸机）

> 接口与后端映射的定义见 `include/CLV_Subtitle.h`；本表是字幕侧的使用视图。

| CAL 接口 | 字幕用途 | 桌面后端（Windows 先行） | 裸机 / 降级 |
|---|---|---|---|
| `IUtf8Validator` | §7 UTF-8 校验 | simdutf **9.1.2** | 手写状态机 |
| `INormalizer` | NFC 规范化（流水线第 2 步） | utf8proc **2.12.0**（Unicode 18） | Passthrough（不实现） |
| `IBidiEngine` | UAX #9 重排 | SheenBidi 3.0.0（**新 API：`SBText` 一族**） | LtrOnly（不实现） |
| `ITextShaper` | 码点 → 字形 | HarfBuzz 14.4.0 | DirectMap（直映射） |
| `IFontResolver` | `font-family` 回退链 | DirectWrite（经 `platform/font/`） | 单字体内嵌 |
| `IFontFace` | 字体度量 / face | FreeType 2.14.3（FTL，经 `backends/text/`） | 预烘焙度量 |
| `IGlyphRasterizer` | 字形栅格化 | FreeType 2.14.3（FTL，经 `backends/text/`） | 预烘焙 atlas |

| 项 | 口径 |
|---|---|
| 彩色位图解码链 | CBDT 的条目是 PNG（实测 `imageFormat = 17`），要 FreeType 开 `FT_CONFIG_OPTION_USE_PNG` ⇒ 依赖 **libpng 1.6.44 + zlib 1.3.1**（`PACKAGES` 十一笔里的两笔，装在 FreeType 之前）；`FT_LOAD_COLOR` 交回的是**预乘 BGRA**，本库 RGBA8 管线吃 straight ⇒ 合成前反预乘 |
| 版本来源 | 取 `scripts/install_third_party.py` 的 `PACKAGES` 现行版本；本节即现行基准，**没有待确认项** |
| Unicode 基准 | **18.0.0**（随 utf8proc 2.12.0）|
| SheenBidi API 选型 | **新 API（`SBText` 一族，3.0.0）**，r12 起全面切换：**不保留旧 API、不留兼容层、不留新旧对照**。该族是上游标 experimental 的并行 API，由 `SB_CONFIG_EXPERIMENTAL_TEXT_API` 开关控制编译（默认 OFF）⇒ **库与每一个消费者都要带这个定义**，否则 `SBText.h` 整段被 `#if` 编空，症状是 `SBTextConfigRef` 变成「未知类型」的语法错而不是链接期符号缺失。`SBTextCreate` 的 config 参数不可为 NULL（实现里直接读该字段） |
| 文本度量 | **两条公开入口并存**：`hb-ot-font` 与 `hb-ft`，不二选一；两者共用同一套渲染参数，由调用方选入口。HarfBuzz 构建必须带 FreeType 支持（`HB_HAVE_FREETYPE=ON`），`hb-ft` 入口才成立 |
| 平台承诺 | Windows 桌面先行；Linux / macOS 侧的 fontconfig / CoreText 只作**后端映射的记录**，本版未经非 Windows 编译与实测，**不写「可用」**；裸机只保留降级模式，同样未实测 |

### 13.4 渲染差异声明

跨平台字形**位置**一致；像素级渲染因 FreeType 编译选项（hinting / subpixel）不同可能有差异，规范**不要求像素一致**。

### 13.5 渲染器输出契约

| # | 项 | 约定 |
|---|---|---|
| 13.5.1 | 缓冲 | 宿主提供 RGBA8 缓冲 + stride + 宽高，并在调用前清为透明；库只画字幕层像素，**不提供混合 API、不负责上屏** |
| 13.5.2 | 像素格式 | straight alpha、原点左上、行间填充由 stride 表达；`dst_stride ≥ dst_width × 4` |
| 13.5.3 | 脏矩形 | 库把本次绘制覆盖区**合并后**写入调用方的矩形数组；结果互不重叠、互不边相邻；按 y 再 x 排序 |
| 13.5.4 | 合并 | 相交或边相邻的两矩形迭代合并为外接矩形，直到无对可并；允许脏区覆盖未绘制像素（保守上界） |
| 13.5.5 | 容量与截断 | 计数出参写**实际总数**；实际数 > 容量时只写前 `capacity` 个并返回 `OUTPUT_TOO_SMALL`，宿主按实际总数扩容重试；**不静默丢矩形** |
| 13.5.6 | 零容量 | 数组指针为空且容量 = 0 合法：只出实际总数，实际数 > 0 返回 `OUTPUT_TOO_SMALL`；指针为空而容量 > 0、或指针非空而容量 = 0 → `INVALID_ARGUMENT` |
| 13.5.7 | 出错时的计数 | `OUTPUT_TOO_SMALL` 时仍写实际总数（供扩容）；其余错误码写 0 |
| 13.5.8 | 无字 | 实际计数 = 0，返回 OK，不写矩形 |
| 13.5.9 | 坐标 | 矩形裁到 `[0, width] × [0, height]`；零面积矩形不输出 |
| 13.5.10 | 回报通道 | 动作口只返码，没有第二个错误出参；计数出参承载的是矩形总数，不是错误档 |
| 13.5.11 | 时间 | 渲染器按调用方给的 `time_ticks` 出帧，**不拥有播放时钟**；调度与同步归宿主 |
| 13.5.12 | 彩色字形 | 反预乘后的 straight RGBA 直通，只乘 `opacity`，**不乘 `font-color`**；彩色位图不描边（§5.2 的交互口径） |

### 13.6 默认样式与覆盖级

公开面用两份参数给默认样式：`CLV_SubtitleParserParamsC.parser_default`（覆盖链第 3 档）与 `CLV_SubtitleRendererParamsC.renderer_default`（第 1 档）；两者都可为 NULL。字符处理模式（NFC / Bidi / 整形）与字体回退策略不开放逐项开关：解析器只用 UTF-8 模式做整包校验，其余由渲染器按 §13.1 / §13.2 的固定顺序执行。

**覆盖序（自低到高，逐字段生效）**：

~~~text
内置默认 → renderer_default → 全局样式块（§9.3）→ parser_default → 包级 position / alignment（§9.2）→ 块属性（§3.2）
~~~

每条字段独立走这条链，先高后低取第一个**已设**的档；全未设则落内置默认。

**`style_source` 编码（字段级来源回报，0–6 七档）**：`CLV_SubtitleBlockC.style_source` 是 `uint64_t`，**每 3 bit 对应 `CLV_SubtitleStyleC.flags` 的一位**（13 个字段占 0–38 位，**39–63 保留、写 0**）。**0–5 数值即优先级：值大的那档赢**；**6 = unset（全链未设）**，是标记不是更高档，不参与赢档比较；**7 保留、不产出、不复用**。

| 值 | 档 | 能落在哪些字段（按 `flags` 位号） | 备注 |
|---|---|---|---|
| 0 | 内置默认 | 全部 13 格 | 最低档 |
| 1 | `renderer_default` | 全部 13 格 | `RendererParamsC.renderer_default` 且该字段已设 |
| 2 | 全局样式块（§9.3） | 只有 0 颜色 / 1 描边色 / 2 字号 / 11 字族 / 12 描边宽 | 载体只带这五样（§9.3 的 `flags`） |
| 3 | `parser_default` | 全部 13 格 | `ParserParamsC.parser_default` 且该字段已设 |
| 4 | 包级默认（§9.2） | 只有 5 对齐 / 6 位置 | 包外层只带这两样 |
| 5 | 块属性（§3.2） | 全部 13 格 | 最高档 |
| 6 | unset | 全部 13 格 | 该字段全链未设；与内置档 0 区分 |
| 7 | 保留 | — | 不产出、不复用 |

| 补充 | 约定 |
|---|---|
| 覆盖链唯一权威 | 本文这条链是 `API.md` 与实现两侧的准绳 |
| 渲染器不参与覆盖序改写 | `renderer_default` 只是链上的第 1 档，渲染器出帧时**不回头改写**高档已设的字段 |
| 字符处理不做覆盖 | 块级 `font-*` 只影响字面选择，不改 NFC / Bidi / 整形的顺序 |
| 形状稳定性 | 参数与视图结构一次定死；落地后改属破坏性变更 |

### 13.7 构建构型与能力位

| 项 | 约定 |
|---|---|
| 开关 | `CLV_BUILD_SUBTITLE_RENDERER=ON/OFF`，默认 **ON** |
| OFF 行为 | 解析 / 编码照常可用；渲染口返回 `UNSUPPORTED` |
| 能力位 | bit3 = 字幕解析 / 编码在（恒 1）；bit4 = 渲染器在（ON 1 / OFF 0）。位号只追加不改义，且回报的是**构建期事实**，不是运行时协商开关 |

### 13.8 多流与宿主混合

- v1 **不定义**多条字幕流之间的层叠关系：一个渲染器只接一条流。
- 库只输出每条流的 RGBA8 字幕层 + 脏矩形；**不提供多流混合 API**，也不把层叠写进渲染器。
- 多流的编排由宿主自定，混合代码由宿主自写；不引入第三方合成库。

### 13.9 依赖与 vendoring

| 项 | 约定 |
|---|---|
| 拉取 | 走 `scripts/install_third_party.py` 的 `PACKAGES`；源码快照不入库，构建产物只落 `build/_install` |
| 许可 | 许可件投 `_install/licenses`；FreeType 用 **FTL** 支（GPL 支不用）；HarfBuzz 内部内存分配为**登记例外**（无客户端注入钩子） |
| 运行时依赖 | 文本栈五件套是渲染器后端的实现依赖，不是公开 ABI 的一部分；解析 / 编码路径不依赖它们 |
