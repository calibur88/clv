# CLV 容器规范

> 本文是 CLV 容器层（文件扩展名 `.clv`）字节格式的**摘要件**：对外可读的那一份，覆盖布局、字段值域、时间模型、分片规则与容错口径。字节口径以仓库内实现与用例钉住的值为准；本文缺项时**不自行补设定**。  
> 文档版本：0.8.0 · 日期：2026-10-21 · 容器格式版本：`version_major = 2`、`version_minor = 0`。**v2 涵盖：流描述符 68 B、扩展块 `ext_len` 4 B、三处偏移与索引 `file_offset` u64 化、索引条目 20 B、动态库导出面、媒体面枚举退场，以及分段器字段（`flags` bit3、`file_ext_offset`、`ext_type = 7` 段描述块、多段读口与分段观测口）。**  
> 容器格式版本写在文件头里，与工程版本、文档版本分轨：三者之间没有换算关系，工程版本可在结构不动时照常递增。
> **格式变更须伴随版本升号**：动到线上字节（布局、字段宽度、偏移口径、取值域）即抬 `version_major`，只澄清语义不动布局才抬 `version_minor`；升号同轮必须重锚入库素材与本摘要件的字节口径条目。  
> 调用面契约（句柄、入参出参、错误码）见 `include/CLV_Container.h` 的头注释；分层与依赖见 `ARCHITECTURE.md`。

## 2 全局约定

以下约定适用于全文件所有多字节整数与校验。

| 项目 | 约定 |
|---|---|
| 整数字节序 | **小端（LE）** |
| varint | 无符号 LEB128：每字节低 7 位是数据、最高位是续接位；u64 最多 10 字节，**第 10 字节只允许贡献 1 位**，超过即解码失败 |
| 最短形式 | **必须**是该值的最短编码长度：编码字节数与该值单独编码所需字节数不相等即判字段不成立（例如两字节编码的 0） |
| 有符号整数 | 二进制补码；`pts_delta` 走 zigzag 后再以 varint 编码 |
| zigzag | `(n << 1) ^ (n >> 63)`，`n` 为有符号 64 位 |
| CRC | CRC-32/MPEG-2：poly `0x04C11DB7`、init `0xFFFFFFFF`、refin **false**、refout **false**、xorout `0x00000000` |

**CRC 覆盖范围逐项声明**：

| 结构 | 校验字段 | 覆盖范围 |
|---|---|---|
| 文件头 | `header_crc32`（偏移 40） | 偏移 `[0, 40)` |
| 流描述符 | `crc32`（偏移 60） | 偏移 `[0, 60)` |
| 索引头 | `header_crc32`（偏移 8） | 偏移 `[0, 8)` |
| 索引条目 | 无校验字段 | — |
| 扩展块 | `crc32`（尾部 4 字节） | 自 `ext_magic` 起到 `crc32` 前 |
| 数据包 | `crc32`（尾部 4 字节） | **包内相对偏移 `[4, total_size)`** |

**`total_size` 语义**（数据包唯一的自证字段）：

- 从 `stream_id` 起算、到包尾**含 `crc32`** 的字节数，**不含 `total_size` 字段自身**；线上一个包占 `4 + total_size` 字节。
- 数据包 CRC 的覆盖区间 `[4, total_size)` 用的是**包内相对偏移**，相对偏移 `0` 就是 `total_size` 的首字节。
- 因 `total_size` 不含自身，`total_size` 恰好等于 `crc32` 的包内相对起始偏移，该区间天然排除 `crc32` 自身；等价写法为 `[0, total_size - 4)`。

## 3 文件布局

```text
CLV 文件
├── 文件头              64 字节
├── 流描述符表          68 字节 × stream_count
├── 扩展块区            可选，逐流成链 + 文件级成链（分段容器的段描述块在这一条链上）
├── 数据包区            多流交错的包序列
├── 索引区              可选
└── 文件尾              16 字节
```

**区域边界**（读方据此划定解析范围）：

| 边界 | 取值 |
|---|---|
| 文件长度下限 | `64 + 16`，短于此判文件头不成立 |
| 包区起点 `area_start` | `64 + 68 × stream_count`，再沿**全部**扩展块链（逐流链与文件级链都在这一区）推进到**已确认块的最大结束偏移**；只算逐流链会在段描述块上留出空档，落在空档上的第一刀不是包 |
| 包区终点 `area_end` | 有索引区时 = 文件头 `index_offset`；无索引区时 = 文件长度 − 16 |

包区的解析从 `area_start` 开始：文件头与描述符表不是包。

## 4 结构定义

### 4.1 文件头（64 字节）

```text
偏移  长度  字段             取值与约束
0     8     magic            "CLVFILE\0"
8     2     version_major    结构版本，当前 = 2
10    2     version_minor    语义版本，当前 = 0
12    1     stream_count     1..255，不得为 0
13    1     flags            bit0 = index_present
                             bit1 = globally_sorted
                             bit2 = streaming
                             bit3 = segmented
                             bit4-7 reserved，本版 = 0
14    2     reserved         本版写 0
16    8     duration_ticks   全局 tick，见下
24    8     total_packets    见 streaming
32    8     index_offset     索引区绝对偏移；无索引区时写 0
40    4     header_crc32     覆盖 [0, 40)
44    8     file_ext_offset  文件级扩展块链首块偏移，0 = 无；仅 segmented = 1 时要求非 0
52    12    reserved         本版写 0
====  ====
总计  64 字节
```

**`flags` 位语义**：

| 位 | 名称 | 语义 |
|---|---|---|
| bit0 | `index_present` | 1 = 文件含索引区 |
| bit1 | `globally_sorted` | 1 = 包区内所有包按统一时间轴升序排列 |
| bit2 | `streaming` | 见下 |
| bit3 | `segmented` | 1 = 本文件是分段容器的一员，`file_ext_offset` 有效 |
| bit4-7 | reserved | 本版 = 0 |

**`streaming`**：

```text
bit2 = streaming
  0 = 非流式写入：文件头 total_packets 为准确值，文件尾 total_packets 与之一致
  1 = 流式写入：文件头 total_packets = 0xFFFFFFFFFFFFFFFF，
                文件尾 total_packets 写真实值
  读取时：flag = 1 且文件尾存在，以文件尾为准
          flag = 1 且文件尾缺失（截断），total_packets 视为未知
```

**`duration_ticks`**：

- 单位 = **全局 tick**（`1 / 1081080000` 秒，见 §5.1）。
- 多流时取**各流末帧 PTS 的最大值**，且按**已平移**的时间轴取值（§5.3）。
- 某流末帧 PTS 落在该流原点之前时不贡献时长。
- `index_present = 0` 时写 **0**，表示**未知**；解码器**不得**据此推断时长为 0。

**文件头值域校验**（读方 `Open` 的判定，任一不成立即整文件回报结构不成立）：

| 检查 | 不成立时 |
|---|---|
| magic 与 `header_crc32` | 判文件头不成立 |
| `version_major != 2` | 判「值域不成立」；**不得**当作损坏继续猜 |
| `stream_count == 0` | 同上 |
| `flags & 0xF0 != 0` | 同上 |
| 偏移 52..63 的 reserved 不为全 0 | 同上 |
| `segmented = 1` 且 `file_ext_offset == 0`（自称分段，却没有文件级链入口） | 同上 |
| `segmented = 0` 且 `file_ext_offset != 0`（不分段，却带着一个无主的偏移） | 同上 |
| 非流式且 `total_packets == 0xFFFFFFFFFFFFFFFF` | 同上 |
| `index_present = 0` 且 `index_offset != 0` | 同上 |

`flags` 的保留位掩码取 `0xF0`：第 0 到第 3 位是本版已赋予语义的位，第 3 位是分段位，第 4 到第 7 位才是必须为 0 的保留位。

### 4.2 流描述符（每条 68 字节）

```text
偏移  长度  字段              取值与约束
0     1     stream_id         0..255
1     1     stream_type       0 = 视频, 1 = 音频, 2 = 字幕
2     1     codec_id          容器层不解释
3     1     codec_version     容器层不解释
4     8     timebase_num      值域限 u32 且非零
12    8     timebase_den      值域限 u32 且非零
20    4     max_packet_size   payload 字节上限（不含包外层），不得为 0
24    8     first_dts         首段 = 0（写方判，判在落盘之前；读方不补这一道拒档）；分段容器后续段 = 该段该流首帧的绝对 dts
32    8     language          容器层不解释（不透明 u64）
40    4     sample_rate       音频流不得为 0，其它流不校验
44    2     channels          音频流不得为 0，其它流不校验
46    2     bit_depth         取值集见下表
48    1     codec_flags_0     容器层不解释
49    1     vlc_table_id      本版 = 0
50    8     ext_offset        该流第一条扩展块的绝对偏移，0 = 无扩展块
58    1     codec_flags_1     预留，本版 = 0
59    1     layer_id          本版 = 0
60    4     crc32             覆盖 [0, 60)
64    4     reserved          本版写 0
====  ====
总计  68 字节
```

**`bit_depth` 合法集**：

| `stream_type` | 合法 `bit_depth` |
|---|---|
| 0（视频） | 8 / 10 / 12 |
| 1（音频） | 16 / 24 |
| 2（字幕） | 0（不使用） |

**逐条不可用规则**：描述符表按 `stream_count` 条逐条解码与校验。`crc32` 不符、值域校验不过、或 `stream_id` 与已登记的流重复时，**只列出可用的流；描述符校验不通过的流在打开时被丢弃，不回报数量，也不占用编号**，其余流照常读取，整文件不判损坏。`CLV_ContainerReaderGetStream` 的 `index` 是可用流列表的下标（不是 `stream_id`），列表里每条的 `usable` 出参恒为 1——被丢弃的流不在列表里，因而读不出 0。落在包区里的被丢弃流的数据包按 §7 的无名流档丢弃。

**`timebase_num` / `timebase_den`**：线上各占 8 字节，值域限 `1 .. 0xFFFFFFFF`。容器层只挡不可表示的值，不封「合理集」上限。

**`max_packet_size` 的双重身份**：对写方它是 **payload 字节上限**（不含包外层），单帧载荷超过即被拒；对读方它是**解析前的资源护盾**——整包长度超出接受上限的包按 §7 的超限档处置，护盾在字段解析之前生效。读方的接受上限默认取**所有已登记流中最宽的 `max_packet_size + 41`**，重同步扫描的候选位置再按该 `stream_id` 对应流的 `max_packet_size + 41` 复核，CRC 自证成立后 `payload_size` 还要与该流的 `max_packet_size` 再比一次。放宽或收紧读方的接受域只改变接受域，不改变格式对写方的约束。

### 4.3 扩展块（链式，位于描述符表与包区之间）

```text
偏移  长度      字段               取值与约束
0     4         ext_magic          'C' 'L' 'V' 'X'
4     1         ext_type           容器层不解释，见下
5     1         ext_version        容器层不解释
6     4         ext_len            ext_data 字节数，0..4294967295
10    8         next_ext_offset    下一条扩展块的绝对偏移，0 = 链尾
18    ext_len   ext_data           不透明载荷
—     4         crc32              覆盖自 ext_magic 起到本字段前
```

| 规则 | 内容 |
|---|---|
| 入口 | 逐流链由所属流的 `stream_desc.ext_offset` 指向首块，一块只属于一条流；**文件级链**由文件头的 `file_ext_offset` 指向首块（只在 `segmented = 1` 时存在），段描述块走这一条链 |
| 组内次序 | 同一链内保持写入序 |
| 链前进 | `next_ext_offset` **必须**大于本块起点，否则读方停止走该链（防成环） |
| 载荷语义 | `ext_type` / `ext_version` 是该流媒体层与调用方之间的约定；**容器层只搬运与校验 CRC，不解释载荷** |
| 必选性 | 容器层不解释载荷，但规定**存在性**：v2 起视频流必须挂 `ext_type = 3` 参数块。缺块的那条视频流在打开时同样被丢弃（不进可用流列表，其余流照常、整文件不判损坏），被丢弃的条数经段观测口的 `video_stream_no_param_block` 查询；读方不替写方补一份默认声明。音频 / 字幕流不写该块 |
| 单块上限 | `ext_len` 是 u32，故单块载荷上限 4 294 967 295 字节；**一个外部原块进一个扩展块，不拆不串**，`next_ext_offset` 只用于同一流挂多类内容 |
| 不成立块处置 | 块本身解析不过（CRC 或布局不成立）时终止该链**并计数**（`ext_blocks_bad`）；**接受域外也计入块计数** —— 声明长度超出接受域的块同样计入块计数：块计数记的是「解析不成立的块数」，含接受域外的那一类，该档排在分配与 CRC 校验之前，块内容未经判定。载荷声明在接受域内、但整块读不进文件（截断）时同样终止该链，不计数。三种情况包区起点都仍按已确认的块推进 |

**分段容器（摘要）**：同一逻辑视频切成多个物理 `.clv`，一个文件 = 一段；段身份落在 `ext_type = 7` 的**段描述块**（定长 48 B：`seg_flags` / `seg_index`（自 0）/ `seg_total`（全 1 = 未知、不得为 0）/ `seg_start_ticks` / `seg_end_ticks`），入口是文件头的 `file_ext_offset`（`flags` bit3 = `segmented`）。**段与分片无关**：段界必须落在帧边界上，所以读方不存在跨段重组。各段的流描述符逐字段必须相等（允许不同的只有 `first_dts` 与 `ext_offset`），不一致则该段不可接入。**格式不设段大小上限，本库也不实施切分策略**（段边界与段大小都由调用方定）；工具侧的建议口径为 `min(10 分钟, 4 GiB)` 且只在关键帧切（编码侧义务：段首帧必须是 I 帧、不得跨段回引，由视频编码层保证）。
已用到的 `ext_type` 取值：视频参数块（`ext_type = 3`，载荷仍是交给视频层解释的不透明字节，容器层只管上一行的存在性）、字幕全局样式块（`ext_type = 4`，见 `assets/fixtures/subtitle_ext4.clv`）、段描述块（`ext_type = 7`）；段索引表取 8（值已留、本期不实现）。层描述、色彩空间、FLAC STREAMINFO 副本等取值属各媒体层约定，容器层未赋予语义，见 §10。

**段间扩展块一致性（本版口径）**

- **每一段都要自带本段的扩展块**。画面尺寸只在视频参数块（`ext_type = 3`）里，流描述符那张 68 字节的表里没有宽与高；
  只在首段写一次的后果是后续段被判不可用、整段拒接（实测形态：只交得出首段的帧）。
- **各段都带块、但内容彼此矛盾时，本版不判拒接**：段照交、返回码仍是 `OK`、段身份的拒接计数也不动 ——
  描述符对账结构上碰不到块内容。一致与否属内容策略，不在字节格式里，库不替调用方默认判错。
- 需要严格一致的读**主动查询口** `CLV_ContainerReaderSegExtCheck`（按 `(stream_id, ext_type)` 与基准段逐字节比版本号与载荷），
  读数同时落到段观测口的两档：`segments_ext_scanned`（含基准段；0 = 从没查过）与 `segments_ext_inconsistent`。
  查询口在 `NextFrame` 通路之外，每次调用为清单里每个段读一次「文件头 + 描述符表 + 扩展链」。
- 基准段 = 按清单里给出的位置顺序逐段试开，第一个结构读得通的段；段号本身以段描述块里的 `seg_index` 为权威，
  清单顺序与文件名只是线索。它与段身份对账用的描述符基准同源，不另起一套口径。

**段描述块字段表（`ext_type = 7` 的载荷，48 字节，小端）**

```text
偏移  长度  字段              取值与约束
0     1     seg_flags         bit0 总数已知 / bit1 段首帧在各视频流上都是关键帧 / bit2 与上一段之间有时间断 / bit3-7 reserved = 0
1     1     reserved          本版写 0
2     8     seg_index         本段段号，自 0 起
10    8     seg_total         总段数；全 1 = 未知，**不得为 0**
18    8     seg_start_ticks   本段视频首帧（解码序第一包）的 DTS 折算成全局 tick
26    8     seg_end_ticks     本段视频末包（解码序最后一帧）的 DTS 折算成全局 tick，**不得小于 `seg_start_ticks`**；与 `duration_ticks` 不同轨
34    14    reserved          本版写 0（34..47 共 14 字节）
```

| 规则 | 内容 |
|---|---|
| 块长 | 载荷定长 48 字节，整块 = 定长前缀 18 + 48 + crc32 4 = **70 字节** |
| bit0 与 `seg_total` 必须自洽 | bit0 = 1 时 `seg_total` 不得填全 1（自称已知却给未知）；bit0 = 0 时 `seg_total` **必须**是全 1（自称未知却给了数） |
| 观测 | 段标识本身在文件头 `header_crc32` 的覆盖之外 ⇒ 它的实测失效形态是**静默丢失**而不是打开失败，所以「拿不到块」「块不成立」「声明有间断」三类都必须做成可查的计数，不能只走日志 |
| 段轨基准 | 两个 tick 字段走**整条逻辑视频的全局容器 tick 轴**（1/1 081 080 000 秒），**不是段内零基** ⇒ 各段可直接比大小、判接缝，无需先归零；两字段**同为视频流 DTS（解码序）轨**（起 = 首帧 DTS、止 = 末包 DTS），非视频流的包不参与；段时长 = `seg_end_ticks − seg_start_ticks`；`seg_flags` bit2 = 0 时 `下段 start − 上段 end` = 该视频流一帧的 tick 数 |
| `duration_ticks` ≠ `seg_end_ticks` | 段块两字段由**调用方给定**、容器层只搬运不解释，且它是 **DTS 轨**；文件头 `duration_ticks` 由库按「**各条流末帧的 PTS** 折算成全局 tick 后取最大」计（音频也参与，其时间基换算不整除）⇒ 带 B 帧或音频更长的段里两者不相等（实测差 1~2 个帧步长）。读方**不得互换或拿其一推另一**；要判段末的呈现位置一律自算 PTS |

### 4.4 数据包

```text
偏移  长度    字段               取值与约束
0     4       total_size         从 stream_id 起算的字节数（含 crc32，不含自身）
4     1       stream_id
5     1       flags              bit0 = is_keyframe
                                 bit1 = is_fragment
                                 bit2 = is_last_fragment
                                 bit3 = has_pts
                                 bit4 = has_fec
                                 bit5-7 reserved
6     varint  fragment_index     仅 is_fragment = 1 的包；自 0 起，帧首片 = 0
...   varint  dts_delta          语义见 §5.2
...   varint  pts_delta          zigzag；仅帧首包，语义见 §5.2
...   varint  payload_size
...   varint  ext_len_varint     包级扩展段长度，本版 = 0
...   N       payload
...   N       ext_data
...   4       crc32              覆盖包内 [4, total_size)
```

`ext_len_varint` 与扩展块里那个 4 字节 `ext_len` 是两回事：前者是包内扩展段的 varint 长度字段，后者是扩展块固定头里的 u32 长度字段。

**分片携带口径**：分片帧的每个分片包都**自带完整外层头**（`total_size` / `stream_id` / `flags` / `dts_delta` / `payload_size` / `ext_len_varint` / `crc32`），不依赖前一包的头部信息。`is_fragment = 1` 时 `fragment_index` 占偏移 6，`dts_delta` 的起算点后移 `len(fragment_index)`；未分片包的 `dts_delta` 仍在偏移 6。`flags` 位图不因本字段而变动。

**字段仲裁规则**：

| 字段 | 规则 |
|---|---|
| `payload_size` | **必须**满足：`total_size` = `1(stream_id)` + `1(flags)` + `len(fragment_index)`（未分片包为 0） + `len(dts_delta)` + `len(pts_delta)`（非帧首包为 0） + `len(payload_size)` + `len(ext_len_varint)` + `payload_size` + `ext_len_varint` + `4(crc32)`。等价形：读完 `ext_len_varint` 后的剩余字节 = `payload_size + ext_len_varint + 4`。不符按 §7 丢包档处置——丢弃本包 + 计数 + 游标跳 `total_size`，**不触发重同步** |
| 帧首包 | 单包帧（`is_fragment = 0`）或 `fragment_index = 0` 的分片包。**帧首包的判定一律以此为准**，不由 `has_pts` 承担 |
| `has_pts` | **冗余位**：所有流的帧首包与所有分片一律置 1。读方的 flags 指纹要求它为 1，读到 0 即判包头不成立。本位**不**表示 `pts_delta` 是否存在，也**不**用于区分首片与后续片 |
| `is_last_fragment` | 包外层 `flags` 是**唯一权威来源** |
| `has_fec` | **本版必须为 0**；读到 1 即判包头不成立，不单独报错。本版不写 FEC 段 |

**时间戳携带规则**：

> R1 · **所有流的帧首包**必须携带 `pts_delta`。音频与字幕流的 `pts_delta` 恒为 0，但**仍必须显式携带**；解码器不做流类型分支。  
> R2 · **后续分片包（`fragment_index > 0`）永不携带** `pts_delta`。一帧的 PTS 一律以该帧首包为准。  
> R3 · 无 B 帧时 I / P 帧的 `pts_delta` 恒为 0——这是**推论，不是规则**，**不得**据此省略字段或反向约束编码器。  

**解析前置检查**（顺序即代码顺序）：

| 序 | 检查 | 不成立时 |
|---|---|---|
| 1 | `total_size < 9` | 判包头不成立 |
| 2 | `4 + total_size` 超过读方接受上限（默认 = 最宽一条流的 `max_packet_size` + 41） | 判包超限（§7 的超限档） |
| 3 | 可用字节 < `4 + total_size` | 判截断 |
| 4 | flags 指纹：bit3 必须 1、bit4 必须 0、bit5-7 必须 0 | 判包头不成立 |
| 5 | `crc32` 覆盖 `[4, total_size)` | 判 CRC 不过 |
| 6 | 字段区（varint 最短形式、`payload_size` 仲裁式） | 判字段不成立 |

### 4.5 索引区

```text
索引头（16 字节）：
偏移  长度  字段            取值与约束
0     4     entry_count
4     4     reserved        本版写 0
8     4     header_crc32    覆盖 [0, 8)
12    4     reserved        本版写 0

索引条目（每条 20 字节）：
偏移  长度  字段            取值与约束
0     1     stream_id
1     1     flags           bit0 = 关键帧；其余位 本版写 0，读方忽略
2     2     reserved        本版写 0
4     8     file_offset     该帧首包 total_size 字段的绝对偏移（u64）
12    8     dts             该帧在自身流上的已平移 dts（绝对值，不是增量）
```

| 规则 | 内容 |
|---|---|
| 建条目范围 | **同一帧只在帧首包上建一条**；后续分片不建条目 |
| 排序 | 无条件按**统一时间轴**升序（§5.4），与 `globally_sorted` 取值无关；不按流分组 |
| tie-break | 全局 tick 相等 → `stream_id` 升序 → 同流同 dts 按文件内出现顺序（`file_offset`） |
| 无描述符条目 | 排在最后：单位不明的 `dts` 不参与统一时间轴换算 |
| 读方校验 | `entry_count` 换算出的条目字节数不得超过包区长度，且不超过读方的实现侧接受域；每条 `file_offset` 落在包区 `[area_start, area_end)` 内；整表按上面的排序键非降；每个 dts 都能换算成全局 tick |
| 校验不过 | 只判**索引不可用**：`CLV_ContainerReaderHasIndex` 返回 0、`CLV_ContainerReaderIndexCount` 返回 0；**不判文件损坏**，包区照常顺序解析 |
| 读方假设 | **不得**假设相邻索引条目同流 |

### 4.6 文件尾（16 字节）

```text
偏移  长度  字段             取值与约束
0     8     magic            "CLVEND\0\0"
8     8     total_packets    真实包数
```

写方**必须**在包区与索引区之后写文件尾；`streaming = 1` 时真实包数只落在这里。非流式写入时文件尾与文件头的 `total_packets` 一致。文件尾供独立核对使用；读方的包区终点按 §3 的边界规则推定，不依赖文件尾。

## 5 时间模型

### 5.1 时间基

| 项 | 值 |
|---|---|
| 全局刻度 | **1,081,080,000 ticks/秒**（`2^6 × 3^3 × 5^4 × 7 × 11 × 13`） |
| 视频流 | `timebase = 1/1081080000` |
| 音频流 | `timebase = 1/sample_rate` |
| 字幕流 | `timebase = 1/1081080000` |
| 起点 | 首段：所有流第一帧 DTS = 0；分段容器后续段：= 该流 `first_dts`（绝对值，跨段可比较） |

`1081080000 × timebase_den` 能被 `timebase_num` 整除时，该流每帧的 tick 数是整数。判据以此为准，常用帧率的每帧 tick 数：

| 帧率 | 23.976 | 24 | 25 | 29.97 | 30 | 50 | 59.94 | 60 | 100 | 119.88 | 120 | 144 | 240 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 每帧 tick 数 | 45090045 | 45045000 | 43243200 | 36072036 | 36036000 | 21621600 | 18036018 | 18018000 | 10810800 | 9018009 | 9009000 | 7507500 | 4504500 |

`1001 = 7 × 11 × 13` 被全局刻度整除，这是 29.97 / 59.94 / 119.88 能精确表示的原因；`48000` 与 `192000` 不被整除（差一个 2）。

### 5.2 时间戳语义

```text
dts_delta = 本帧 DTS − 同流解码序上一帧的 DTS
  基准：同流第一帧的 DTS = stream_desc.first_dts（首段强制 0；后续段取该段首帧的绝对 dts）
        该绝对 dts 由段内首包的 dts_delta 直接携带（本段累加基准从 0 起）—— 不得在首包之外再叠加一次 first_dts
  约束：dts_delta >= 0
  编码：无符号 varint（LEB128，最短形式）
  分片：同一帧的所有分片包携带相同值（帧级冗余）

pts_delta = 本帧 PTS − 本帧 DTS
  编码：有符号 varint（zigzag），可为负
  携带：仅帧首包（§4.4 R1 / R2）
  基准：相对本帧 DTS，不是相对上一帧 PTS
```

时间换算：`t = dts × timebase_num / timebase_den` 秒。

### 5.3 写方平移义务

> 封装前，写方**必须**把整条流的时间轴平移至首包 `dts = 0`。原始码流存在负 dts 时（例如 B 帧前瞻使首包 dts 为负），平移由写方统一完成，**读方不承担平移义务**。  
> 平移量在 `pts_delta = pts − dts` 的相减中抵消，故 `pts_delta` 直接取原始两值之差，与平移量无关。  
> 样例：`assets/fixtures/neg_dts.clv` 源首包 dts 为负，落盘后首包 `dts = 0`、`pts_delta = 80`。

写方另有一条入参约束：同一条流的帧**必须按解码序（dts 非降）提交**，乱序被拒且不会写坏文件。

### 5.4 统一时间轴与跨流比较

- 统一时间轴是**逻辑刻度**，不新增文件字段，也不改动各流既有 `timebase` 声明。
- 比较两条流上的两个时间戳**必须用有理数交叉相乘精确比较**：`t_a ≤ t_b` 判 `dts_a × num_a × den_b ≤ dts_b × num_b × den_a`。**不得**取整、**不得**转浮点、**不得**预归一化。乘积需 128 位精确值。
- `flags` bit1 `globally_sorted = 1` 声明**包区**内所有包已按统一时间轴升序排列。该位只声明包序，不改变索引区的排序规则（索引区一律按 §4.5 排序）。
- `globally_sorted = 0` 时包区按写入序排列，跨流呈现顺序由使用方按各流时间基重排。

## 6 分片与帧重组

| 编号 | 规则 |
|---|---|
| C1 | 同一条流内，属于同一帧的相邻分片包 `fragment_index` **必须差 1**（自 0 起连续递增） |
| C2 | 出现跳变（如 `1 → 3`）即视为**丢片**：记录丢片 + 计数 + **继续解析**（游标按当前包 `total_size` 跳到下一包边界） |
| C3 | 丢片处置**不触发重同步**，也**不判整文件损坏**——包边界由 `total_size` 自证，丢的是内容不是同步 |
| C4 | `is_last_fragment` 置位时本帧总片数 = 该包 `fragment_index + 1`，解析器据此与实收片数比对；不符按 C2 处置 |
| C5 | 帧首包缺失（`fragment_index > 0` 的片先到，例如重同步落在帧中间）：该帧的 `dts_delta` 无人认领，一律**丢弃残帧**并计数，时间轴不推进；**不得**靠猜把 delta 加在本片上 |
| S1 | 未收到 `is_last_fragment` 就来了下一帧（帧首片或单包帧）：上一帧按**不完整**出帧（`complete = 0`）+ 计数，不得静默吞掉已收到的内容 |
| S2 | 同帧出现重复 `fragment_index`：忽略后到达的那一片 + 计数，不重复拼接 |
| S3 | CRC 自证成立但 `stream_id` 不在流描述符白名单内：丢弃该包 + 计数，其余流照常解析 |
| S4 | 分片拼接一律按 `fragment_index` **排序落位**，不按到达顺序（同帧两片互换要能复原） |
| S5 | 出帧带 `fragments_received` 与 `fragments_expected`（0 = 末片未见、总片数未知），供使用方判断完整性 |

**资源约束（读方）**：**不得**以 `fragment_index` 的数值为依据预分配缓冲、槽位或其他资源；分片表只按实际到达的片增长，序号极大的单个片只占一个表项加它自己的载荷。分片数据的资源上界由 §4.2 的 `max_packet_size` 护盾承担。

## 7 容错与重同步

**解析分档与处置**（一个包一次判定）：

| 档 | 触发条件 | 处置 |
|---|---|---|
| 成立 | 六项前置检查全过 | 分发载荷，进入 §6 的重组 |
| 截断 | 可用字节不足一个包且位于包区末尾 | 置 `truncated`，包区结束 |
| 包头不成立 | `total_size < 9`、或读不出边界、或 flags 指纹不符 | **触发重同步** |
| 包超限 | 整包长度超出读方接受上限 | 跳得动（本包字节已在窗口内）就丢包 + 计数 + 跳 `total_size`；跳不动才触发重同步 |
| CRC 不过 | `crc32` 与实算不符 | 丢包 + 计数 + 跳 `total_size`，**不触发重同步** |
| 字段不成立 | 非最短形式、`payload_size` 仲裁式不符、字段越界 | 同上：丢包 + 计数 + 跳 `total_size` |

**触发重同步的唯一入口**：下一包的**包头不成立**那一档（见上表）。CRC 不过与字段不成立都不进这里。

**重同步扫描**（窗口 64 KB，本版为定值、不设可调参数）：

```text
在 [pos, pos + 64K) 内逐字节尝试候选位置 q（q 从 1 起，pos 本身已判失败）：
  a. 取 4 字节作为 total_size 候选 TS
  b. 范围校验：TS >= 9 且 q + 4 + TS <= 包区末尾
     （上界复核：TS <= 该 stream_id 对应流的 max_packet_size + 41）
  c. 正向标识（两条都要过）：
     c1. buf[q+4] 的 stream_id 在流描述符白名单内
     c2. buf[q+5] 的 flags 过同一指纹（bit3 = 1、bit4 = 0、bit5-7 = 0）
  d. CRC 复核：覆盖 [q+4, q+TS)，长度 TS − 4
  e. 全过 → 判定 q 为下一个合法包头，回到正常的逐包读法；否则 q = q + 1
扫描失败 → 放弃包区剩余内容，游标推到包区末尾
```

- 步骤 b、c 为**廉价校验，必须先于**步骤 d 的 CRC 计算执行。
- 本版包内没有 magic 字段，候选头的正向标识由 `stream_id` 白名单 + `flags` 指纹 + CRC 复核三者叠加承担；更强的帧同步码属结构变更，不在本条口径内。
- 本版的包区是各流共享的单段线性序列，读方**无法只停一条流**：重同步失败即放弃包区剩余内容。此时**索引区与文件尾照常可读**，仍**不判整文件损坏**，置 `abandoned` 计数。

**解析器容错义务（总条）**：

> 凡 CRC 不过、字段区不成立、或超出接受上限的包，一律**丢弃 + 计数 + 跳到下一包边界**（跳不动时才重同步）；**永不判整文件损坏**。单包、单帧、单流的损失只在该对象的范围内生效，其余流继续按各自时间轴解析。

**观测口**：全部计数经读方统计一次取回，字段含义见 `include/CLV_Container.h` 的 `CLV_ReaderStatsC`——`packets_ok`、`dropped_crc`、`dropped_field`、`dropped_too_large`、`dropped_unknown_stream`、`resync_count`、`resync_bytes_scanned`、`resync_failed`、`frames_ok`、`frames_incomplete`、`fragment_gaps`、`missing_first_packets`、`duplicate_fragments`、`ext_blocks_bad`，加 `truncated` 与 `abandoned` 两个标志。

## 8 上限一览

| 对象 | 上限 | 来源 |
|---|---|---|
| 单文件长度 | 结构不设上限 | 索引 `file_offset`、描述符 `ext_offset`、扩展块 `next_ext_offset`、文件级链入口 `file_ext_offset` 都是 u64；分段容器（多个物理文件拼回一条逻辑序列）已落地，格式侧对每段长度同样不设上限，工具侧建议 `min(10 分钟, 4 GiB)` 且只在关键帧切 |
| 流数 | 255 | `stream_count` 是 u8 且不得为 0 |
| `stream_id` 值域 | 0..255 | u8 |
| 单个扩展块载荷 | 4 294 967 295 字节 | `ext_len` 是 u32，上界 = 该字段全 1 |
| 一条扩展块链的块数 | 不限（按 `next_ext_offset` 串） | 读方有实现侧接受域（跳数上限），见下 |
| 索引条目数 `entry_count` | 4 294 967 295 条 | 索引头里是 u32；读方另有实现侧条目数上限，见下 |
| 单包 payload | 该流 `max_packet_size`，且 ≤ 8 388 567 字节 | 写方拒超帧；读方按护盾档处置。第二条由写方在登记流时判，派生自读方默认窗口 8 MiB − 外层最坏 41 字节 |
| 单帧载荷合计 | 2^30 = 1 073 741 824 字节 | 含该帧全部分片；写方在合计处判，判在落盘之前。算式：宏块数上界 = 补后像素上界 2^28 ÷ 256 = 1 048 576，单宏块线最坏取整到 1 024 字节 ⇒ 1 048 576 × 1 024 = 2^30；取值钉在 `src/container/writer.h` 的 `kMaxFramePayload` |
| 包外层开销 | ≤ 41 字节 | `total_size` 4 + `stream_id` 1 + `flags` 1 + `crc32` 4 + 各 varint；分片包带 `fragment_index` 不带 `pts_delta`，单包帧反之，两处最坏同为 41 |
| 重同步扫描窗口 | 64 KB | §7，本版定值 |

读方另有若干**实现侧接受域**（一次驻留的窗口大小、扩展块链跳数、索引条目数上限、单个扩展块载荷上界——最后一条按算式派生、不写魔数：默认窗口 8 MiB − 定长前缀 18 − 块尾 CRC 4 = 8 388 586 字节），只决定解析器愿意处理到多大，超出即按 §7 的档位处置或判索引不可用；**不构成格式约束，也不构成新的合法取值范围**，具体取值见 `src/container/`。

## 9 一致性检查清单

按序执行，每步都能由一份 `.clv` 的字节独立判定：

1. 读文件头 64 字节，校验 magic、`header_crc32` 与 §4.1 的值域表。
2. 按 `stream_count` 读描述符表，逐条校验 `crc32`、值域与 `bit_depth` 合法集，登记可用流白名单。
3. 沿各流 `ext_offset` 走扩展块链，校验 magic、`crc32` 与链前进单调，取已确认块的最大结束偏移作为包区起点。
4. 定包区终点：有索引区取 `index_offset`，否则取文件长度 − 16。
5. 从包区起点逐包按 §4.4 的六项前置检查解析，按 §7 的档位处置不成立的包。
6. 按 §6 的规则把分片落成帧，检查片序连续性与末片声明的总片数。
7. 累加 `dts_delta` 得各流绝对 dts，检查首包 dts 为 0（分段容器的后续段改检「等于该流 `first_dts`」）且时间轴非降。
8. 按 §5.4 的交叉相乘核对包序与索引序。
9. 读文件尾，核对 `total_packets` 与统计值、与文件头 `total_packets`（`streaming = 0` 时**必须**一致）。
10. 取读方统计，确认丢包与重同步计数与逐项观察一致。

## 10 预留与未落地

| 项 | 状态 |
|---|---|
| `has_fec` 与包内 FEC 段 | 位已占，本版必须为 0，载荷格式未赋予 |
| 文件头 `flags` 的第 4 到第 7 位、数据包 `flags` 的 bit5-7、各结构 reserved 段 | 本版 = 0，未赋予语义 |
| 包级 magic / 帧同步码 | 本版没有；候选头识别靠 §7 的三重叠加 |
| 段索引表（`ext_type = 8`） | 值已留、本期不实现；段身份走 `ext_type = 7` 的段描述块，那条已落地 |
| `codec_id`、`codec_version`、`codec_flags_0`、`language` | 容器层原样搬运，取值集与编码由各媒体层约定，尚未随本仓库发布 |
| `ext_type` 的未赋予语义取值（层描述、色彩空间、FLAC 流信息副本一类） | 容器层只搬运与校验 CRC，除存在性外不解释载荷。已落地的取值：**3** 视频参数块（对视频流必选）、**4** 字幕全局样式块、**7** 段描述块；**8** 段索引表值已留、未实现 |
| 视频 / 音频 / 字幕载荷的位流格式 | 由各自的规范文档定义，本文只约束容器层；这三份文档尚未随本仓库发布 |
| `include/CLV_Container.h` 的接口形状 | 属对外 ABI：函数名 / 参数结构体 / 出参形态改动即破坏调用方，错误码只在枚举尾部追加。本节只列**格式侧**的未落地项，不含接口形状 |

## 11 术语

| 术语 | 定义 |
|---|---|
| 帧首包 | 单包帧的那个包，或分片帧中 `fragment_index = 0` 的分片包 |
| 后续分片包 | 同一帧中 `fragment_index > 0` 的分片包 |
| 帧级冗余 | 同一帧的所有分片包重复携带同一份 `dts_delta` |
| 包区 | 各流数据包交错排列的连续区段，边界见 §3 |
| 白名单 | 已登记且值域校验通过的 `stream_id` 集合 |
| 不可用流 | 描述符 CRC 或值域不成立、或 `stream_id` 重复的那条流；打开时即被丢弃，因而不出现在可用流列表里，其余流不受影响 |
| 统一时间轴 | 把各流 dts 按 `t = dts × num / den` 归一到同一刻度后的逻辑时间轴 |
| 已平移时间轴 | 写方把整条流平移到首包 `dts = 0` 之后的时间轴，落盘值与读回值都用它 |
| 片序跳变 | 同一帧内相邻分片包的 `fragment_index` 差值不为 1 |
| 残帧 | 帧首包缺失或片不全的帧，按不完整出帧或被丢弃 |
