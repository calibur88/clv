# CLV 视频语法规范

> 本文是 CLV 自研视频流（`stream_type = 0`、`codec_id = 0`）的**载荷语法规范**：一帧的 VOP 载荷由哪些位域组成、宏块与块数据怎么写、系数载体有哪两档、量化档取什么域、失败按哪个码回报。字节口径以仓库内实现与用例钉住的值为准；本文缺项时**不自行补设定**。  
> 文档版本：0.9.0 · 日期：2026-10-26 · 语法版本：**v1**。载荷内部不带版本字段，版本由流描述符（`codec_id` / `codec_version`）与该流的 `ext_type = 3` 参数块声明，见 §4.6。  
> **格式变更须伴随版本升号**：动到线上字节（字段宽度、位序、码表、取值域）即抬声明的 `codec_version`，只澄清语义不动布局才在本文档版本上递增；升号同轮必须重锚入库素材与本文的字节口径条目。  
> 调用面契约（句柄、入参出参、错误码文案）见 `include/CLV_Video.h` 的头注释；一帧的包外层、片序与重组、时间基与索引属容器层，见 `docs/容器规范.md`；分层与依赖见 `ARCHITECTURE.md`。

## 2 全局约定

| 项目 | 约定 |
|---|---|
| 位序 | **MSB-first**：先读的位放在高位，写侧同序；位流里不出现位序标记（`src/video/bits.h`） |
| 单次位宽 | 一次读写**最多 32 位**；越界的请求两侧都不消费（`BitWriter::Write` / `BitReader::Read`） |
| 定长字段 | 帧头与片头里的逐字节字段是**定宽单字节**；片头的 `frame_id` 与 `fragment_count` 为**小端**（`WriteU32LE` / `WriteU16LE`）；参数块的宽与高为**小端 u16**（`ParseEncMeta`） |
| varint | 无符号 LEB128：每字节低 7 位是数据、最高位是续接位；最多 10 字节（`kMaxVarintScratch`） |
| 最短形式 | varint **必须**是该值的最短编码：非最短形式一律判读出的字段不成立（`clv::core::IsShortestVarint`） |
| zigzag | 有符号残差先 zigzag 再走 varint；解码式 `(raw >> 1) ^ -(raw & 1)`（`ReadZigZag`） |
| 字节对齐 | **每个宏块的块数据以字节边界结束**（写侧在本宏块全部在场块写完后 `AlignToByte(0)`）。位位置不跨宏块携带、更不跨片携带 |
| 载荷尾 | 宏块序列解满 `mb_count` 个之后，**剩余不足一字节**的是补齐位，不校验取值；**剩余整字节**判该帧不成立（`DecodeMacroblockLayer` / `DecodeBvopLayer` 的 `used < size` 判点） |
| 位深 | v1 只有 8-bit 一档实现（`kBpp = 8`）；所有饱和边界与预测电平由它派生（`kCoefClampMaxIntra8`、`kCoefClampMaxInter8`、`kResidualClamp*8`、`kSampleMax8`、`kIntraPredLevel8`） |

## 3 帧与片的关系

| 编号 | 规则 |
|---|---|
| F1 | 一帧 = 一个完整的 **VOP 载荷** = VOP 帧头 + 宏块序列（或 B 帧的宏块序列）。包外层、片序、时间戳都不在载荷里 |
| F2 | 片（分片）按**宏块边界**切，不按字节切；每片从宏块边界起始、到宏块边界结束；片数 **≤ 65 535**（`kMaxFragmentCount`，上限由片头 `fragment_count` 的 2 字节宽度推出） |
| F3 | 片数 = 1 时载荷**不含片头**，直接从 `vop_type` 起；片数 > 1 时**首片** = 片头 + **完整 VOP 帧头** + 该片宏块，**后续片** = 片头 + 该片宏块 |
| F4 | 片序由容器外层包头的 `fragment_index` 承担，片头里没有片序字段。片头的 `is_first_fragment` / `is_last_fragment` 是**冗余声明**，与容器外层同时出现时以容器外层为权威，两者矛盾即判片头不成立 |
| F5 | 片界不另立长度字段：每片片头带 `mb_run`（该片实际宏块数），解完 `mb_run` 个宏块吃到的字节数就是下一片的起点 |
| F6 | 运动矢量预测链**在片界重置**：层函数每次调用内新建预测器状态、调用结束即弃，故多片路径等价于「每片从 0 起」，坏片不传染 |
| F7 | 片是各自独立的字节缓冲，片界是**缓冲区边界**而不是位位置——这是片级并行能成立的前提，属规范性要求 |
| F8 | 「每片宏块数」是**编码器配置**（`CLV_VideoEncParamsC.slice_mb_count`），**不进码流**；码流里唯一的真相是片头的 `mb_run`。解码侧对配置值完全无感知 |

**整帧入口的调用方契约**（`CLV_VideoDecoderDecode` 的 `fragment_count`，取容器出参 `CLV_FrameC.fragments_expected`）：

| # | 判据 | 不成立时 |
|---|---|---|
| 1 | `fragment_count` **必须** > 0 且 ≤ 65 535（0 = 没等到末片就喂） | `CLV_VIDEO_VALUE_RANGE`，不进解析 |
| 2 | 片必须已按 `fragment_index` 升序拼好 | 由容器读方保证，本层不设「片不完整」这一档 |
| 3 | 声明 ≥ 2 时，片头在带的 `fragment_count` 与声明值对账 | `CLV_VIDEO_VALUE_RANGE` |
| 4 | 声明 ≥ 2 时，各片 `mb_run` 累加 = 首片 VOP 头的 `mb_count` | `CLV_VIDEO_VALUE_RANGE` |
| 5 | 声明 ≥ 2 时，本片 `first_mb` = 前片累加值（首片为 0），即片按宏块光栅序首尾相接 | `CLV_VIDEO_SLICE_SEQUENCE` |
| 6 | 整段载荷必须被吃光（不多不少） | `CLV_VIDEO_VALUE_RANGE` |
| 7 | 声明 = 1 时走单片解析路径：多片拼接的字节不构成一帧的单片载荷 | `CLV_VIDEO_HEADER_BAD`（该路径没有片头可对账） |

**段与片无关**：段界落在帧边界上，一个段一个编码器实例，故库里没有跨段参考状态。无参考可依的位置（段首、新句柄首帧）**只接受 I 帧请求**，请求 P / B 判 `CLV_VIDEO_STATE_ERROR`——段首真做成 I 帧是结构上成立的，不是约定。

## 4 结构定义

### 4.1 VOP 帧头（定长前缀 6 字节 + varint）

```text
偏移  长度    字段                取值与约束
0     1       vop_type            0 = I，1 = P，2 = B；其余不成立
1     1       vop_quant           量化步长 q，三段域：0 = 无损 / 1..QuantCeiling(quant_precision) = 有损 / 其余不成立
2     1       vop_fcode_forward   1..7，0 非法；本版写方恒 1
3     1       vop_fcode_backward  1..7，0 非法；只对 B 帧有意义；本版写方恒 1
4     1       vop_flags           bit0-2 = intra_dc_vlc_thr
                                  bit3   = 顶场优先，本版 = 0
                                  bit4   = 隔行扫描，本版 = 0
                                  bit5-7 = 系数载体选择器（0 = 定长档，1 = 法 1 档；2..7 不成立）
5     1       vop_dquant          bit0-4 = 帧级量化偏移（5 bit 二补码，域 -16..+15）
                                  bit5-7 = reserved，本版 = 0
6     varint  mb_count            本帧宏块数，不得为 0，且必须等于 `mb_width × mb_height`
...   N       宏块数据            恰好 mb_count 个宏块首尾相接
```

**`vop_flags` 位语义与掩码**（两条掩码是格式定义的一部分，定义在 `headers.h`）：

| 位 | 名称 | 语义 | 掩码常量 |
|---|---|---|---|
| bit0-2 | `intra_dc_vlc_thr` | 本版**无消费点**：两档系数载体都不做 DCT 系数 VLC，没有供它选择的档位表。写侧恒 0；读侧取位后既不判值也不使用 | — |
| bit3 | 顶场优先 | 本版必须为 0 | `kVopFlagsReservedMask = 0x18` |
| bit4 | 隔行扫描 | 本版必须为 0 | 同上 |
| bit5-7 | 系数载体选择器 | 已赋予语义，**不是保留位**；只认 0 与 1，读到 2..7 判该帧不成立 | `kVopCoefCodingMask = 0xE0`、`kVopCoefCodingShift = 5` |

**`vop_dquant` 字节的 reserved 掩码** = `kDquantByteReservedMask = 0xE0`（bit5-7）。帧级偏移域 `-16..+15` 由 `kVopDquantMin` / `kVopDquantMax` 给出，与宏块级 `kMbDquantMin` / `kMbDquantMax`（2 bit，`-2..+1`）是**同族两档、位宽不同故值域不同**，两级偏移不得互换。

**读方判点**（任一不成立即整帧判不成立、拒这一帧，句柄状态不推进。可用字节不足「定长前缀 6 + 至少 1 字节 varint」时本函数同样返回假，**出口码按调用路径给**：单片路径与多片路径的帧头这一道都落 `CLV_VIDEO_HEADER_BAD`，落不到 §7 的 67 那一格）：

| 检查 | 不成立时 |
|---|---|
| `vop_type > 2` | 帧头不成立（`CLV_VIDEO_HEADER_BAD`） |
| `q` 越出三段域（既非 0 也不在 `[1, QuantCeiling(p)]`） | 同上 |
| 两侧 `fcode` 为 0 或 > 7 | 同上 |
| `vop_flags` 的 bit3-4 非 0 | 同上 |
| `vop_flags` 的 bit5-7 > 1（未赋法） | 同上——**不得**把未知当 0 处理 |
| `vop_dquant` 的 bit5-7 非 0 | 同上 |
| `mb_count` 非最短形式、读不尽、或为 0 | 同上 |

`fcode` **只判存在性，不做限幅**：本库的运动矢量差走 §4.3 的 zigzag varint 全域，不受 `fcode` 限幅、没有折叠分支，该字段只作声明值在场。

### 4.2 分片片头（只在真分片时出现）

```text
偏移  长度    字段              取值与约束
0     4       frame_id          小端 u32；把同帧的片归组，不代表顺序（单片帧不发片头，故不占号）
4     2       fragment_count    小端 u16，本片所属帧的总片数，**必须 ≥ 2**，≤ 65 535
6     1       flags             bit0 = 末片，bit1 = 首片，bit2 = 携带 vop_quant，bit3-7 = reserved
7     1       vop_type          同 §4.1
8     1       vop_quant         仅 bit2 = 1（首片）时在场，域同 §4.1
...   varint  first_mb          本片第一个宏块的光栅序
...   varint  mb_run            本片实际携带的宏块数，**必须 ≥ 1**（0 = 空片）
...   N       该片宏块数据      mb_run 个宏块首尾相接
```

| 规则 | 内容 |
|---|---|
| 定长部分 | 后续片 8 字节、首片 9 字节（`kSliceFixedNoQuant` / `kSliceFixedWithQuant`），两个 varint 另计 |
| 携带位自洽 | `bit2` 与 `bit1`（首片）**必须同值**：`has_vop_quant != is_first` 即判片头不成立 |
| 保留位掩码 | 片头 flags 的 bit3-7 = `kSliceFlagsReservedMask = 0xF8`。**它与帧头是两个字段、两条位序，不共用常量**——帧头的 bit5-7 已赋予选择器语义，两处的「保留」定义就此分岔 |
| 空片分档 | 空片（`mb_run = 0`）是**值域不成立**；「片头读不尽」「携带位矛盾」才是**片头不成立**（`CLV_VIDEO_SLICE_HEADER_BAD`）。字段先交出再判空片，调用方要按档分派 |
| 权威来源 | 首末片位以容器外层为权威；`fragment_count` 是片数在码流里的唯一载体，也是喂入侧片数的对账依据 |
| 长度校验 | 载荷剩余不足 `block_size` 声明的字节数即判载荷过短；片解满后按**向上取整到字节**回报消费量，下一片的片头从该处起 |

### 4.3 宏块头 · I / P 型（变长码）

字段序：`not_coded(1 bit)` → `mcbpc` → `cbpy` → `dquant(2 bit)` →〔`motion_vector()`〕→ `block_size(varint)` → 块数据。

| 字段 | 宽度 | 语义 |
|---|---|---|
| `not_coded` | 1 bit | 1 = 本宏块无残差，**跳过其后全部字段**（含块模式、量化偏移、运动矢量），码流里只占这一 1 bit。解码端按「帧间、运动矢量为零、无系数」处置。I-VOP **没有 skip 语义**：`not_coded = 1` 在 I 帧一侧是写方不会产出的位型，读到即判该帧不成立 |
| `mcbpc` | 1..9 bit 变长 | 一行同时给出宏块类型与色度块模式 `cbpc`（2 bit） |
| `cbpy` | 2..6 bit 变长 | 四个亮度块的块模式（4 bit） |
| `dquant` | 2 bit 定宽 | 宏块级量化偏移，每个已编码宏块都带，无逃生路径 |
| `motion_vector()` | 2 枚 zigzag varint | **只在「帧间且 `not_coded = 0`」时在场**；帧内宏块不带（压根没有矢量），`not_coded` 宏块也不带（矢量恒零但照样参与预测器推进） |
| `block_size` | varint | 本宏块**块数据的字节数**，覆盖该宏块全部在场块；`not_coded = 1` 时必须为 0 且块数据不在场 |

**三张码表与本库的行数**（`src/video/annex_b_tables_p.h`）：

| 表 | 本库行数 | 行构成 | 码长集合（bit） |
|---|---|---|---|
| `kMcbpcIVop` | **5** | 4 行 intra + 1 行 Stuffing | 1 / 3 / 9 |
| `kMcbpcPVop` | **13** | 4 行 intra + 4 行 inter + 4 行 inter4v + 1 行 Stuffing | 1 / 3 / 4 / 5 / 6 / 7 / 8 / 9 |
| `kCbpyFourBlocks` | **16** | 帧内查 `intra` 列、帧间查 `inter` 列，两列**逐行互为按位取反** | 2 / 4 / 5 / 6 |

宏块类型编号与名称按 ISO 的 `MB type` 编号：`0 = inter`、`2 = inter4v`、`3 = intra`、`-1 = Stuffing`（`kMbTypeInter` / `kMbTypeInter4V` / `kMbTypeIntra`）。**本库两张 `mcbpc` 表不含 `+q` 行**（`mb_type = 1` inter+q、`4` intra+q）：宏块头无条件带 2 bit 量化偏移，`+q` 与不带 `q` 的差别不存在。被裁掉的行留在 `kMcbpcIVopDroppedQRows`（**4** 行）与 `kMcbpcPVopDroppedQRows`（**8** 行）里作对照——它们**不属于本库码流语法**，逐个喂回解码器必须判表外码字，不得静默命中别的码。

**两条失败路径不得混用**：表内保留的排除集行（`mb_type = 2` 与 Stuffing）判「被排除的工具」（`CLV_VIDEO_TOOL_EXCLUDED`）；**两张表都不含的码字**判码流不成立（`CLV_VIDEO_HEADER_BAD`）。

**`cbpc` 列的读法**：表内 `cbpc` 的 2 bit 按 §4.5 的合成位序读——**bit1 = Cb、bit0 = Cr、`00` = 两色度块都不在场**。从外部标准搬过来的只有码字行（码长、码值、宏块类型），列语义随本库位图位序定，**不沿用外部标准的 4:2:0 色度块模式码原列读法**（原读法 `00` = 两块都在场、`11` = 无）。编解两侧同表、同合成式 `(cbpy << 2) | cbpc`，位流不与外部解码器互通。

**`dquant` 位型表**（2 bit 二补码）：

| 位型 | `00` | `01` | `10` | `11` |
|---|---|---|---|---|
| 偏移 | 0 | +1 | −2 | −1 |

**`motion_vector()`**：两条 zigzag varint 残差，相对**三候选逐分量取中值**的预测器。候选取同层已解码宏块的 A（左）/ B（上）/ C（右上）；越界、缺位、或该邻居不带该方向（帧内宏块）时**按零矢量参与中值**。矢量单位是**半像素**（偶值 = 整像素、奇值 = 半像素），两分量按 32 位有符号交付；预测 + 残差回绝对矢量时先在 64 位里定界再落回 32 位，越界取 `INT32_MAX` / `INT32_MIN`，**不静默回绕**（`SaturateVectorComponent` / `AddMvComponent`）。

**`block_size` 校验**（一律按**字节**口径）：

| 条件 | 判定 |
|---|---|
| `block_size` 大于载荷剩余字节数 | 载荷过短（`CLV_VIDEO_PAYLOAD_TOO_SMALL`） |
| `block_size` 自身的 varint 读不尽 / 非最短形式 | 码流不成立 |
| `block_size = 0` 且块模式非全零 | 取值不成立——有残差就至少有一块数据 |
| `block_size = 0` 且块模式全零（或 `not_coded = 1`） | **合法**：本宏块不带块数据，全部块按零残差处置 |

### 4.4 宏块头 · B-VOP 型（本库自研，字节对齐）

B 帧宏块层不走 §4.3 的 `mcbpc` / `cbpy` 变长码。字段序：`not_coded(1 B)` → `mb_type(1 B)` → `mvd[]`（zigzag varint 残差）→ `cbpy`(varint) → `block_size`(varint)。

```text
偏移  长度    字段          取值与约束
0     1 B     not_coded     0 或 1；> 1 判码流不成立
1     1 B     mb_type       0 = direct，1 = interpolate，2 = backward，3 = forward；4..255 本版 = 0，读到即判被排除的工具
...           mvd[]         个数由 mb_type 推：direct = 0，interpolate = 2，backward / forward = 1；interpolate 按**前向、后向**次序排
...   varint  cbpy          **六块全位图**，值域 0..63（`kPatternMask6`），直存图样本身，不查变长码；越界判取值不成立
...   varint  block_size    仅 `not_coded = 0` 时在场；= 0 的合法性同 §4.3（位图全零才成立）
...   N       块数据        not_coded = 0 时才有，长度 = block_size
```

| 规则 | 内容 |
|---|---|
| `not_coded` 与 I / P 侧**不同义** | 它只决定后面接不接块数据，**不跳过任何字段**：`mb_type` / `mvd[]` / `cbpy` 照旧在场（direct 型仍占 `mb_type` 那一字节） |
| 位序 | 本节的 `cbpy` 是同一张 6 bit 合成位图（bit5..2 = 亮度块 0..3、bit1 = Cb、bit0 = Cr），不单独设色度字段 |
| 自洽 | `not_coded = 1` 时 `cbpy` **必须**为 0（读到非 0 判码流不成立）、块数据必须为空（写侧同判） |
| 预测器 | 残差相对中值预测器，**前向 / 后向各挂一套状态**；`mb_type` 决定邻居带不带该方向，不带即该候选按零参与；状态在每次层调用内新建（片界重置） |
| direct | 不带残差、不带块数据：矢量取**后向参考**同位宏块的矢量纯缩放。同位宏块是帧内、是 `not_coded`、或缺位时按零矢量处理 |
| 帧级时间判据 | `TRB = 本帧 PTS − 前向参考 PTS`、`TRD = 后向参考 PTS − 前向参考 PTS`（容器 tick）。`TRD > 0 && 0 < TRB < TRD` 不满足即**丢这一帧**：`CLV_VIDEO_OK` + `disposition = CLV_VIDEO_DISP_DROP_DIRECT_TIME`，不建帧、不入队、不进参考缓冲 |
| direct 缩放式 | `MVF = (TRB × MV_ref) / TRD`、`MVB = MVF − MV_ref`；乘与除一律 64 位有符号、`/` 取**向零截断**的整数除法（禁 `>>`）；结果按 §4.3 的饱和口径落回 32 位。入口另有 `TRD <= 0` 与 `TRB > TRD` 两档判**取值不成立**（宏块式检查，与上面的帧级判据分属两层、互不替代） |
| 双向合成 | 两向各取一套六块后逐像素平均 `P = (Pf + Pb + 1) >> 1`（`BidirectionalAverage` / `BlendMacroblocks`，direct 与 interpolate 同一条式子） |

### 4.5 块数据与系数载体

**块存在性** = 合成块模式位图：`cbpy`（4 bit 亮度）与 `cbpc`（2 bit 色度）合成 6 bit，**bit5..2 = 亮度块 0..3（左上起、行优先），bit1 = Cb，bit0 = Cr**。位为 0 的块不占任何字节；位为 1 的块按位序从 bit5 到 bit0 依次紧随写出。一个宏块 6 块（`kBlocksPerMacroblock`）。

**系数顺序**：一个 8×8 块的 64 个系数按**自然行序**排列，`n = 0..63`、`(u, v) = (n % 8, n / 8)`、`n = 0` 是 DC。**不引入 zigzag，也不引入 alternate 扫描**。

**位宽不进码流**：每系数位宽由生效量化步长 `q'` 与块型（帧内 / 帧间）现算，两侧同式（`BlockBits` / `BlockQfMax`）。算式 `bits(q') = ⌈log2(QF_max(q') + 1)⌉ + 1`，`QF_max` 是该档幅值上界。

**两张七档表 + 无损档**（表体在 `block.cpp` 的 `kIntraRows` / `kInterRows` / `kLosslessRows`；`q` 落在「本档起点 ≤ q < 上一起点」即取本档，末档起点 65（帧内）/ 64（帧间）覆盖 `q` 的整个可表达域，不另按字面量截断）：

| 帧内 `q'` 起点 | 每系数位 | `\|QF\|` 上界 | 定长档单块字节 | 法 1 档单块最坏字节 |
|---|---|---|---|---|
| 1 | 13 | 4095 | 104 | 209 |
| 3 | 12 | 1365 | 96 | 177 |
| 5 | 11 | 819 | 88 | 161 |
| 9 | 10 | 455 | 80 | 145 |
| 17 | 9 | 240 | 72 | 129 |
| 33 | 8 | 124 | 64 | 113 |
| 65 | 7 | 63 | 56 | 113 |

| 帧间 `q'` 起点 | 每系数位 | `\|QF\|` 上界 | 定长档单块字节 | 法 1 档单块最坏字节 |
|---|---|---|---|---|
| 1 | 14 | 8159 | 112 | 209 |
| 2 | 13 | 4080 | 104 | 193 |
| 4 | 12 | 2040 | 96 | 177 |
| 8 | 11 | 1020 | 88 | 161 |
| 16 | 10 | 510 | 80 | 145 |
| 32 | 9 | 255 | 72 | 145 |
| 64 | 8 | 127 | 64 | 129 |

| 无损档 `q' = 0` | 每系数位 | 幅值域（= 变换输入域本身） | 定长档单块字节 | 法 1 档单块最坏字节 |
|---|---|---|---|---|
| 帧内 | 15 | 8192（= `64 × 2^(bpp−1)`） | 120 | 225 |
| 帧间 | 15 | 16320（= `64 × (2^bpp − 1)`） | 120 | 225 |

帧间各档起点比帧内同序档低 1、位宽恰多 1（除首档两侧同为 1 之外）。无损档不是「第 8 档有损」：它装的域是 `kCoefClampMaxIntra8` / `kCoefClampMaxInter8`，与第二级饱和域同源，载体位宽 `1 + ⌈log2(界 + 1)⌉ = 15`，两档同宽；有损 `q' = 1` 档（13 / 14 bit、上界 4095 / 8159）装不下满幅系数，故无损**不能**靠「把有损档取到最细」得到。

**系数载体有两种写法：定长档与法 1 档（先写结束标志 EOB，再用位数递增的 Exp-Golomb 编码写幅值）；具体用哪一档由视频帧头第 5 到第 7 位声明，本库默认法 1。**

| 档 | 选择器值 | 每块的写法 | 符号 | 零的表达 |
|---|---|---|---|---|
| 定长档 | 0 | 64 个系数逐个定宽直写：每系数 `bits(q')` 位 = 1 bit 符号（0 正 1 负）+ `bits(q') − 1` bit 幅值，**符号位在前** | 每系数都带 | `QF = 0` 时符号位仍写 0——**不做零省略**，零照样占位 |
| 法 1 档 | 1 | `all_zero` 1 bit →（为 0 时）`eob` 6 bit → 槽 `0..eob` 依次写 `level` = 幅值的 Exp-Golomb(order-0) | **只在非零槽出现**，紧跟该槽的 level | 零槽占一格 `EG(0)` = 1 bit，不写符号位；块尾（`eob` 之后）一概不写 |

| 项 | 口径 |
|---|---|
| 选择器来源 | 帧头 `vop_flags` bit5-7，**逐帧携带**：解码侧按帧头取档，不拿建解码器时的假设顶替码流事实；编码器写哪一档是编译期事实（构建项 `CLV_COEF_CODING`，取值 0 / 1），不占公开面入参 |
| `eob` 字段宽 | 6 bit（`kEobFieldBits`）——`all_zero` 已吃掉「整块无非零」那一档，剩下的取值恰是下标 `0..63`，`eob ≥ 64` 在字段宽度上结构性不可能出现，读方**不需要另补范围判据** |
| EG 码长 | order-0：`x = level + 1`、`L = ⌊log2 x⌋`，写 `L` 个 0、再写一个 1、再写 `x` 的低 `L` 位 ⇒ 码长 `2L + 1`；无参数、无表、自分隔（`WriteEg` / `EgBits`） |
| 读侧前导零上限 | `kEgMaxPrefix = 24`：前导零数到 24 时值已接近 `2^24`，远超任何一档的上界，**到顶即判读不尽**（载荷过短），这一条本身就是拒绝路径 |
| 全零块 | 位图为 1 而 64 个系数全零：定长档**没有**能表达它的码字，读到即判取值不成立；法 1 档语法允许 `all_zero = 1` 写成合法码字，解回来是全零系数而不是失败。写方两档都不给全零块置位图 ⇒ 这条差别只在坏码流或人为构造的流上可见，它是**语法的表达力**，不是写方的自由度 |
| 上界判据 | `\|QF\| ≤ BlockQfMax(q', intra)`（定长档由载体宽度给出，法 1 档由 `bits(q')` 给出的仍是同一个幅值上界），越界判取值不成立 |
| `eob` 位必须非零 | 法 1 档读到 `qf[eob] = 0` 判取值不成立——`eob` 的定义就是「最后一个非零系数的下标」 |
| 宏块级长度校验 | 定长档：`block_size` **必须恰等于** `present × BlockBytes(q', intra)`；法 1 档：只卡上界——`present = 0` 时唯一合法值是 `block_size = 0`，其余 `1 ≤ block_size ≤ present × BlockBytesMax(q', intra, 法 1)`。判点在 `BlockSizeMatches` |
| 解完的封口 | 定长档剩位必须为 0；法 1 档允许剩 `0..7` 位补齐，**剩整字节**即与本法自终止出的块界矛盾，判取值不成立 |
| 最坏字节数为什么必须按档另算 | `BlockBitsMax(法 1) = 1 + 6 + 64 × (EG(QF_max) + 1)`。变长只在**平均意义**上更短：满幅系数的 EG 码长**过** `bits(q')`，沿用定宽档的「块数 × 单块定宽」会把稠密内容判成码流不成立，那是解码端自造的假阳性 |
| 两法都不得改重建 | 两档承载的是同一组 `QF`，反量化与重建式一字不变 ⇒ 同一条输入在两档下的重建像素逐字节相同；换档只动码率与长度校验口径 |
| 本条不是压缩收益 | 定长档下帧内要 `q' ≥ 33`、帧间要 `q' ≥ 64` 才追平「宏块 384 B」；帧间最低就是 8 bit / 系数。定长档存在的目的是让变换-量化-反量化-反变换在位流里真有位置，把它当码率指标读是错的 |

**零残差的三档，不得混用**：位图为 0 的块按零残差处置（重建即预测块）；`not_coded = 1` 的宏块从参考帧整块搬预测（`ScatterBlock8x8`），其块模式与块数据都不在场；`block_size = 0` 且位图全零的宏块六块都写预测块。

## 5 量化档

| 项 | 口径 |
|---|---|
| 合法域三段 | **`q = 0` = 无损档**（块数据直载变换系数原值，不量化、不夹取）/ **`1 ≤ q ≤ 2^p − 1` = 有损档**（`p = quant_precision`）/ **其余取值 = 域外不成立** |
| 上界的唯一推导点 | `QuantCeiling(quant_precision) = min(2^p − 1, 255)`，`p` 先夹进声明域 `[3, 9]`。入参先夹是因为 `vop_quant` 字段本身只有 1 字节，`p ≥ 8` 时上界取不满。**帧头校验、片头校验、编码入口、有效步长夹取四处一律经本函数取界** |
| v1 取值 | `p = 7` ⇒ 有损段是 `[1, 127]`。**条文与判式都不写死 127**：`p ≠ 7` 时按 `2^p − 1` 取界 |
| 下界 | 恒为 1，与 `quant_precision` 无关（`q' = 0` 没有反量化式，`kQuantMin`） |
| 有效步长 | `q' = clamp(q + d_vop + d_mb, 1, 2^p − 1)`（`EffectiveQuant`）：帧级偏移域 `-16..+15`、宏块级 `-2..+1`，v1 两级叠加，**不设 escape 路径、不设量化方法标志位**——模式信号只有 `q` 本身 |
| 无损支 | `q = 0` 时 `q'` 原样取 0，帧级与宏块级偏移都不参与算术（`FrameQuant` 是全库唯一取档口：无损流若被偏移量折进有损档，两侧就不再逐字节全等）。字段照旧在场、写方写 0、读方略过，不新设标志位 |
| v1 编码侧写出的偏移 | `vop_dquant` 恒为 0、宏块级 `dquant` 恒为 0；`CLV_VideoFrameInfoC.quant_used` 是本帧帧头的 `vop_quant` 原值，两级偏移与夹取在量化那一步现算、不回填该字段 |
| 反量化 | v1 只有一种算法（第二法反分段，电平集 `{0} ∪ {±((2n+1)q − δ)}`，`δ = 0`（q 奇）/ `1`（q 偶），步长 `2q`，无 ±q 级） |

## 6 变换、域与重建

| 项 | 口径 |
|---|---|
| 正变换 | `T = H X Hᵀ`，`H` 是 8×8 Sylvester Hadamard（元素 ±1），全程整数、**不归一** |
| 反变换 | `Y = H T H ÷ 64`（除以 64 = 2⁶，双精度下整数÷64 精确可表示） |
| 反变换输出取整 | `f = (Y ≥ 0) ? ⌊Y + 0.5⌋ : ⌈Y − 0.5⌉`（四舍五入、半程离零，`RoundResidual`）。编解两侧逐字同式；任一侧换取整（截断、就近偶、查表改写）两侧就不再逐字节全等 |
| 四级饱和域 | ① 码流系数 `\|QF\| ≤ QF_max(q')` → **越界判取值不成立**；② 反量化后系数 → 按块类型两档 `±T_max`（帧内 8192 / 帧间 16320）→ **夹取、不拒解**；③ 残差域 `[−2^bpp, 2^bpp − 1]` = `[−256, 255]` → 夹取；④ 重建 `d = 预测 + f` 夹 `[0, 2^bpp − 1]` = `[0, 255]` → 夹取，**存进参考帧的是夹完的值** |
| 为什么第二级不是 `±2^(bpp+3)` | 那个界只在**归一化**变换下成立。本库变换不归一，`DC = 64 × 残差均值`，照搬等于把残差均值限死在 ±31.98，而帧内预测电平恒 128 ⇒ 亮度出 `[96, 160]` 的块全被砍 DC |
| 帧内预测 | 帧内宏块的预测块**恒为常量** `kIntraPredLevel8 = 2^(bpp−1) = 128`；v1 不做帧内 DC / AC 预测（属排除集），故系数载体不吃块位、不吃邻块 |
| 宏块与块几何 | 一个宏块 16×16（`kMbSize`），含四个亮度 8×8（左上起、行优先）+ Cb 8×8 + Cr 8×8；平面内地址唯一由 `MacroblockBlockAt` 给出，四处共用 |
| 半像素取样 | 参考取样坐标 = 整像素坐标 ×2 再叠矢量（全程 int64，`PredictBlock8x8`）。核三式，舍入固定 `R = 0`：横向 `(A+B+1)>>1`、纵向 `(A+C+1)>>1`、双轴 `(A+B+C+D+2)>>2`，整像素直接取 A。亮度与色度**同核**，差异只在矢量换算与块尺寸 |
| 色度矢量换算 | `round_half(v) = floor((v + 1) / 2)`（负数也向下取整）；用整除式写而不用右移，因负数右移在标准里是实现定义 |
| 参考缓冲边缘 | 参考帧带一圈 1 像素边缘复制带：坐标越界时取最外像素（`SampleReplicated`）；复制带属取数口径，不落缓冲、不进码流、裁回显示尺寸时也不带；**矢量本身一律不裁剪** |
| 补边与裁回 | 原始显示尺寸 ∈ `[1, 65535]`，必须声明；补后尺寸 = 原始尺寸向上取整到 16 的倍数、**不落字节**，由 `CLV_VideoCodedSize` 按 32 位无符号推导（原始 65521..65535 时补后 65536，需 17 位）。补黑只补右与下，填充宏块照常编码；显示按原始尺寸裁回，原始尺寸未声明时不裁边 |
| 编码侧闭环 | 帧间预测与运动估计的参考像素一律取自编码器自己产出的重建帧（`ref` / `cur` 双缓冲、帧末交换），不得取自调用方喂入的原始帧；B 帧不进参考链 |

## 7 错误码段与留白

| 项 | 口径 |
|---|---|
| 段位 | 视频面是**独立枚举**：成功恒 0，失败码落在 **64 到 95** 段内，**现用到 85**；枚举成员 18 个、失败码 17 个 |

## 8 帧池与帧的归还

| 项 | 口径 |
|---|---|
| 三种持有 | 一帧的引用计数只有这一份账，落在帧对象上，来源三处：**架上持有**（建帧那一次，跟着这帧走完「待输出队列 → 待取队列」）、**参考窗持有**（I / P 进参考缓冲时由调度器加，逐出 / 冲刷 / 重置时放）、**调用方持有**（取帧口交出时加） |
| 归还语义 | 取帧口交出帧时引用计数加一；调用方用毕调 `CLV_VideoFrameFree` 减一；计数归零的帧才回收进空闲池。Free 之后该帧指针失效，建议立即置空。重置或关闭会使所有已交出的帧指针失效，此后再调 Free 返回参数不成立 |
| 两扇门 | `CLV_VideoFrameFree` 带回报码、只受理**取帧口交出的那一次**（状态闸 `handed`，落下后不再受理）；`CLV_VideoFrameRelease` 不带回报、与 `CLV_VideoFrameAddRef` 配对，减调用方名下的任意一次持有。两扇门走同一份计数；交出的那一次还没还时 Release 先消耗它，闸随之落下，此后 Free 判参数不成立——两条路合计只还得掉一次 |
| 重复 Free | 对同一帧重复调用返回参数不成立；跨复用后的陈旧调用属调用方未定义行为，本版本不做幂等保证。重复归还的判点落在「取帧那一次还没还」这道状态闸上，**不落在计数是否归零上**：还在参考窗里的帧计数本来就大于 1，只判归零会让第二次归还把被引用的帧从池里收走 |
| 不复活 | `CLV_VideoFrameAddRef` 对空指针返回 0 且不崩溃；对已作废的帧一律返回 0、不加计数 |
| 失效的落点 | 重置与关闭走同一条作废步：计数账清零、像素缓冲全部回收（`FreePlanes` 用 swap 退还容量）、已交出指针失效。没人持着的格子就地回收；还带着调用方持有的只剩一个对象壳挂在句柄名下，由句柄兜到关闭——壳不能就地 delete，否则失效后那一次归还读的就是已释放内存，那是崩而不是回报 |
| 回收口径 | **可回收 ≠ 全回收**：只回收「引用归零且不在参考窗」的槽位；DPB 参考窗内的帧由解码器自持一份计数，计数自然不为零，**不另设参考窗保护分支**，一动不得。归零的池内槽位连同像素缓冲留在原槽当下一次的空闲位，故常驻量看「同时在场的帧数」而不是「解出过多少帧」 |
| 池饿 | 空闲位取不到时允许槽位数超过参考缓冲 maxlen，超出部分由调用方未归还数封顶 |
| 上界式 | 占用 ≤（参考缓冲 maxlen + 调用方未释放数）×（帧像素字节 + 每帧附加开销）+ 基线。`kDpbMaxlen = 2`；每帧持有字节 = `kFrameHoldBytesMeasured = 3 336 260`（实测，1920×1080 全 I 帧，含池与对齐开销；像素账 3 110 400 B，余 225 860 B 是帧对象、逐宏块矢量场与分配器对齐余量）；基线 = 起池阈值那一档的在途帧与句柄自身。稳态目标 = `maxlen × 每帧持有字节 + 常数`，与帧数无关 |
| 所有权 | 帧对象始终归库，交出去的只是带计数的借用句柄——调用方既不接管内存也不共享所有权；要留内容自己拷。C++ 侧包装层必须自持「已释放」标志（手动 Free 置位、析构先查位再调 C 口），且要么禁拷贝、要么把转移语义写清：一次持有只许有一个所有者；纯 C 调用方没有析构可兜底，仍须显式 Free |
| 编码器申请的帧 | `CLV_VideoEncoderAllocFrame` 交出的帧不落在解码器帧池里，计数归零即释放该缓冲；那一次交出同样带状态闸，Free 只受理一次，重复归还是参数不成立 |
| 码流缓冲 | `CLV_VideoEncoderEncode` 产出的载荷缓冲**归调用方所有**，用完 `CLV_VideoBitstreamRelease`；对 NULL 调用是 no-op，不得对同一指针 Release 两次；编码器关闭不替你释放仍在你名下的码流 |
| 帧平面有效期 | `CLV_VideoFrameGetDesc` 交出的平面指针指向库拥有的缓冲且可写，只到该帧最后一个引用被归还为止有效；已作废的帧一律返回参数不成立且不写出参 |

**输出序与参考缓冲**：

| 项 | 口径 |
|---|---|
| 参考缓冲（DPB） | 只存非 B 帧；v1 非分层 B 结构下容量恒为 `kDpbCapacity = 2`，与 `max_b_frames` 无关。满且要进新 I / P 时逐出**解码序最旧**的一帧（FIFO 头）并放掉参考窗那一次持有，**不得按显示序 / POC 驱逐** |
| 待输出队列 | 按显示序（PTS 升序）排；每解一帧入队，队列长度达到阈值时弹出其中 PTS 最小的一帧；流结束按 PTS 升序清空。**弹出 ≠ 出参考缓冲，驱逐 ≠ 出输出队列** |
| 出帧阈值 | 地板 = `max_b_frames + 2`（重排所需深度，`Scheduler::ReorderFloor`）。`CLV_VideoStreamParamsC.preroll_frames` = 0 表示未声明 ⇒ 取地板；受理后的阈值经 `Scheduler::Threshold` 可查。**只升不降**，低于地板的按地板受理，因为阈值低于地板会在显示序排好之前吐帧，直接违反「出帧按 PTS 升序」这条契约 |
| 冲刷 | 冲刷之后句柄进入 EOS 态，再喂新帧返回 `CLV_VIDEO_STATE_ERROR`，必须先重置才恢复接收 |
| 丢帧不是错误 | 参考缺失、双向时间权重不成立、已解码待输出（显示序落后于解码序）都以 `disposition` 回报、返回值仍是 `OK`；本层不累计分档计数，处置只按当次调用回报，要分档由调用方自计 |

## 11 术语

| 术语 | 定义 |
|---|---|
| VOP 载荷 | 一帧的全部码流字节 = VOP 帧头 + 宏块序列；容器重组后一次交进本层 |
| 片 | 一帧按宏块边界切出的独立字节缓冲，自带片头（单片帧不带） |
| `mb_run` | 片头里给出的该片实际宏块数，是片界在码流里的唯一载体 |
| 在场块 | 合成块模式位图中为 1 的块；为 0 的块不占字节、按零残差处置 |
| 生效量化步长 `q'` | 帧头 `q` 叠上帧级与宏块级偏移并按本流上界夹住后的值，位宽档与上界都按它取 |
| 定长档 / 法 1 档 | 系数载体的两种写法（§4.5）：前者每系数定宽直写、零照样占位；后者先写结束标志 EOB、再用位数递增的 Exp-Golomb 编码写幅值 |
| 排除集 | 本层不收、但表里留着专供识别的宏块语法（4MV、Stuffing、`mb_type ≥ 4`），读到判被排除的工具 |
| 表外码字 | 两张码表都不含的码字，判码流不成立——与排除集分属两条失败路径 |
| 拒解态 | 致命声明码置下的句柄态；除重置、关闭、观测口自身外其余入口一律返回拒解码 |
| 架上持有 | 帧从建好到交进队列之间那一次持有，取帧口交出时交接给调用方 |
| 参考窗持有 | I / P 进参考缓冲时由调度器加的那一次持有 |
| 失效 | 重置或关闭使已交出的帧指针不再可用；此后归还包括参数不成立，指针内容不再作数 |
| 空闲位 | 引用归零后留在池里当下一次复用的槽位（对象与像素缓冲都留着） |
