# CLV 交付记录（回执 / 账本 / 变更日志）

## 触发条件

- 一批改动做完要出统一汇总
- 每落地一件要同步回执（不允许攒到最后一次写）
- 改了字节格式 / 公开面 / 冻结判据，需要登记影响面
- 清扫了一类纪律违例，要把"违例是我引入的"写清

## 三种载体的分工

| 载体 | 是否随仓库发行 | 写什么 |
|---|---|---|
| `CHANGE.log` | 是 | 版本演进与兼容声明：`新增 / 变更 / 修复 / 废除` 四段式 + `测试情况`。每条要让读者据此判断影响范围 |
| 过程账（项目内的工程记录与回执目录） | 否（未随 git 发行） | 逐件落点、实测读数、判读顺序、停点与待拍项。回执一份一文件、带日期、不在其下再建子目录 |
| 项目账本（维护者的私有工作文件） | 否 | 轮次流水、谓词表、执行体边界等元规则 |

**发行件里不得出现的**：私账编号、未发行文档的节号、本机绝对路径、`temp/`、证据件名、跑次编号。
指不到对象比少写一句更坏——协作者克隆后按线索找不到东西。

## 硬规则

1. **追加优先，禁改前件原文**。修订旧结论用"追加更正条"，把旧条原文留着当基线；
   唯一例外：某条自己写着"随后刷新"的占位，按承诺就地刷新（这是兑现，不是重签）。
2. **数值一律带算式，改前改后齐**：例数 `300 → 316`、素材 `347 → 377 B（每条视频流 +30 B = 18 + 8 + 4）`、
   `EXPECT 300 → 316`。没有算式的数字当作未取证。
3. **行数用字节级 LF 计数**，并顺手查 CRLF：中文文件用编辑器统计会差行，`.gitattributes` 钉了 `eol=lf`，
   混进 CRLF 要按机械卫生直接修掉（`.bat` 另有重读陷阱，见门禁规程）。
3b. **账面行有自指**：记"本回执自己有多少行"那一行，改它本身就改行数 ⇒ 该数字只能在**全部编辑落定后**实测一次，
   并在行内写明"落定后实测"。其余各件同理：中途写的行数都是未定稿读数，收尾必须逐件重取并把漂掉的记成追加更正——
   账面漂一次（写了正文再没回来刷新计数）比不写更坏，因为读者会拿它当已核过的事实。
4. **引用内部件钉符号名，不钉行号**；跨文档要点名是哪一份，不带节号。
5. **每落一件更新回执**，订单结束时再给一次统一汇总；两者都要写"当前什么没做完"，不要只写做完的。
6. **自己的失误单独成条**（写错判据、区间替换吞掉函数、审查委托没验产物…）+ 归因 + 修复证据。
   维护者会拿这些条核对下一次是否复发。
7. **对外条目写"机制"不写"决策"**：脱敏不只是删私账编号，还把理由改写成读者能独立验证的话
   （"读到未赋值的编码判字段不成立，不做『未知当 0 处理』" 而不是 "按某单第 X 条拍定"）。
   错误码类条目一律带**码值 + 产它的入口 + 与近邻码的处置层差别**三条，缺一条就是让读者自己猜影响范围。
8. **字节格式变更要成对登记 + 兼容方向实测**：同一素材的新旧两侧读数都写（只写新侧，读者没法判断差价的量级），
   并写清"旧实现读到新流"与"新实现读到旧流"各发生什么。这一对**必须活体跑出来**——
   由"选择器落在既有保留位"推断出"会当场拒"是合理猜测而不是证据，实测一条 `DECODE_FAIL` + 一条同库读旧档的对照组才算。

## 回执骨架

```markdown
# 回执 · <单名> · <日期>

> 单子 = 《…》。执行体交付：逐件带实测、改前改后齐、数值带算式。
> 本轮跑次 = <TAG 范围> 与门禁 <终局轮>。

## 一 · <拍定项>（完成 / 未完）
| 项 | 实况 |          ← 结论进表格，别写成长段

## 六 · 实现主体（逐落点）
### 6.x 落点 N <名>（本轮）
| 件 | 形状 |   ← 写"为什么这么实现"的取舍与硬约束

## 七 · 门禁与例数
| 项 | 改前 | 改后 |

## 八 · 账面（文件级 before / after）
| 文件 | 改前 → 改后（LF，CRLF 0） | 说明 |

## 九 · 停点、单外与待维护者
```

- 「单外发现」只登记**事实 + 是否已处理**，不夹带新决策。
- 待拍项要写清"为什么不自裁"（属字节格式 / ABI / 冻结判据 / 版本语义 / 权威件归属者才拦，其余自便）。

## 工作流

1. 落一件 → 立刻在回执对应节加一行（含读数）。
2. 批次收尾 → 补 `七 / 八` 两节的改前改后表；`CHANGE.log` 按四段式追加，测试情况带分域计数与判据复现值。
3. 自扫一遍新写的文字：发行件用复扫谓词表过一遍（见复扫规程），过程账不受此限但也别写绝对路径。
4. 交付时给一次统一汇总：完成项 / 未完成项 / 新撞出来的事实 / 等谁的决策，四段。

## 示例

输入：「更新回执」
输出：定位该单的回执文件 → 在对应节追加（不重写旧段）→ 回报改了哪几节 + 关键读数 + 还欠什么。

## 注意事项

- `CHANGE.log` 里"变更"与"新增"分错段是常见错：静默降级被取消、新增了拒绝档，属**变更**；
  只有全新对外能力才算新增。写"无对外可感修复"之前先确认确实没人受影响。
- 表格单元格里出现 `|` 要转义，否则渲染断行（本仓文档常见）。
- 冻结判据（验收线的数值、素材哈希）不重签：要动就在回执里明说"这是重签"，等维护者。
- **同一张表不混两把库的读数**：换库后旧数据留档时，在表头写明库哈希前缀（如 `旧库 160be82e`），新跑的写当前库前缀；
  不标 = 读者把两代库的读数当同一轮复现看，"逐字节对平"当场失去含义。回执里"沿用不重跑"的读数也要带这句归因
  （哪一刀动了它、为什么不动）。
- **例数两写**：本轮数出的 `N` 与门脚本里的 `EXPECT` 现值同时落纸，并注明后者未拍动。只写 `N` 会读成"闸已同步"。
- **报告口径 ·「无基准格 ≠ 偏差」**：对平类读数一律**两个计数分开写**——"真偏差格数"与"无对平对象（无基准）格数"，
  不许合成一个数。并成一格报出来的后果是：读者没法区分"代码漂了"和"这块以前没测过"，
  而后者恰恰是**首次基准**、是要入册的料。写"零偏差"时必须同时给出**覆盖数**（多少格有基准、多少格查无基准），
  否则"零偏差"是拿有基准的那部分自证。
  同族的一条：**入册后复跑对平 = 同源自洽，不是独立对平** —— 基准值和被比值出自同一次跑批时，
  rc=0 只证明"抄写没抄错"，措辞要写明这层，别让它冒充跨轮复现；给不出跨轮复现也要直说缺（哪一轮没覆盖这几格）。
- 别把长分析写成新文档塞进发行件——发行件只留结论与指得动的对象，推理过程进过程账。
