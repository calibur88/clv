# 项目级 Skill 生成器

## 1. 目标

把项目里反复要用的约定与流程沉淀成可复用 Skill，并保证它**真的会被所用平台加载**。
两件事分开：内容（写什么）与落位（放哪儿）。落位错了，内容再好也不生效。

## 2. 触发条件

- 生成 / 创建 / 沉淀一个项目级 Skill
- 把项目规范、约定、流程写成 Skill
- 配置 Skill 目录、平台入口，或接入第二个平台
- 排查"Skill 写了但没被识别"

## 3. 一条铁律：`skills/` 放通用件，各平台的入口自己核对后添加

```text
<仓库根>/
├── skills/                          # 通用件与项目共同件：与平台无关，唯一事实来源，随 git 提交
│   └── <skill-name>/SKILL.md
└── <平台约定的路径>/skills/         # 平台自己的扫描目录，里面只放逐件链接，整体不入库
    ├── <要用的件 A>  ->  ../../skills/<要用的件 A>
    └── <要用的件 B>  ->  ../../skills/<要用的件 B>
```

- **一处同名陷阱：仓库根 `skills/` 与平台入口 `<平台>/skills/` 末级同名**（取复数是为了跟多数平台的入口名一致）。
  所以本件与所有文档、脚本输出、报错信息里**一律写全路径**，不写"`skills` 那个目录"这种半截话。
  `.gitignore` 里更要小心：忽略行必须带平台目录前缀（写作 `.qoder/skills`），
  写成裸 `skills` 会把仓库根那份唯一事实来源一起忽略掉——克隆里就没有 Skill 了。
- **若某平台的项目级目录恰好就是仓库根的 `skills/`**（共同区与入口同址），不要往里链自己：那会自我引用、
  并把该平台的专属件混进共同区。停下来问一句，要么给共同区另起名字，要么改用那家支持的另一个入口路径。
- **一件一链，不要把整个 `skills/` 链进平台目录。** 整目录链等于"这家把共同件全量加载"，
  也等于以后谁往 `skills/` 加东西都会自动进那家的视野——想给某一家单独加一件，只能往共同区塞，共同区就被污染了。
  逐件链接是一份**显式的加载清单**：那家用哪几件就链哪几件，专属的东西留在它自己目录里（真实物理文件），
  谁也不挤谁。
- **`skills/` 只放与平台无关的内容。** 某个平台的路径 / 生效方式 / 实测结论属于"这家自己的事"，
  写进本件的平台表或该平台的说明文件，不写进 `skills/` 里那些通用件的正文。

- **`skills/` 下的件是通用的；哪个平台要用，自己在调用前核对该平台的约定并添加入口**——
  不存在"默认就是某一家"，也不存在"本仓只服务一个平台"。一台机器上常常同时有好几家在协作，每家一套约定。
- **不要把任何平台的目录名写成通用规范**（包括下面表里已复核的那一家：它只是"目前已核对过的一个个例"）。
  每个平台的项目级路径、末级名字、单复数、层级都不一样，同一产品家族的用户级与项目级目录名也可能不同。
- 接入一个平台前必须做三件事，缺一不可：
  1. 查该平台的**官方文档**，确认「项目级 Skill 目录」的完整路径与命名要求；
  2. 确认它的**用户级**目录，避免同名覆盖关系搞反；
  3. 确认它的**生效方式**（是否新会话才扫、有没有重载命令）。
  查不到就别写进表——下面那张表只有标了复核日期与来源的行可用，其余一律先复核再用。

| 平台（个例，非默认） | 项目级入口 | 用户级目录 | 生效方式 | 跟随子链接？ | 复核 |
|---|---|---|---|---|---|
| Qoder CN CLI | `.qoder/skills/<name>/SKILL.md` | `~/.qoder-cn/skills/` | 新会话自动加载；运行中 `/skills reload` | **是**（实测：链上后清单出现，调用时基目录就是那条链接） | 官方文档 + 本机实测，2026-10-13 |
| 其它（Claude Code / Codex / Cursor / OpenCode …） | 待各自官方文档复核 | 同左 | 同左 | 待该平台实测 | 未复核，禁止按记忆填 |

最后一列必须由**在该平台上干活的人自己测**后回填；抄别家的结论等于没测。

- 通用格式要求（多数平台一致，仍以各平台官方文档为准）：`SKILL.md` 文件名大写敏感、位于 Skill 根目录；
  frontmatter 必填 `name` 与 `description`；`name` 只允许小写字母 / 数字 / 连字符、≤ 64 字符且与目录名逐字一致；
  `description` 写清"负责什么 + 何时触发"并内嵌自然语言触发词——平台靠它做自动匹配，含糊描述会让 Skill 不被唤起；
  项目级通常覆盖同名用户级。
- 官方文档一般**不承诺**符号链接可用，更不会说它跟不跟**目录里的子链接** —— 有的扫描器只认实体目录，
  链了也看不见，而且看不见是静默的。所以逐件链完必须实测一次再下结论（步骤 6）。

## 4. 落位工具：`scripts/setup_skills.py`

链接一律不入库，两个原因叠在一起：Windows 的 junction 记**绝对路径**，仓库换目录或换机器就指向旧位置；
而 git 存符号链接存的是"内容为目标路径的特殊文件"，Windows 上没开开发者模式时 checkout 会**退化成一份写着路径的文本**
——看着在、其实不可用。所以入库的只有 `skills/`，链接每台机器现场重建。

```bash
python scripts/setup_skills.py --check                      # 只报状态，不写任何东西
python scripts/setup_skills.py                              # 给已复核的平台把 skills/ 全部件链上
python scripts/setup_skills.py --only a b                   # 那家只要其中几件（这就是它的加载清单）
python scripts/setup_skills.py --platform .claude:skills    # 新平台：确认过官方路径后显式给「目录:入口名」
python scripts/setup_skills.py --prune                      # 顺手清掉目标已消失的陈旧链接
```

脚本的行为边界（设计成这样就不许越过去）：

- 优先建**相对符号链接**（换目录不失效；相对深度建时按入口目录层数现算，入口目录直挂仓根即常见的两级 `../../skills/<name>` 形），
  失败再退 junction（绝对路径），并在输出里明说"换机器要重跑"；
- 已链对 → 不动；链到别处 → 只告警；悬空 → `--check` 报出来，实跑时重链，`--prune` 只清不建；
  空占位目录（已保证为空）→ 实跑时用不递归的删目录调用清掉后再建链，`--check` 只报"将被替换"；
- **同名的真实文件或真实目录出现在平台入口里 → 判成这家的有意分叉，停手不覆盖不删除**，
  并提示"保留或改成能区分的名字"——这就是防共同区被污染的那道闸；
- 平台入口本身若还是一整目录链（旧形态）→ 先核验它的目标确实指向本仓 `skills/` 才摘掉、再逐件建，`--check` 阶段只报不动；
  核验不了（悬空）或指向别处的链接，一律 STOP 不摘——那是平台或人工建的，不是本脚本的清理对象；
- 未复核的平台目录名一律拒绝，必须显式写成 `<目录>:<入口名>`，即"你自己查过那家的官方文档了"；
  显式写法解析后仍要落在仓界内，带 `..` 之类越界的直接拒；
- 退出码是有限枚举（码表在 `scripts/setup_skills.py` 的模块 docstring）：多个问题并存取最高一档，不做按位累加；
  `--only` 件名打错、该摘的链接摘不掉都记非零，不会"全绿"退 0。
- 顺带体检 `skills/`：缺 `SKILL.md`、frontmatter 两条 `---` 不完整、`name` 缺失或与目录名不一致，都会报出来。

Agent 不手敲 `ln` / `mklink` / `git rm`——链接相关的一切走这个脚本。

## 5. 工作流

### 步骤 0：确认平台与路径（不可跳过）

当前是哪个平台、是否多平台并存、该平台项目级入口的**确切**路径与命名、生效方式。
任一项不确定就先问用户；不要假设，也不要拿别家的路径套。

### 步骤 1：收集项目上下文

优先级：仓库根结构与构建配置 → `README` / 架构文档 / 规范正文 → 已有 `skills/` →
项目账本与协作约定（命名、目录、代码风格、测试与验收流程、记录规范）。
缺关键信息就先列"待确认问题"再给草案，**不要虚构项目规范**。

### 步骤 2：定边界

一个 Skill 只解决一类问题；跨领域就拆多个。目录名用 `kebab-case`，与 `name` 逐字一致。

### 步骤 3：写 SKILL.md

必含：触发条件、适用范围、规则（可执行、非口号）、工作流（有序步骤）、示例、注意事项（边界与易错点）。
控制在 500 行内；长表 / 模板另放一层深度的附属文件，别在 SKILL.md 里堆参考手册。

### 步骤 4：产物自检（任一不过回到步骤 3）

- [ ] `name` == 目录名，只含小写字母 / 数字 / 连字符，≤ 64 字符
- [ ] frontmatter 的两条 `---` 是**裸破折号**（曾被导出器写成 `\---` 或给标题加反斜杠转义，那样整份文件不会被解析）
- [ ] 正文无 `\#`、`\*\*`、`&#x20;` 等残留转义；条目之间不隔空行
- [ ] 无 `<占位符>`、TODO、示例残留
- [ ] 引用的路径在**新克隆**里存在（未入库目录、临时目录、本机绝对路径都不算）
- [ ] 与现有同名 Skill 不冲突；冲突先问用户
- [ ] `python scripts/setup_skills.py --check` 里本 Skill 在清单中且无 WARN

### 步骤 5：落位

写进 `skills/<name>/SKILL.md`，再 `python scripts/setup_skills.py --only <新件>`（或全量）把该链的链上。
平台入口与 `.gitignore` 的写法见第 4、6 节。

### 步骤 6：实测加载（不可省，也不可用别家的结论代替）

链上不等于能加载 —— 逐件链接能不能被跟随，是每家平台各自的行为。做三条最小验证：

1. **重载**：按那家的规定刷新（如 `/skills reload`）或开新会话；
2. **看清单**：该件是否出现在可用 Skill 列表里；不在就说明它不跟子链接，改走"物理复制 + 同步脚本"或整目录链，
   并把这条结论记进第 3 节表格该平台那一行；
3. **调一次**：真调用一件、确认返回的基目录是那条链接（证明读的是共同区，不是平台目录里的副本）。

顺手验防污染那道闸：在平台入口里手放一个与共同件同名的真实目录，脚本应报 `STOP ... intentional fork` 且不动它；
验完删掉探针。

## 6. 入库边界

`.gitignore` 只忽略平台入口，不忽略 `skills/`；每接一个平台加一行（写该平台自己规定的那个路径，别照抄别家）：

```gitignore
<平台约定的路径>/skills
```

例：已复核的那一家写 `.qoder/skills`。链接一律不入库（原因见第 4 节），所以**新克隆的仓库里平台目录是空的**，
协作者要各跑一次 `scripts/setup_skills.py`——这一句该写进贡献者说明，别只留在本文。

落这一行之后要**验一次忽略规则的边界**（同名陷阱的直接后果）：`git check-ignore` 对平台入口里的链接应命中，
对仓库根的 `skills/<name>/SKILL.md` 必须**不**命中；只有一条裸 `skills` 的行会把两者一起吞掉。

若某平台入口此前已被 git 跟踪，需**由用户**执行 `git rm --cached -r <该平台入口路径>`（本流程不代跑 git 写操作）。

## 7. 交付检查清单

- [ ] 平台、项目级入口、用户级目录、生效方式四项已确认，附复核来源与日期
- [ ] `skills/<name>/SKILL.md` 已生成，`name` 与目录名一致，且通篇不含本项目 / 本平台的专属事实
- [ ] frontmatter 与正文无残留转义
- [ ] 引用路径在新克隆里可达
- [ ] 逐件链接由脚本建立；Windows junction 绝对路径、git checkout 退化符号链接两条风险已提示
- [ ] **该平台已实测加载**（清单里有 + 调用能命中共同区），结论回填进第 3 节表格
- [ ] 分叉探针验过一次（同名真实目录要被脚本停手），探针已清理
- [ ] `.gitignore` 片段已给出（每平台一行）
- [ ] 已提示重载 / 新会话，并说明"重载前看不到属正常"
- [ ] 待确认问题已列出

## 8. 边界：本件不管什么

- **不管各家的加载行为。** 每个平台怎么扫目录、跟不跟子链接、要不要重载、去重与优先级如何，都得由**在该平台上干活的
  那家 AI 自己实测**后回填；本件只给约定、工具和不许越界的规则。表格里的实测值只对该平台该版本有效，
  换版本要重测。
- **不管项目内容。** `skills/` 里任何一件都不该写"本仓有哪几个件""本机是哪个平台"这类项目 / 机器事实——
  那属于项目的架构文档、账本或该平台自己的说明。判断标准：换个项目或换个平台，这句话还成立吗？不成立就别放这儿。
- **不管用户级 Skill。** 跨项目通用的工具件放用户级目录更合适；本件只管项目级。
- 不碰 git 写操作、不删平台实体文件、不覆盖同名件、不猜未复核的路径。
