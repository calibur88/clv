# CLV 私有面清仓与归档

本件管的是**不入库那一部分仓库**：在役工作区（未入库的那棵工作树，目录名见 `.gitignore`）、
归档区（同样未随仓库发行）、构建树、示例产物、参照工具链与素材。发行面（源码、测试、公开文档）只读，不参与清仓。

## 触发条件

- 磁盘占用失控，要一次性回收几十 GB 的构建 / 跑批 / 沙盒产物
- 一轮工作收完，过程账要从在役区迁进归档区
- 归档区要按职责重编号或整理落点
- 要删某棵目录，但不确定它是否还被门禁脚本、规范件或别的目录引用

## 0 先定边界（不做这一步，后面全是赌）

| 类 | 判据 | 处置 |
|---|---|---|
| **A 可再生** | 删后能按仓库里现成的命令重建（构建树、跑批产物、示例输出、缓存、已解包的上游压缩包） | 落清单后删 |
| **B 过程证据** | 文本台账 / 日志 / 探针源码，被归档区记录引用 | **先整目录迁入归档区**，件数对平，再从删除集剔掉 |
| **C 在役** | 下轮还要用（当前沙盒、门禁依赖的工作目录、参照媒体 / 二进制 / 字体、工具链、台账） | 保留 |
| **D 待确认** | 归属或唯一性不明，删了不可复原 | 只**集中**到待判区，观察后再判，当期不删 |

发行面一律禁改禁删。归档区的文本件一律不动，只允许动其中**派生大二进制**（见第 5 节）。

## 1 顺序：先归档 → 再整理 → 最后清理

删除是单向门。顺序反了的代价不是"多删了几件"，而是**复跑载体和被引用的证据先没了**，
后面任何"重跑一遍证明给你看"都做不到。所以：

```text
P0 取证与清单 → P0.5 预裁决 → 停点待确认 → P2a 归档 → P2b 整理 → P3 清理 → P4 验收 → P5 交付记录
```

- **P0.5 预裁决**四项必须在停点前跑完：① 门禁与规范件里对被删路径的引用（全文搜「在役区」字样求交集，命中即剔出删除集）；
  ② 疑似同一来源的大文件先做逐文件 SHA，命中才判重复；③ 疑似重复的目录先逐文件对平再谈删一份；
  ④ 无消费者的配置件先搜引用，搜到就保留（**理由过期不等于结论过期**，配置件的判据要按当前工具链重查）。
- **停点是硬的**：回收量、删除白名单、清单不完整名单三件报出去，拿到确认才动第一刀。

## 2 删前硬闸：清单与对平

每一棵要删的目录，先落 manifest 再动手，缺一律不删：

1. **两路枚举对平**：普通路径一次、`\\?\` 长路径前缀一次，文件数必须相等；
   任一路抛错、数量不等、目录非空而清单 0 行 ⇒ 该根进 `_INCOMPLETE.txt`，当期不删。
2. **两个字段必须采**（不采就会在事后查不出成因）：`nlink`（硬链接计数）与
   `reparse`（目录联接 / 符号链接属性）。
3. **跨根重复扫描**：删之前先扫「同一 `(FileId, VolumeSerial)` 出现在多个根下」和「根内任何一级是 reparse 点」。
4. 清单本身**保留**（它是"删了什么"的追账），并随结果件一起进归档区。
5. 超长路径的删除兜底用空目录 `/MIR` 镜像法，**不用通配符硬删**。

## 3 目录联接：`rmtree` 会穿链接删掉真实树

实测过的事故形态：几棵构建 / 沙盒树共享同一份预编译依赖视图，删其中一棵时，
共享视图里的文件被**兄弟根**一起带走——缺口数与视图条目数逐位相等（如 `287×5`、`189×2`）。
被穿的若只是同一批可再生产物就算侥幸；指向在役件时不可挽回。

- 判据不是"看起来像目录就递归删"，而是先 `lstat` 看是不是 reparse / 链接；
- 命中则改判**只删链接本身**（`os.rmdir` / `os.remove` 作用于链接，不进它的目标）；
- 删除集定案前，第 2 节的第 2、3 两条没做完 = 不许开删。

## 4 白名单是唯一事实源

- 删除集**只能逐项列**（路径 + 现算字节），脚本从那份清单读，不允许另写一份、不允许增删项。
- **禁止时间兜底、通配符兜底、"不在保留清单里就删"兜底**：时间 + 黑名单必然误伤 D 类
  和隐藏引用件（被门禁脚本 `cd` 进去的那种，目录名看着像垃圾）。
- 路径一律写**字面量**。用标签字符串反推路径是事故源：`replace` 替换的是**所有**出现处，
  名字里带重复前缀或被当过分隔符的字符就会拼出不存在的路径，脚本判 "missing"、当场漏删整根，
  而且退出码照常是 0。标签只用于取基线。
- 根级散件默认**不进自动删除范围**，只登记清单，逐项确认后另行处置。

## 5 归档区的落位与映射

| 原则 | 做法 |
|---|---|
| 一份文件只进一个职责目录 | 同一事件的提案 / 交付记录 / 证据 / 过程账分开落，不混在同一目录 |
| 迁移不重写历史原文 | 旧路径引用**不改**，另落一份「旧 → 新」映射表（带实测件数），必要时在被引件追加【补记】一行 |
| 归档前先验发行面引用 | 全文搜发行面对旧归档路径的引用，命中数报出来；为 0 才说明重组不破坏克隆 |
| 归档脚本随件走 | 门禁 / 复跑脚本迁走后必须在新路径先跑一遍（日志落点、绝对路径、被引用的工作目录都正常）再算迁完 |
| 归档区瘦身 | 只动**派生**大二进制；文本件一律不动。某个大文件是不是原件，靠逐文件 SHA 判，不靠名字 |

## 6 数字口径（每个数都要能自证）

1. **回收量用删除时现算**，不用删前的基线估值——基线会被共享视图、链接、未落盘目录高估或低估。
2. **每阶段收尾把现存量逐目录落盘**（目录 / 文件数 / 字节）。只在对话里报一个合计数，事后连自己都对不平，
   差额只能按"口径缺口"登记，不许编成因。
3. 两个数不能同时成立时，先重算再归因；记账值与实测值冲突，写清哪个是现算、哪个是登记。
4. 判据阈值超标时（保留量比估算多出一截），先分解差额来源、再报"实质达标 / 待拍"，不要静默抬阈值。

## 7 证据源的次序

**先把已经落盘的清单算完，再去要新的证据源。** 提权读文件系统日志、跑卷级取证都是新证据源，
成本高、还要人配合；绝大多数"这批文件是谁删的"其实能在自己刚落的 manifest 里按分组重算定位。
采证中间件（几十 MB～几百 MB 的原始导出）默认**不留存**，只留推导结果与可重出的脚本。

## 8 验收（逐项读数，缺一不算收完）

| # | 判据 |
|---|---|
| V-1 | 私有面存量 ≤ 目标（超了按第 6 节第 4 条分解） |
| V-2 | 在役区只剩保留清单里的项 |
| V-3 | 构建树只剩必须留的第三方预编译视图 |
| V-4 | **发行面零改动**：跟踪件里"mtime 晚于删前基线"的 = 0 件；复跑类例外要双证（`git diff` 空 + 与 `HEAD` 逐字节等值），并写清"只动 mtime" |
| V-5 | 归档迁移件数三重对平（源计数 / 目的计数 / manifest 行数） |
| V-6~V-8 | 净构建、全量测试、示例直跑全过（构建目录被删 ⇒ 必须重建后再判，不能引用清理前的读数） |
| V-9 | 格式闸三半全部 PASS |
| V-10 | 全程**只读 git**：不 add / commit / push / tag；待入库件列成清单，等具备入库权限的一方落地 |

## 9 收尾必做

- 逐阶段结果件、manifest、取证脚本进归档区的清仓账目录；**计划件本身**也进同一职责目录，不留仓库根。
- 交付记录按"清理一项写一项"落，最后给完整版；自己的失误单独成节，撤回的结论把原文留着标作废，不删。
- 复跑清单要自带「复跑 → 期望读数」；探针若往跟踪件里植入再复原，必须写明它会推 mtime。
- 待判区**当期没判完就是合规状态**，别为了账面干净把它删掉。

## 易错点

- 终端渲染出来的标点不是证据（`/` 被显示成 `-`），以码点为准。
- 文件系统的 Reason / 属性位标志别凭记忆填：同一行里标签与值要对齐后再用，跨工具的同名标志可能不同档。
- 归一 FileId 时别抹掉序号位，跨代复用会串到别的树上去。
- 批量改写一律走字节写；文本写在 Windows 上会静默换成 CRLF（发行面钉了 `eol=lf`）。
- "退出码 0"不等于"活干了"：漏删的根常被判成 missing 而照常绿，要断言删除集的每一项都命中过。
