# CLV 收口纪律复扫

## 触发条件

- 一批改动做完、准备写回执之前
- 改过或删过公开枚举值、改过字节格式、动过 `include/` 的注释
- 实现过某件此前标着"未落地 / 不在范围"的东西
- 维护者指出"这里怎么又带私账编号"——说明上一轮复扫没做净，要重跑全套

## 适用范围

- 纳管代码面：`include/` `src/` `tests/` `demo/` `scripts/` `platform/` `backends/` `cmake/`
- 对外发行文本：`README.md` `API.md` `ARCHITECTURE.md` `CHANGE.log` `docs/` `assets/README.md` `demo/README.md` `tests/docs/`
- **不在范围**：`third-party/`（上游件不受本仓纪律约束）、`archive/` 与 `content.md`（过程账，本来就写给自己看）

## 四类复扫，一类都不能少

1. **入库注释**——逐条按谓词表扫（先提取，别翻源文件）。
2. **对外文档**——同一套谓词，外加数值对账与跨文档指针可达性。
3. **陈旧范围声称**——凡写「未落地 / 不在本期范围 / 占位 / v1 恒 …」，去代码里 grep 对应符号确认是否已实现；
   已实现就地补条目，并检查同一条声称在别处的副本。反向也查：说已支持但代码查不到对象。
4. **退场符号残留**——改名 / 删值 / 退场一个码之后，全库复扫旧名，逐条报"残留引用 = 0"。

## 谓词表

| 谓词 | 搜索串 | 判定 |
|---|---|---|
| 节号引用 | `§` | 只允许指向**自己文件里存在的小节**；跨文档必须点名是哪一份且不带节号。自指要验证该小节标题真存在 |
| 条号引用 | `执行单\|本单\|单子\|落点 ?[0-9]\|批次[①-⑩]` | 违例 |
| 过程引用 | `前一轮\|本轮\|上一轮\|清单说\|先前那句\|旧件头写成\|按实码改准` | 违例——但"原来只打印，红不出来"这类**说明为什么这么断言**的是有效 WHY，保留 |
| 口径词 | `拍定\|待拍\|待裁\|待批\|裁决\|复议\|签认\|待签项` | 代码与对外文档违例；`CHANGE.log` 的验收叙述属维护者口径词，有意保留 |
| **归属词** | `维护者\|受托方\|派遣` | 代码注释与对外文档**违例**：入库文本只陈述约束本身，不写这条约束由谁拍、也不写它是哪一轮改的。私有账本（`content.md` / `archive/`）照旧点名，那是写给执行体自己看的 |
| 过程账词 | `回执\|提案\|草案\|权威件\|归档\|核验\|跑次\|设计方案` | 点名而不带节号者按既有约定保留；带节号 / 带路径者违例 |
| 私账编号 | `CL-\d\|X-\d\|D-\d\|V-\d\|M-\d\|E[0-9]\|G[1-6]\|Q[1-7]\|W\db` | 违例；注意假命中（`BSD-3-Clause` 被 `D-` 吃、量化档名 `q=1/32` 被 `Q[1-7]` 吃、`SEG1` 被 `G[1-6]` 吃、`单子进程` 被 `单子` 吃） |
| 本机痕迹 | `temp/\|C:\\\|E:\\\|/Users/\|\.log\b\|\.bat\b\|NOTES-` | 违例（`.gitignore` 里的 `temp/` 是配置本身，假命中） |
| 判据编号 | `判据 ?[0-9]` | 代码注释与用例文案违例，改成写约束本身（「冻结值 2304」「要求 0」）；对外文档的验收叙述保留 |
| 行号钉法 | `\.(h\|cpp\|c\|py\|md)\s*[:：]\s*(L)?\d{2,5}` | 违例——引用内部件钉**符号名**，不钉行号 |
| 旧名残留（改名之后） | 除 `旧名/` 外**必须再扫裸名**：`"旧名"`、`'旧名'`、元组 / 常量 / 参数默认值 / 配置表里的字符串项 | 违例。漏法很具体：目录名写成不带分隔符的一项时，按 `旧名/` 扫一处都不会命中 |
| 手抄镜像表 | 工具件里把公开头的枚举 / 常量抄一份（`名字 → 值` 对照表、位宽表、魔数表）：拿现行公开头独立解析后**逐格比对 + 双向差集** | 违例。抄件不随退场与改值同步，落后几轮后整体错位；若某个判据列是**由这张表推出来的**（如「查得到名字就算合法」），错位会让该列**恒真、判据空转**——修表之后必须实测那几格能报假 |

## 工作流

1. 提取注释：`python scripts/dump_comments.py`（默认写 `build/audit_comments.txt`，并打印文件数与条数）。
2. 逐谓词扫清单件：对**正文**匹配（先把 `path:line:B|L:` 前缀剥掉，否则每条都命中路径）。
3. 每条命中回源核实：确认不是假命中、确认替换文案不改变语义；分三类并给计数。
4. **报零之前先跑对照**：拿一个已知存在的符号（如 `ext_type`）跑同一条命令，证明扫描通路有效——假零比漏改更坏。
5. 批量落地用脚本，逐处断言命中数 = 1 + LF 行数不变；**同一文件禁止并行编辑**，改完查 CRLF。
6. 复核收尾：`python scripts/format_all.py`（检查模式违例应为 0）、增量构建 + 全量 `ctest`，
   再按门禁 Skill 跑一轮净构建双配置（改过入库 `.cpp` / `.h` 的注释也要跑）。

## 扫描口径的五个已知坑（都是实测撞出来的）

- **`dump_comments.py` 只吃 C/C++**：`.py` 的 docstring 与 `#` 注释整批不在清单里 ⇒ 复扫必须另跑一遍 Python 侧
  （`scripts/` 全量），否则「脚本注释干净」是假零。实测漏网的就是这一族：`scripts/gen_fuzz_corpus.py` 里那条归属说法。
- **数例数的谓词会漏缩进**：`grep -c '^TEST('` 数不到写在命名空间里、带制表符缩进的用例 ⇒ 分域相加 335、ctest 却报 342，
  于是五处对外计数全写成旧数。要用 `^[[:space:]]*TEST\(`，并且**分域和必须等于 ctest 的 N**，不等就是有用例没被数进来。

- **`git ls-files` 全集扫不到用例代码**：本仓 `tests/win32/**`、`src/video`、`src/audio` 整体未纳管（git 写操作被禁用，无法 `git add`），
  `git ls-files` 只有一小部分文件。复扫必须按目录扫 + 排除 `__pycache__/`，否则会给出假零。
- **Windows 控制台是 GBK**：脚本打印 CJK 会乱码，读日志的人会被误导。工具脚本的输出一律 ASCII，中文只放注释和文档。
- **改名后的裸目录名藏在元组 / 常量里**：`script/` → `scripts/` 那轮按 `script/` 复扫，两处写成裸名 `"script"` 的目录清单
  （`format_all.py` 的 `PY_DIRS`、`find_todo.py` 的 `DEFAULT_DIRS`）一处都没命中，于是格式化门禁的 Python 半边
  **覆盖 0 件却报通过**——假绿了整整一轮，直到改名第二轮数了一下它自报的件数才露馅。**工具跑完要看它自己报的覆盖面数目**，
  数目为 0 或骤降就当作失败读，别看退出码。

## 示例

输入：「收口了，把注释和文档再扫一遍」
输出：四类各给「命中数 / 违例数 / 有意保留数 / 假命中数」+ 违例明细表（文件:行 | 原文 | 命中哪条 | 替换文本）+ 落地脚本路径 + 复跑读数。

## 注意事项

- 修注释属机械卫生，**直接改并证明**，不要拿去向维护者提问；只有字节格式 / ABI / 冻结判据 / 权威件归属才拦。
- 回执与账本要登记"违例是我自己引入的"这类事实，不粉饰——上一轮写进公开头的节号就是本轮扫出来的。
- 判定分类必须落字：把「有意保留」写成"看着没问题"等于没判。
- 清单件会过期：改过注释后重新 `dump_comments.py` 再扫，别拿旧清单的计数交差。
